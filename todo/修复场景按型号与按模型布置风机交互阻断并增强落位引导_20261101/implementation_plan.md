# 修复场景按型号与按模型布置风机交互阻断并增强落位引导 实施方案

## 1. 需求与核心原则确认

根据排查根因与用户明确指示的 4 个修正点与细节，本方案旨在彻底解决场景编辑器中风机布置的可用性、交互动线与连续布置体验：
1. **解除模式门禁拦截并提供一键辅助编辑**：场景在只读查看模式下，点击布置按钮不再静默置灰或无响应，自动引导/辅助用户进入编辑模式；
2. **零静默阻断与错误显式提示**：消除 `activateTurbine` 与 `activateCard` 门禁未通过时的静默退出，任何模型未校准或地理不符均 100% 明确提示；
3. **型号列表补充缩略图（默认优先外观版）**：
   - 在风机型号卡片左侧增加 `ModelThumbnail`；
   - 因一个型号可能包含多个模型（外观版、完整版），卡片缩略图**默认且优先展示【外观版】的缩略图**（`appearanceModel`）；若无外观版则降级展示【完整版】缩略图；
4. **去除“外观版/完整版就绪”文字，点击地表后弹出模型形态选择对话框**：
   - 移除型号卡片上硬生生的一整行状态标签；
   - 点击【布置风机】后点击地表确定机位坐标，随即弹出落位配置对话框；
   - 对话框中展示该机型下属绑定的模型版本（外观版 vs 完整版，附带对应缩略图与规格），默认选中【外观版】；
   - 用户确认后正式落位到场景中；
5. **禁止布置后强行跳转“场景内容”，支持顺畅连续布置**：
   - 移除 `setLeft('content')` 的硬跳转逻辑，放置完成后保持在“模型资源”面板与当前选中的型号列表，方便用户连续布置机位。

## 3. 具体实施改动点

### 3.1 步骤一：`ResourcePanel.tsx` 交互重构与缩略图补全
1. **型号列表补充缩略图**：
   - 引入 `<ModelThumbnail api={client} version={thumbnailVersion} name={title} onStatus={thumbnailUpdated}/>`；
   - 提取规则：**`const preferredRef = turbine.appearanceModel || turbine.detailedModel;`**，确保默认且优先使用外观版模型版本与对应缩略图；
2. **移除“外观版就绪 完整版就绪”标签**：
   - 彻底移除卡片上原有的 `ov-resource-card-state` 两列就绪标签，使卡片紧凑整洁；
3. **只读模式点击拦截与友好转编辑**：
   - 为 `ResourcePanel` 添加 `onEnterEdit?: () => void`；
   - 当用户处于只读模式点击【布置风机】或【放置】时：
     - 若具备写权限，调用 `onEnterEdit` 自动激活编辑模式并继续；
     - 若无写权限，弹出明确提示告知权限限制；
4. **消除静默吞点**：
   - `activateTurbine` 中，若模型未校准或无法落位，通过 `setNotice` 明确给出告警原因，绝不静默返回；
5. **按型号布置回调适配**：
   - `onPlaceTurbine?: (turbine: ProjectTurbineDefinition) => void`；
   - 用户点击型号的【布置风机】时，触发 `onPlaceTurbine` 进入机型放置待落位状态。

### 3.2 步骤二：`SceneWorkspace.tsx` 增加落位确认对话框与流程打通
1. **状态定义**：
   - `pendingPlacement`: 支持 `{ kind: 'turbine', turbine: ProjectTurbineDefinition }` 及 `{ kind: 'model', model: ProjectModelVersion }`；
   - `turbinePlacementDialog`: `{ turbine: ProjectTurbineDefinition, point: Vector3, selectedType: 'appearance' | 'detailed' } | null`；
2. **地表点击处理**：
   - 当处于 `pending.kind === 'turbine'` 状态且用户点击地表网格时：
     - 记录点击坐标 `point`；
     - 弹出 `turbinePlacementDialog`，**默认选中 `selectedType = 'appearance'`**（若仅有完整版则选中 `'detailed'`）；
3. **对话框确认落位**：
   - 对话框清晰展示该机型下属的外观版与完整版选项卡；
   - 用户选择形态（外观版或完整版）后点击确认；
   - 异步读取该版本的 `ProjectModel` 并执行 `placeModel`；
   - 新实例自动关联该机型定义，设置正确的 `displayName`；
4. **连续布置体验（彻底解决自动切“场景内容”的问题）**：
   - 检查并移除 `place` 函数中硬编码的 `if(!continuous){setPending(null);setLeft('content');}`；
   - 改为：放置完成后保持 `left` 不变（仍然为 `'resources'`），且不强行关闭侧边栏（`setSide(null)` 只在小屏移动端自适应，宽屏保持打开）；
   - 用户可继续点击地表布置下一台，或者在左侧选择下一个型号。

### 3.3 步骤三：`SceneViewport.tsx` 地表点击与容错
- 在用户处于放置状态点击非地表区域时，捕获异常并给出温和提示：“未击中地表区域，请在风场地表网格上点击以落位风机”，不阻断当前布置意图。

### 3.4 步骤四：后端 `turbine_definitions` 模型版本查询加固
- 在 `apps/api/project_model_library.py` 的 `turbine_definitions` 中，SQL 查询增加版本校准与创建时间排序，确保获取的关联模型始终为最新已核准版本。

## 4. 验证计划

1. **单元测试回归**：
   - 运行前端全量单元测试（`node --test apps/workbench/tests/*.test.mjs`），确保既有测试全部通过；
   - 新增针对机型放置对话框、优先外观版缩略图、连续布置保持在资源面板的单元测试用例。
2. **端到端交互实测**：
   - **缩略图优先外观版**：验证【风机型号】列表卡片默认展示外观版 3D 渲染缩略图；
   - **标签净化**：验证卡片不再显示“外观版就绪 完整版就绪”标签；
   - **点击地表弹窗**：点击【布置风机】后在场景地表点击，验证弹出机型模型选择对话框，且默认选中【外观版】；
   - **确认落位**：点击【确认布置】，风机成功生成在地表所选点位，三维模型正常渲染；
   - **连续布置**：落位完成后，验证左侧面板依然停留在“模型资源”与风机型号列表，未跳转至“场景内容”，支持用户连续高效布置。
3. **保护文件约束**：
   - 绝不修改或触碰 `README.md` 与 `docs/references/夏李风场空间导航验证.md`。
