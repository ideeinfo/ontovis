## 2. 测试部署的限额与运行目录

处理器硬上限仍为256MiB；实际HTTP上限允许由服务启动参数降低，响应`limits.maxUploadBytes`返回生效值。测试配置采用100,000,000字节（95.37MiB），与Nginx一致。该基线参考[Cloudflare官方默认上传限额](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/#upload-limits)，实际账户方案及自定义区域限制未核实，不能据配置声明公网大文件上传已通过。

候选unit使用`/data/ontovis/runtime/gis-current/bin/python`及1536M内存上限；为父进程和两个各自有界的地形/几何处理进程留出空间。运行目录从已验证的独立GIS环境复制，不在服务启动时安装依赖，不修改旧运行环境。代理仅补齐实际场景、工程对象、资源和地形路由；Demo继续410，私有素材仍受保护。

隔离Linux100项（0跳过、102.558秒）、原生Nginx/unit语法及服务用户依赖检查通过；77份源/配置前后相同。同等保护属性的独立短期服务已实际验证ontovis用户、1536M cgroup、无有效capabilities和合成GeoTIFF读写，随后collect；不等于实际workbench已启动。证据登记于[本批输出](../../output/q06-scene-acceptance-20261023/README.md)。候选workbench的实际沙箱启动和本人读取已另在新副本验证；在线入口尚未切换，鉴权上传与公网端到端验收仍须分列，不由配置检查代替。

## 3. 备份及回退顺序

1. 切换前停止旧工作台写入，核对进程/cgroup/端口无写者；用工具保存原配对目录B0、外部回执SHA、运行版本和配置。`--service-stopped`只是操作者声明，不能替代停服证据。
2. 使用已验证、能识别旧写冻结门的后端与固定版本产物。当前来源或工程条件变化则重新核验，不能把本机旧回执直接用于在线库。
3. 生效后若失败，先停止受影响写入，并备份包含所有新修订、登记和审计的当前B1。不能回用B0覆盖新数据，也不删除新场景。
4. 优先保留兼容后端和旧写冻结状态，仅回退能安全读取的前端；否则维持维护/停止状态。旧部署脚本自动启动不识别冻结门的历史后端不可复用。
5. 从B1恢复至新目录R1，核验完整文件/表/当前头和冻结门，再明确配置指向。工具不自动覆盖、启用、改属主或合并数据库。恢复目录不直接作为校验过程的可写服务目录。

上述实际副本已验证备份、重复核验、错误回执拒绝及新目录恢复；在线停服备份、来源重核、生效与故障回退尚未执行。
