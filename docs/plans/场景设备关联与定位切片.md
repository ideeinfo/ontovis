## 1. 已实现的读取接口

以下均为当前同源服务的`POST`路径，复用本人 HttpOnly 会话、固定连接/项目及`expectedSessionRevision`。响应附当前`sessionRevision`；普通读取 JSON上限16KiB，不接受上游地址、任意URL、文件路径或处理命令。接口存在不代表本批已部署到`vis.ontobase.ai`。

| 路径 | 主要请求字段（省略公共会话字段） | 当前行为 |
|---|---|---|
| `/api/workbench/objects/context` | `entityUid`，可选`expectedEntityRevision` | 从当前权威对象发现实际设备上下文，不默认7号；返回自身对象、上下文、完整性明确的祖先链及关联条件 |
| `/api/workbench/objects/detail` | `installationContextId, entityUid, expectedHierarchyRevision`，可选`expectedEntityRevision` | 核验明确上下文及期望修订；上下文与层级修订允许同时为null，以读取型号定义等自身信息 |
| `/api/workbench/objects/children` | `installationContextId, entityUid, expectedHierarchyRevision`，可选`cursor` | 按实际设备父级分页，保留上游不透明游标；每页最多50项并重核当前对象/上下文 |
| `/api/workbench/objects/evidence/resolve` | `installationContextId, entityUid, expectedEntityRevision, expectedHierarchyRevision` | 只解析所选对象自身或其明确型号来源的当前图纸；返回原有证据列表结构 |
| `/api/workbench/objects/evidence/content` | 上述四字段＋`evidenceRef, expectedSourceRevision, expectedContentSha256` | 上游重核对象、来源修订和原PDF指纹后返回受保护PNG；会话和项目授权在返回前再次核验 |

对象读取只接受精确身份解析；合并、别名替代、跨项目或不再有效的身份不能静默换成另一UID。型号定义和未分类对象可以合法阅读自身资料，但不因此成为可关联安装设备。父链不完整时保留自身可读对象，明确标为不可新建关联；不以模型树、名称或电气接线推断物理父子关系。

新资料入口不依赖有效几何或完整定位链，不以祖先宿主替换所选对象。无几何子设备定位到CN时，图纸仍来自该子设备自身或其明确型号来源，不能换成CN的图纸。当前仅支持既有受保护整页预览，不新增历史归档、照片上传或外部抓取。原PDF的`sourceContentSha256`与返回PNG的`imageSha256`分开；HTTP二进制指纹使用PNG摘要，不能把两者混用。

实现：[明确对象读取](../../apps/api/scene_engineering.py)、[当前图纸](../../apps/api/scene_evidence.py)、[会话接线](../../apps/api/workbench_server.py)、[HTTP边界](../../apps/api/session_http.py)。新路径与旧固定演示入口并存，不借新读取接口改变旧入口的默认语义。

## 2. 实例设备及内部构件关联

关联使用既有`/api/workbench/scenes/check`、`/save`和`/open`，没有新增OntoBase写入口。`rootBinding`和`componentBindings`属于场景实例；相同模型版本及构件键可以由不同实例分别关联不同设备身份。

| 操作 | 当前服务约束 |
|---|---|
| 关联设备 | 同项目可读的安装对象，具有当前完整物理链；可关联风机、变压器或其他层级设备，不限定三柜或上下文根 |
| 关联内部构件 | 对象必须为已关联设备自身或完整已记录后代；每对象可关联一组当前固定模型构件，同一实例内不能抢占另一对象的构件键 |
| 清除内部关联 | 仍核验被移除对象的当前条件；不能通过删除行绕过对象及层级审阅 |
| 更换或解除设备 | 返回逐实例`rootBindingImpact`及完整`removedBindings`；保存必须显式声明旧根、新根、清空旧内部关联及已审阅移除摘要，不能仅凭最终空列表推测用户同意 |
| 保存与冲突 | 完整快照＋固定`expectedSceneRevision`＋UUID幂等请求；当前项目admin才可写入，最终工程/资源/授权变化整次回滚，不推进场景头或审计 |

`check`读取当前权威条件，返回`reviewedEngineering`、`rootBindingChanges`和影响清单；这不是自动确认工程事实。保存使用客户端明确保留的审阅条件，与当前权威完整比对，并在最终事务内再次核验。`open`可返回新鲜对象条件和动态阻断问题，但仅在响应内合并，不覆盖旧保存修订的依据。旧审阅条件失效时，不能用打开或预检时新读到的条件悄悄替代。

前端的“关联设备”“关联内部构件”仅修改本地草稿，普通场景保存完成提交；位置锁定不禁止关联，仍禁止移动/删除等位置操作。更换设备的确认弹窗读取旧、新设备及全部被移除对象的业务名称，逐项显示构件数；任何名称读取失败都禁用确认并提供重试，不用UID或临时名称兜底。名称读取只是展示，不修改审阅条件；保存期间不能取消该确认。工程条件变化时提供单对象「核实当前关联」：重新读取对象和路径，用户明确确认后仅更新该对象审阅条件；几何快照未变也可保存，不用改名触发或批量接受预检返回的新条件。

实现：[纯关联规则](../../apps/api/scene_bindings.py)、[当前权威校验](../../apps/api/scene_engineering_validation.py)、[场景存储](../../apps/api/scene_library.py)、[前端审阅状态](../../apps/workbench/src/sceneEngineeringState.ts)、[设备及构件关联](../../apps/workbench/src/SceneInstanceLinks.tsx)、[关联变更确认](../../apps/workbench/src/SceneBindingReview.tsx)。

## 3. 当前场景定位

新增`POST /api/workbench/scenes/locate`，普通读取上限仍为16KiB：

```ts
{
  expectedSessionRevision,
  sceneId, sceneRevision, // 必填当前查看的固定保存修订，不隐式取最新头
  selectedObjectRef: { ontobaseConnectionId, projectCode, entityUid },
  contextEpoch,
  representationChoice?: { sceneModelInstanceId, modelVersionId }
}
```

请求先限定配置的连接/项目，再打开指定修订、核验当前工程条件和固定资源，读取当前所选对象，最后解析定位并再次核验本人权限。明确选择的实例与版本仍须属于当前场景及合法设备子树；不接受构件键、客户端矩阵或服务器路径来替代核验。

服务先找所选对象的直接表示，没有时才按完整物理链逐级找最近祖先。近层待核关联、身份/层级失效或不完整父链都会停止查找，不能跳到更远的整机。一个对象有多个有效实例表示时返回`choose_representation`和`choices`，不随机选择，也不沿用上次查看的实例。近层有阻断问题、另一实例仍有有效表示时，先提示`BINDING_NEEDS_REVIEW`并要求明确选择该有效表示。

返回沿用契约的`SceneLocationResult`：固定场景/修订、始终为自身的`selectedObject`、另列的`hostObject`、`mode`、实例/模型版本/构件集合、`worldBounds`、几何质量、关系状态、选择清单、原因及原`contextEpoch`。正常状态为`located / choose_representation / unavailable`；不可定位不伪造空坐标。常见原因包括`NO_REPRESENTATION`、`AMBIGUOUS_REPRESENTATION`、`INCOMPLETE_PHYSICAL_CHAIN`、`BINDING_NEEDS_REVIEW`、`RESOURCE_NOT_READY`和`RESOURCE_CHANGED`。

整模型根表示使用固定报告全模型边界；内部表示对每个构件盒的八角分别执行模型校准、实例旋转和平移后再合并，不能先合并局部盒导致旋转边界虚大。局部场景使用米制位置和`yaw=-heading`；投影场景只使用该修订已验证保存的`displayPlacements`，不在普通API进程导入GIS或采用经纬度近似公式。

模型必须为精确固定版本，就绪、可布置，并匹配保存的内容修订及SHA。地理场景要求有效校准；经明确来源核验的`legacy_display`版仅允许局部场景的原样显示和定位，不能进入地理布置、首次锚定或地理换版。整模型几何质量为来源候选；构件集合中任一代理几何则返回代理精度，不宣称现场精度。直接定位的`relationshipStatus=null`；祖先定位按实际经过的边归纳，遇假定边即为`assumed`，否则为`confirmed`。

隐藏但有权的实例仍参与搜索，服务不改变保存显隐。前端成功定位后临时显示并从当前镜头平滑切换，以独立边框高亮固定世界边界，不改共享模型材质；未保存草稿先保存再执行对象定位。对象切换、取消、退出及会话变化丢弃迟到结果；图纸仍可独立读取，不等待定位成功。

实现：[定位解析器](../../apps/api/scene_location.py)、[前端定位状态及类型](../../apps/workbench/src/sceneEngineeringTypes.ts)、[实例构件边界聚焦](../../apps/workbench/src/sceneComponentFocus.ts)、[场景工作台](../../apps/workbench/src/SceneWorkspace.tsx)。

## 4. 模型换版后的阻断

换版不按同名或相同构件键自动迁移工程关联。目标实例清空旧内部关联，并由服务从旧保存依据派生持久`model_version_changed`问题；其他实例和旧修订保持各自固定版本。有效CT关联与待核CN问题可以并存，CN子设备到达该近层时仍被阻断，不能因构件列表已清空而兜底到整机。

只有当前模型构件、当前对象及其当前已记录子树经过显式重新关联并成功保存，才解决对应问题；预检、打开或取消换版不会自动消除问题。工程身份/实体修订/父链变化另产生`engineering_changed`，读取历史也重查当前授权和工程条件。正式现场身份、真实物理归属与构件精度核实仍属后续Q-11，不由本切片升级为已确认。
