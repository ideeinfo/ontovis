# 工单工作流重构实施计划

2026-11-11 · 统一队列 **Q-55** · [设计基线](../design/工单工作流与分析复用设计.md)。工单工作流、分析复用及处置进展回流已部署并完成公网验收。实际接口见[实施契约](../contracts/工单工作流与分析复用契约.md)，结果见[执行§219](开发执行记录.md#219-工单工作流与分析复用实施及验收2026-11-11)。下文保留设计基线与验收矩阵。

## 1. 调整后的目标与范围

下一业务阶段先简化工单，再接助手辅助办理。完成从发起到归档、文本记录、附件、同码分析推荐、人工采纳及修改另存的闭环。诊断排查集中在分析画布，撤销原 EA-05 继续向工单追加结构化假设/排查步骤的建设方向。

Q-55 为唯一队列任务号，WF-01—07 是其内部交付步骤，不另算第二套项目。EA-05 对应 WF-06，复用 Q-55 前序服务。Q-25/Q-49/Q-50 的旧实现和验收保留，不把重构写成这些历史批次失败。多来源公网知识验收、Q-54 全驾驶舱原画质 4K 长测和旧 AI 凭据备份夹具修正继续分别跟踪，不作为新工单诊断功能扩大范围。

## 3. 顺序、交付与完成门

| 步骤 | 任务 | 前置 | 交付和完成门 |
|---|---|---|---|
| WF-01 | 页面与服务契约 | 本设计 | 在原 MagicPath 项目更新工单列表/详情/新建/采纳/另存/上传/冲突及只读状态。核对人员权限、源端上传限制、共享内容权限和旧版兼容。冻结相关字段、实际路径、错误/回执及状态映射，不增加用户未要求的审批平台 |
| WF-02 | 简单工单与处理记录 | WF-01 | 普通建单、认领/分派/转交、文本记录、完成/归档/重新处理及作废。工单卡与固定来源同步可读新过程/结果，不能出现新记录已存但画布为空。后端具体权限和版本控制、旧单首次操作升级留痕通过，旧诊断历史可读，不要求旧结构化清单 |
| WF-03 | 工单附件 | WF-01、WF-02 | 文档/照片上传和引用已有资料，源端固定文件、本单/记录关联、预览/下载/移除与历史。画布工单卡可打开相应记录的固定附件。上传成功但关联失败可单独恢复，OCR/AI失败不影响已上传文件使用 |
| WF-04 | 可复用分析与自动推荐 | WF-01、WF-02 | 一般故障码/代码体系/对象/型号语境检索，本人及明确共享固定版可用。同码候选、分页、无结果/失败分别展示。项目共享只含所选分析版本，私人对话和受限来源不泄露 |
| WF-05 | 采纳、新建、修改另存 | WF-02、WF-03、WF-04 | 一个主要采纳版和多项参考，两个工单引用同一版。新建分析可带本单/附件，修改旧分析另存并追溯来源，原事件证据不冒充本次。保存/关联/采纳分项回执及重试通过 |
| WF-06 | 助手辅助办理（EA-05） | WF-02—05 | 后台助手按权限检索推荐、编辑画布、整理用户提供的文本、准备附件关联。工单证据优先读取可引用的处置过程/结果，原分析建议不递归展开或重复作独立佐证。人工最终采纳/完成/归档，驾驶舱查询及转后台。旧“整理到工单”不再写结构化诊断条目 |
| WF-07 | 兼容、恢复与公网验收 | WF-02—06 | 相关测试、类型和正式构建通过，最新数据配对备份及独立恢复，隔离测试单全流程公网验收，再提交相关仓库并记录精确部署/回退版本 |

第一可用切片为 WF-01—03，完成轻量工单与附件。第二切片 WF-04—05 接通分析复用主线。第三切片 WF-06—07 完成助手和整体验收。中间切片只能声明实际完成范围，全部通过前不核销 Q-55。

## 4. 需冻结的逻辑合同

下列为待实施字段语义，不是已部署请求定义。复用既有请求 ID、期望修订、来源句柄和身份格式。

| 对象/动作 | 最少语义 | 必须守住的条件 |
|---|---|---|
| 工单 | 项目、编号、标题、问题、对象/报警/故障码语境、状态、处理人、修订、完成/归档事件 | 人工发起无故障码可用，同一来源重复提交不重复建单；不得由旧历史推断新处理人 |
| 处理记录 | 记录 ID、正文、操作者、发生/录入时间、修改历史、当时采纳引用 | 更正留痕，AI整理稿与已保存记录分开；完成结果可引用已保存记录 |
| 附件关联 | 源端文件与内容/显示版本、摘要、本单或记录位置、添加人、时间、关联状态 | 固定原件，重新授权；上传/关联分别回读；移出不删源文件 |
| 共享分析版本 | 固定分析 ID/修订/摘要、故障码语境/适用性、保存版中的分析摘要/建议、所有者明确选择的项目可读范围 | 与私人对话分开授权；助手回答先整理入画布并保存；不自动共享新修订；摘要与来源内容一起防撤权泄露 |
| 采纳分析 | 工单期望修订、固定分析引用、采纳人/时间、当前主要引用和更换事件 | 关联不等于采纳；同一工单不出现两个同时生效的主要引用；不确认工程根因 |
| 修改另存 | 来源固定分析、本次工单上下文、新分析身份和保存回执 | 原画布/其他工单不变，旧事件资料仍标历史；无权内容不复制 |
| 组合操作 | 分别返回保存、关联、采纳的真实结果 | 不伪造跨库原子事务；已保存分析可保留并单独重试关联；结果未知查原请求 |
| 画布工单资料 | 固定工单/记录修订、过程正文、结果、时间/操作者、附件引用及原分析链接 | 加卡不写工单；新进展显式载入，记录/附件可定位；原建议与实际记录区分，双向引用不递归取全文 |

每次写入前后核对当前权限和版本，记录审计。升级后的工单拒绝旧客户端诊断写动作，旧历史只读端点保持。修改应用代码时同时覆盖实际 HTTP 路径，不能仅在服务单元测试中删除旧清单门槛。

## 5. 验收矩阵

| 用例 | 必须观察到的结果 |
|---|---|
| WF-T01 普通任务 | 无故障码/无分析/无照片，发起→受理→文本记录→完成→归档成功；不出现诊断必填 |
| WF-T02 两单复用 | 两张同码测试单自动获得可见分析 A，分别人工采纳同一固定版，记录/附件各自独立 |
| WF-T03 修改另存 | 第二单从 A 修改得到 B 并采纳，第一单及 A 的内容/摘要/引用不变；B 保留来源追溯 |
| WF-T04 当前与历史上下文 | 副本使用第二单对象/事件，原趋势、旧工单、照片仍标明历史来源；不自动换成新资料 |
| WF-T05 匹配语境 | 同数字不同代码体系、型号不适用、模拟对真实均不冒称等价；候选原因明确；历史不被短趋势窗口误筛 |
| WF-T06 共享及隐私 | 本人私有可见、他人未共享不可见；明确共享版可按权限复用，私人对话/其他版本及撤权来源摘要均不可读 |
| WF-T07 采纳与版本 | 关联不等于采纳，新版本不会改旧单；更换/撤回留痕；并发采纳仅一个主要引用生效 |
| WF-T08 保存部分失败 | 分析已保存但关联或采纳失败，仅重试失败动作；无重复画布/事件，无假成功回执 |
| WF-T09 附件完整流程 | 实际上传文档与照片、引用已有文件、预览/下载、关联处理记录、移出及旧修订回读；源内容不受移出影响 |
| WF-T10 附件异常 | 上传失败/取消/重复/断网及上传成功关联失败可恢复；OCR未完成不阻塞使用，权限失效停止内容返回 |
| WF-T11 记录与完成 | 多次文本保存、更正历史、以已有记录作完成结果、归档后只读、重新处理追加周期，旧记录不清空 |
| WF-T12 权限 | 未授权建单、非本单处理人、跨项目操作、只读成员、失权后的重复请求均拒绝；处理权限不等于项目管理权限 |
| WF-T13 驾驶舱与助手 | 查询可用，驾驶舱所有业务写入后端拒绝；转后台只预填。助手不能替人采纳、完成、归档或编造现场记录 |
| WF-T14 旧数据兼容 | 五种旧状态正确显示；诊断、采纳、链接、照片、原修订/hash保持，旧固定JSON不补空字段；旧关闭不冒充归档、旧关联不冒充采纳 |
| WF-T15 并发与迟到 | 工单/分析/附件在操作期间变更、退出或切项目后，拒绝冲突并保留草稿，迟到内容不串入另一单 |
| WF-T16 UI | 深浅主题、长工程名称、1280×720和390×844可用；详情三页签、清晰层次、统一预览宽度，无嵌套诊断表 |
| WF-T17 恢复与回退 | 最新在线副本独立恢复，新旧工单/记录/附件/分析引用逐项一致；兼容回退保留新数据，不回灌旧库 |
| WF-T18 工单作为分析资料 | 完成单和未完成单均可加入画布；准确显示过程/结果/附件，助手能引用具体记录回答“做过什么、结果如何”；建议和未读文件不冒充执行结果，无结果明确标示 |
| WF-T19 处置进展回流 | 原工单新增/更正记录后，原卡及历史分析保持旧版；比较后显式载入并保存新画布修订；删除卡片不改工单，固定附件可按授权回读 |
| WF-T20 双向引用 | 分析A被工单采纳，该单再加入A或B时不递归取回A全文；原建议不重复计作佐证，新人员观察可被引用，摘要保留出处及未读/省略范围 |

自动化覆盖错误/权限/并发及兼容场景。公网使用明确隔离的模拟测试单和可分发合成附件完成两单复用、另存、记录、完成归档、重新加入画布参考处置过程/结果及驾驶舱只读；不修改用户现有案例来“造通过”。真实与模拟、合成测试与公网回执分别记录。模型只在验收确实用到助手时调用，沿用既有连接并记录实际次数和范围。

## 6. 交付纪律与剩余决策

当前用户已明确职责边界，按本方案可继续准备下一实现批次，无需再次询问是否把诊断放回画布。四态流程、一个主要采纳分析、默认本项目复用是本次设计取值，未引入多级复核或跨项目权限扩大。

新角色映射和源端接口差异先依据现有系统核对并落实到契约。只有发现既有授权无法满足实际处理人员、需要扩大附件可见范围或接入外部业务系统等新的产品决定时，才提交具体选项。设计阶段不为核对这些内容部署应用、迁移数据或触发模型调用。

维护本设计、助手计划、统一队列、指南与执行记录。新流程操作见[工单指南](../guides/演示工单操作指南.md#当前工单流程2026-11-11)，旧诊断保留历史说明。公网使用授权管理员和明确标记的模拟工单，处理人和撤权用隔离环境验证。备份同时校验原版、另存来源与工单固定引用。
