# 模型缩略图与存量补图

2026-10-24；用户要求上传模型后生成缩略图，并为现有模型补图。状态入口为[统一任务队列](统一任务队列.md)，实际验收及测试部署在[执行记录§60](开发执行记录.md#60-模型缩略图与存量补图2026-10-24)。本切片承接既有模型中心、场景资源卡片和私有GLB，不重设计布局。

## 1. 范围与身份

- 缩略图是可视化派生图，不是几何版本、场景实例、型号属性或工程证据。生成/补图不增加几何版本、不改库的几何修订、旧场景head、安装身份、关联、原GLB或校准。
- 同一项目库内，以原GLB SHA256复用一个缩略图；上传版、校准版和相同原文件可共享。不同几何的完整模型/外壳模型分别生成。图片记录保留来源模型版本及固定渲染规则`model-thumbnail-v1`。
- 缩略图展示原文件的整体几何与材质，不展示场景位置、实例名称、设备状态、绑定高亮或后加示意代理。它不证明现场身份、安装位置或工程精度。

## 2. 生成与私有存储

项目模型上传、导入已有模型、校准及保留旧显示后自动登记派生任务；原兼容上传在允许写入的范围内同样登记。模型提交成功后由单个后台线程串行生成，上传响应无需等待图片渲染。项目管理员也可显式补图或重试，普通读者只读取。

使用已安装的Node及Chrome，在受控子进程中加载由当前Three r184构建的专用渲染程序。固定正交视角按投影包围盒留边、256×256、透明背景、保留原材质及内嵌Logo贴图；无脚本/模型外部依赖，纹理加载失败不发布无贴图图片。仅把本次输入和固定程序通过随机能力路径的回环HTTP交给自有浏览器；CDP走私有管道，不开放调试端口。子进程不继承用户会话/凭据或整个父进程环境。

一次最多一个浏览器任务，30秒墙钟上限；最多100份派生图、每份384 KiB，隐含总上限37.5 MiB。原20 MiB上传、100个模型保留版和200 MiB几何总量限制不变。服务器实测原TasksMax=64不足以创建Chrome线程；保持原用户、NoNewPrivileges、ProtectSystem/Home、PrivateTmp、地址族、1536 MiB及256文件限制，仅将TasksMax改为192后成功。浏览器使用软件WebGL，不把首张生成耗时当公网上传或GPU性能证明。

私有目录为库内`thumbnails/files/<原GLB SHA>.png`，临时浏览器及输入在`thumbnails/temporary/`，完成或失败后释放浏览器进程组、资源和临时目录。不建立公开图片静态目录。仅接受校验通过的256×256 RGBA PNG；检查签名、尺寸、块CRC和有上限的解压流，拒绝SVG、JPEG替代、动画PNG、超限与尾随内容。

新增`model_thumbnails`保存来源、渲染规则、独立任务修订、状态、图片SHA/大小和操作者；`model_thumbnail_requests`保存不可改写的幂等请求。已就绪图不可原地改写；生成失败和处理中断可按当前缩略图修订重试。重启不会复用失效会话或收养半成品；未完成任务标记中断，仅清理本处理器的临时输出和已登记失败任务的未发布图片，原模型及已就绪图保留。

## 3. 服务契约

均为同源POST，沿用当前项目权限、当前sessionRevision和原请求体上限；缩略图生成需要当前管理员写权限，读取需要当前项目读权限。

| 路径后缀（`/api/workbench/resources/model/`） | 输入 | 输出/副作用 |
|---|---|---|
| `thumbnail` | modelVersionId、expectedContentRevision、expectedSha256 | 当前派生状态；不生成、不写入 |
| `thumbnail/ensure` | 上述三项＋expectedThumbnailRevision（首次null）＋clientRequestId | 登记或复用任务；相同幂等请求不重复生成，不同载荷同ID拒绝；失败重试须当前派生修订 |
| `thumbnail/content` | 原三项＋expectedThumbnailRevision＋expectedImageSha256 | 受保护PNG；no-store、nosniff、当前session及图片SHA响应头 |

状态为missing、queued、processing、ready、failed。状态对象包含独立thumbnailRevision和rendererVersion；ready时包含imageSha256、bytes、width、height。资源目录和详情附带对应状态，不生成几何版本。生成时重新校验来源文件SHA，发布时再检查权限和任务修订；撤权/退出/来源变化不发布私有图片。失败和中断不影响已上传模型的几何读取与使用。

## 4. 界面与交互

资源中心和场景共用的既有56×62卡片图区域显示真实缩略图；未进入可视区域时不获取图片，不为列表启动浏览器3D视口或下载整份GLB。生成中使用原图标与11px“生成中”；失败/缺图明确显示未就绪，管理员在详情中“生成缩略图/重试缩略图”。后台完成后按状态更新图片。中文/英文、灰绿深浅主题、主导航和三栏保持。

图片通过受保护二进制接口取回后创建本次会话blob URL；切版本、过滤、退出和卸载会中止迟到请求并回收URL。当前版本的标识与图片一起核对，避免短暂显示其他固定版本的旧图片。

MagicPath同项目模型中心`464539038066548736`、工作台`464539041816252416`只更新原资源目录两文件，展示就绪、生成中及失败重试的合成缩略图状态；示意图不冒充真实几何。两个修订均构建完成并检查云端初始页面。正式图片使用上述服务生成。

## 5. 补图、验收与部署

1. 以正常管理员API冻结当前资源身份及场景head/快照，按不同原GLB SHA登记缺失任务；已有图片复用，未知结果用原幂等ID重放，失败先查当前修订再重试。
2. 检查所有现有版本均可得到其来源对应的就绪图；全量核对图片SHA/尺寸、完整与外壳区别、模型版本数量、库几何修订、场景及工程数据保持。抽样实际UI核对图片，不能仅以存在PNG文件判定成功。
3. 定向测试覆盖自动上传、重复请求、同SHA复用、权限/撤权/退出、版本变化、PNG限制、失败重试和进程/URL释放；实际Linux服务限制下再验证受限渲染，不用合成处理器替代。
4. 配对备份工具注册并校验图片与原GLB来源，包含两新表、请求和PNG；停写B0、候选检查、新目录恢复、切换及包含新增图片/请求的B1继续既有规则。禁止用B0覆盖新数据或回退不识别旧写门的后端。

测试进度、实际数量及保全回执见执行记录，本页不以原型或首张PNG提前声明测试站全部补齐。
