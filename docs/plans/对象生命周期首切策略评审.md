# 对象生命周期首切策略评审

## 需要业务决定的差别

建议先做**可恢复停用**：标为不可继续新绑定/定位，保留身份、关系、来源与审计；项目管理员可以说明理由后恢复。这不表示设备已拆除或永久报废。

另一方案是**永久退役**：保留旧UID与历史，但不允许恢复；重新投运需另建安装身份并明确替代关系。它适合已确认的永久退出事实，不把一次演示操作自动升级为现场工程事实。

该差别决定是否提供恢复动作、旧引用如何解释以及后续重新启用时是否产生新安装UID，属于业务生命周期选择，不是前端按钮文案。两种方案均不硬删除对象，不撤回用户已取得的外部副本。

## 建议首批范围

- 仅7号演示安装范围内的对象，不批量操作原1,131个同型号定义，也不自动推广到其他机位；工程关系与正式发布继续阻断。
- 仅当前项目管理员可发起；服务端核验活跃账户、项目角色、安装归属、对象/层级修订、幂等键和理由，事务内记录审计。SSH或前端自报权限不能执行。
- 停用不自动关闭物理关系、不推导拆除日期，也不级联停用子对象。所选对象或最近定位宿主不可用时清理旧高亮、返回未定位，不跳到更远祖先。
- 有权用户仍可查看保留的对象身份和当前合法资料；退出、撤权、内容变化继续遵守现有清理/重新选择规则。旧版本对象修订不能作为当前写入条件。
- 草拟独立POST路径`/api/v1/projects/{project_code}/installations/{context_id}/objects/lifecycle`，请求携带所选UID、动作、理由、期望对象/层级修订及clientRequestId。此路径尚未实现；策略选择后再冻结具体DTO/数据库增量和页面状态。
