# 场景环境渲染配置实施方案

状态：2026-10-24已实施ENV-01—03并完成本机首批验证，测试部署和配图指南正在收尾；ENV-04为后续按需质量选项。下文保留原方案与实施前基线，准确字段以[环境V1契约](../contracts/场景环境渲染契约.md)为准，实际证据见§10和[执行记录§57](开发执行记录.md#57-场景环境渲染首切2026-10-24)。任务状态由[统一任务队列](统一任务队列.md)维护。

## 1. 结论与首批范围

可将贴图显示、PBR照明、曝光、太阳、天空/雾、局部阴影和受限水面效果纳入ONTOVis的场景配置。优先补齐**保存契约、静态环境与局部阴影，再加入海面波纹**。当前已导入的七个海上相对平面可作为首批水面验证资源。动态水面、平面反射、浮体运动和风机运行仿真应分别处理，不能因视觉效果相似而合并成工程仿真。

承接现有MagicPath工作台及三栏结构，在右栏属性增加“环境渲染”折叠分组和预设，与原“场景显示”并列，不另建整套编辑器。UI继续灰绿；天空、水面的场景颜色可独立配置，不改变产品主题。正文13px、说明11px；只在必要处显示来源、精度、降级和阻断原因。

现模型的用户确认测试使用授权继续有效，不以旧“未授权”记录阻断开发。本方案也不据公开浏览推断新纹理、HDR或整站代码的产品分发许可：首批用程序生成天空/法线和已有受控资源即可继续，不下载来源不明的HDR环境图。

## 3. TerraUrsa效果由什么组成

用户截图已只读查看：MySE18.5-260浮式机组周围有细密海面波纹、天空渐变和长方向阴影。页面的9m/s、5.35rpm、8,868kW、平台3.4°是该时刻的教学模拟状态；260m转子、170m轮毂等又属于来源规格/建模参数，两类信息不能混用。[原型号页](https://terraursa.com/wind-lab/turbines/mingyang-myse18-5-260.html)也区分公开规格、派生/建模内容和运行控件。

| 来源证据 | 实际机制 | ONTOVis采用方式 |
|---|---|---|
| MySE页面664–718行 | ACES曝光、半球光、方向太阳、2048阴影图和有限阴影相机 | 采用这些可配置能力，参数重新验证；不直接照搬r128灯光数值 |
| MySE页面720–752行、共享`sea.js` | 多个方向波的视觉位移、程序法线、近面/远环、按视角混合天空色 | 首批自主实现受限法线波纹；后续再验证视觉位移。不是一张静态海面贴图 |
| MySE页面738行附近及运行逻辑 | 平台运动另由模拟参数驱动，并非单由水面shader计算 | 本批不接入浮体姿态、转子/输出模拟，不移动实例安装变换 |
| Dogger共享hero模块 | 太阳/天空/海面共用视觉参数，雾衔接远海；部分效果为专用shader | 用统一场景环境参数协调颜色和方向，保持ONTOVis自身渲染实现 |
| Crystal地形模块 | 真实来源影像贴图与程序地表、局部太阳阴影；阴影只覆盖近处 | 保留影像来源/日期和地形精度；不把12km场区全部塞进一张低清阴影图 |

来源站点有版权保留，且r128/r160源码依赖与本产品Three r184不同。已派生静态GLB还曾规范化部分材质扩展；添加环境光无法恢复原站全部材质、UV和交互，更不能承诺逐像素或同等材质复制。原始HTML/JS只作本机分析证据，不移入产品包。

[Three的MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)支持金属度/粗糙度PBR；[颜色管理说明](https://threejs.org/manual/pages/color-management.html)要求颜色贴图与法线、粗糙度等数据贴图分别处理。首批沿用模型已有PBR，baseColor/emissive按sRGB处理，normal/ORM用NoColorSpace，不把所有贴图统一改为sRGB，不重写源模型版本。

## 5. 拟议配置合同

### 5.1 场景快照候选

保留原`defaults`三项；新增可选`environment: SceneEnvironmentV1 | null`，不把defaults任意扩成无界字典。缺失表示旧景尚未采用，null表示用户明确恢复legacy（须写能力确认）；读取时不把两者互相改写。下面是2026-10-23的候选示例，冻结后的准确字段、范围和预设差异见环境V1契约；仅声明已实现的水面模式。

```json
{
  "environment": {
    "schemaVersion": 1,
    "renderProfile": "standard-v1",
    "presetId": "offshore-overview-v1",
    "color": {"toneMapping": "aces", "exposure": 1.0},
    "lighting": {
      "hemisphereIntensity": 1.0,
      "environment": {"source": "procedural-sky-v1", "intensity": 0.8},
      "sun": {"enabled": true, "azimuthDeg": 135, "elevationDeg": 35,
              "intensity": 2.0, "color": "#fff3df"}
    },
    "atmosphere": {
      "sky": "gradient-v1", "topColor": "#8daec0", "horizonColor": "#d7e0dd",
      "fog": {"mode": "linear", "nearM": 1500, "farM": 13000}
    },
    "shadows": {"mode": "sun-local", "quality": "balanced", "radiusM": 500},
    "surface": {"imageryShading": "source-color", "textureSet": null},
    "water": {
      "enabled": true, "baseSurface": "active-flat-relative-terrain",
      "mode": "normal-waves", "travelHeadingDeg": 20,
      "rippleStrength": 0.35, "amplitudeM": 0,
      "wavelengthM": 20, "travelSpeedMps": 0.6,
      "color": "#507d91", "roughness": 0.3,
      "reflection": "procedural-sky", "seed": 771
    },
    "animation": {"defaultPlayback": "playing", "initialPhase": 0}
  }
}
```

- 每个对象严格allowlist，拒绝NaN/Infinity、额外字段、非法颜色、超范围数值、任意URL、用户shader/JS。示例参数只是初始候选，不代表实海况。
- 曝光倍率候选0.25–2.5；太阳方位0≤角度<360、高度5–85°、视觉强度0–5；颜色为`#RRGGBB`。阴影半径100–1000m，质量映射到受限1024/2048图；雾0≤near<far≤100km。太阳角度为“朝向太阳”的方位，非风向FROM。
- 波纹行进方向明确为TO，北0/东90；地理场景经锚点真北/网格收敛转换，局部场景只能称局部北。方向/速度是视觉参数，不能自动从测点风速推导海况。
- `rippleStrength`无量纲；法线波模式的`amplitudeM=0`。不能把法线强度冒充米制波高。ENV-04若启用位移，候选波幅0–2m、波长5–200m、行进速度0–5m/s，并按所有波的总幅值约束；不以“显著波高/海况等级”命名这些视觉参数。
- 保存seed、算法/预设版本、静态参数和默认播放状态；运行playhead、实际降级质量、GPU资源及当前时间不写进快照，不产生逐帧修订。重开从固定初始相位开始。
- 内置预设/程序材质有明确版本号；后续纹理集固定引用形如`textureSetVersionId + expectedContentRevision + expectedManifestSha256`，不保存可变路径或第三方URL。

### 5.2 旧景与旧客户端

1. `environment`缺失时，在渲染内存中适配`legacy-v1`，保留现有plain/sky、neutral/dusk、solid/grass的准确颜色/灯光、无阴影、原影像行为；当前r184默认NoToneMapping/曝光1也应显式记为legacy策略。**open不补写字段、不新建修订，不把旧default自动升级为ACES。**
2. 管理员明确采用新环境后，才把`environment`写入正常场景新修订；旧快照/旧修订保持原JSON与表现意图。取消预览不调用保存。
3. `SceneCapabilities`候选增加`environmentSchemaVersions`、`waterModes`等受限能力。含环境的check/save拟要求`environmentWriteVersion:1`作为写能力确认；新后端拒绝旧客户端无确认地漏掉/覆盖已有environment。明确重置legacy也走带确认的受限请求，不靠删除未知字段实现。
4. 未知schema/mode不可编辑或静默改写；可降级只读显示并提示，不能将降级结果保存替换原环境。前后端同时版本化，先部署新后端和能力声明，再开放新前端写入。
5. `scene_geometry`和`scene_library`均严格校验。anchor、terrain/model replacement、legacy migration及相关receipt检查必须完整携带environment，空间变更不能暗改/丢失它；纯环境改动也不得改coordinateFrame、placement、绑定或固定模型版。

### 5.3 保存、版本、权限与备份

ENV-02/03复用`scenes/check`、`scenes/save/open`；不新增无权限的视觉写通道。保存继续用当前project/admin、expectedSceneRevision、幂等请求、工程/空间条件；后端验证environment和其固定引用。一次采用环境是一份场景修订，不是新模型版；场景中的100台同型号机组继续共用已有固定模型。

后续纹理资产若确有上传用户，才新增窄范围私有资源合同：`POST /api/workbench/environment-assets/upload|version|content`、`surface-materials/create|version`为候选路径。单张PNG/JPEG先限制2048²、最大4096²、文件≤16MiB，单纹理集最多baseColor/normal/ORM三张、总解码≤16M像素；角色、色彩空间、通道、来源/许可/署名、用途、文件/manifest SHA都由后端检查。拒绝SVG、外链、压缩包穿越和用户程序；不为此建立通用素材平台。HDR另行定义格式/解码预算，当前不获取或接受任意HDR URL。

资产上传、创建材质集与场景引用均受项目权限和版本条件控制；content读取同样要求当前会话及固定SHA。`SceneOpen.environmentRefs`记录实际固定资源，撤权时中止在途读取并清空相应GPU资源；引用保留/使用去向、配对备份、恢复清单和B1保护必须覆盖新资产。ENV-02/03只有配置/内置资源，无需先建资源库或写OntoBase表。

## 6. 预览与渲染细则

### 6.1 预览、采用、取消

右栏分“预设、光照、天空、表面、水面、高级”，默认只展开常用项。滑动参数只更新本地预览，每帧合并请求，不逐pointermove做远程几何check。松手/采用时一次验证；程序环境生成做有界延迟合并，不能拖一次曝光就重载全部GLB或重建renderer。

“采用”把受限配置加入当前场景草稿并标未保存；正常“保存”持久化。“取消”恢复进入预览前的场景环境、播放状态和资源引用，保持相机/选择/位置不变，释放试验纹理/RenderTarget，恢复按需绘制。退出、切场景、撤权和预览迟到回调均按当前epoch/意图取消；只读用户可有个人临时查看偏好，不能写共享场景或上传资源。

### 6.2 PBR、影像与阴影

- GLB原有金属/粗糙度和嵌入纹理是默认依据；全局环境光不是重写模型材质。若未来确需材质覆写，只克隆当前视口所需Material，保留源components/nodeIndex与校准矩阵，不修改共享cache/原GLB，恢复/释放不污染其他实例、视口和预览。
- **资料原色**：保留影像几何UV、掩膜和署名，MeshBasic及`toneMapped=false`保持原色意图；不能因全局ACES使资料图无声变色。此模式不承诺接收真实灯光阴影。
- **照明显示**：采用同UV/掩膜的受光表面，可接收阴影；界面明确这是视觉照明，影像本身可能已有拍摄阴影，不声称已消除或物理校正。不得从RGB亮度推导几何高程/法线以改变工程表面。
- 单方向太阳投影，从太阳position指向target；[Three的方向光合同](https://threejs.org/docs/pages/DirectionalLight.html)不以Euler旋转直接设朝向。半球光/环境光不各开一套阴影。
- [官方阴影说明](https://threejs.org/manual/pages/shadows.html)指出每个投影光源会增加场景绘制。平衡档用一个1024局部阴影图、当前选中/近处有限投射物，固定太阳/静态模型时缓存，不让水纹每帧重算静态阴影。2048高质量与更大范围须单独过预算；全景不承诺每个远机组都有清晰投影，不用一张图覆盖整片风场。

### 6.3 水面、基准与拾取

ENV-03仅支持用户明确采用的**当前有效、平坦UNKNOWN_RELATIVE定位面**：后端检查高程范围近似常数、固定地形引用及用户选择。已有七份合成海上平面符合此验证方向；不能按名称中“海”字或DSM颜色自动认定海域。局部场景/起伏DSM/真实岸线需另定视觉面范围和高度来源，首批明确不支持，不静默铺满整张地形。

启用水面需要明确选择该显示方式；同一覆盖区域只保留一个可见色彩表面，避免已采用的海面色板盖住水纹或双层深度闪烁。影像固定引用及其可恢复显隐意图保留，关闭水面即恢复原影像；不能悄悄删除遥感资料或改其UV/掩膜。水面查看时在图层状态标明当前显示水面，资料原色模式另行选择，不以抬高定位网格来消除闪烁。

水面是独立视觉层，保留原固定terrain mesh与高度报告；法线波不移动顶点。后续位移波只改变独立water mesh，视觉波峰/波谷不参与贴地、海拔、模型校准、测量、物理层级或分析对象定位。不能让浮式平台跟波面移动后回写实例安装位置；真实基准和相对reference都不改。太阳、水色、雾等变化也不生成新的frameRevision或terrainVersion。

沿用当前`groundPoint`只对原terrain mesh求交、`hitModel`只对models组求交的分离。water/sky/shadow辅助层不进模型或构件拾取集合；水面外的背景环不可放置。选择高亮、柜体/构件拾取、无几何子设备最近有效祖先定位仍用原模型/空间宿主，不以波浪表面代替分析对象。位移模式再测CPU Raycaster与GPU显示差异，并持续提示“按定位基准面放置，水波仅显示”。

### 6.4 动态时钟与降级

- 关闭水纹、暂停或静态场景保持按需绘制；动态平衡档最多30次视觉时间更新/秒，镜头输入请求仍合并在同一RAF，不另开永久定时器。
- document.hidden后取消所有环境RAF/反射/阴影更新；恢复用累计可见时间，首帧dt=0，不把后台时长补进波相位、镜头或路线。GLB/地形/纹理未变不重取，沿用同renderer。场景动画与现有tween要共用生命周期，不能两套循环争抢。
- 默认尊重prefers-reduced-motion：波纹/动态云停在固定相位，保留静态颜色/阴影；个人明确播放可作临时偏好，离开重置，不改共享快照。系统改变时即时响应并清理监听。
- 自动质量降级先关平面反射、再降阴影/动态更新、最后静态水色；不移动模型、删除组件、改LOD精度标识或改变数据基准。保存“希望的质量档”，实际生效档是本机状态并可见，不反复写场景修订。
- 卸载/切景/退出释放水面/天空geometry、material、法线纹理、PMREM输出、阴影/反射target及监听。已有[renderer清理](../../apps/workbench/src/sceneRenderer.ts)和controls隔离测试必须保留，新增多视口/迟到回调反例。

## 7. 性能预算与验收

以下是**拟议门槛，不是已有测试结果或帧率保证**。固定设备/浏览器/分辨率/DPR、相同模型/相机和暖缓存，以环境关闭为基线；CPU提交、实际GPU计时、内存与视觉结果分别记录。当前100实例仍是探限样本，不能因该功能通过就写稳定30fps。

| 档位 | 可用效果与预算候选 | 超额行为 |
|---|---|---|
| 静态/低动态 | 无连续动画、无平面反射；阴影关闭或单1024；程序环境一次生成 | 保留按需绘制，拖动不增加资源重新下载 |
| 平衡首发 | 程序PBR环境256级、单1024局部阴影、≤8投射实例且≤250k阴影三角、1张256²法线；新增GPU纹理/target估算≤32MiB/视口 | 动态水纹≤30Hz；20实例相同镜头下CPU提交额外P95≤4ms且总提交耗时增幅≤20%，未达则缩档再测 |
| 高质量后续 | 2048局部阴影≤500k阴影三角；可选1个256反射target，最长15Hz刷新 | 只在单机近景开放；反射额外场景pass必须计数，不能默认覆盖100机全景 |

[Water官方说明](https://threejs.org/docs/pages/Water.html)及本轮固定r184源码表明平面反射需要额外target和镜像场景pass；当前r184 addon还把target封装在内部。首批不直接接入未完成生命周期管理的addon。后续若采用其MIT代码，应保留署名/固定版本、显式管理target释放和嵌套render状态，并验证与现有DFG_LUT清理及模型预览互不干扰；不把Water的视觉反射当流体求解。

验收按批次补证，不重跑无关历史套件：

1. **合同/兼容**：旧景open/无操作保存前后defaults与快照不变；新环境保存重开参数、预设/算法版本和资源SHA一致；缺失字段、未知版本、非法枚举/颜色/范围、NaN、越权/过期修订均有拒绝反例，拒绝后0业务变更。
2. **预览**：连续拖动只更新本地；取消恢复环境和播放/静态状态，无新修订，选择/相机/位置不变；快速换资源、切景、撤权的迟到结果不覆盖当前场景。
3. **资料与视觉**：原色模式的影像不受曝光/太阳改变；照明模式有明确标识。一个MySE近景、一个20实例海面、一个有来源影像陆地景记录日光/黄昏、天空/雾、阴影/水纹开关；不以截图“像”代替所有合同验收。
4. **空间不变量**：环境开关前后frame、实例经纬度/高程引用/采样、安装绑定、源componentKey完全一致；至少100条固定射线对模型/构件/柜体/地形的命中标识一致，水面不成为落点或分析对象。未知子设备仍定位祖先而保留自身身份/图纸。
5. **生命周期**：重复进入/退出10轮后，卸载资源计数归零，再按既有GC方法检查保留引用/增长趋势，不能用计数替代堆证据；实际hidden持续5分钟0环境绘制，恢复同renderer/固定资源且相位连续、镜头/路线不跳跃。reduced-motion初始和中途变化各验一次。
6. **预算**：同设备同视角的1/20/100实例，静态/交互/动态分列；记录新增render pass、calls/triangles、CPU提交P50/P95、可用时的GPU计时、纹理/target估算、GC后堆和峰值。不支持GPU计时时标缺口，不把CPU提交次数称GPU完成FPS。
7. **部署/恢复**：Linux新后端合同及资源读写权限、新前端同源CSP/资源清理通过；配对备份含固定纹理资产并可新目录恢复。已有environment写入后不回退到不识别其schema的旧后端；必要时保护B1并保持维护状态。
