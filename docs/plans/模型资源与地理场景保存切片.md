2026-10-22。承接[Q-01基线](场景页面与服务契约冻结.md)和[上一批场景/地形服务](场景保存与地形服务切片.md)，实现项目模型资源、固定校准版本及首次地理锚定。Q-02/03继续进行中；本批是服务实现，尚未更新测试站或接入产品场景页面。工程关联、多实例渲染及旧7号关联迁移仍有后续工作。

## 1. 项目模型资源

同一工作台新增六条同源POST，继续采用本人会话和当前项目授权；成员读取，管理员上传/校准。无需先读取默认7号安装对象，也不接受客户端指定另一个项目、上游地址、服务器路径或审核人。

| 路径（`/api/workbench`后） | 当前实现 |
|---|---|
| `/resources/models` | 资源分组、用途/名称筛选、固定版本摘要；游标绑定本人/授权/库快照 |
| `/resources/model` | 明确资源及版本的报告、构件目录和校准状态 |
| `/resources/model/content` | 期望内容修订和SHA-256核验后的私有GLB |
| `/resources/model/upload` | 新建项目资源，或为指定资源追加版本；不更改已有场景 |
| `/resources/model/calibrate` | 为同一资源生成新的固定校准版本；旧版本保持不变 |
| `/resources/uses` | 当前仅支持`resourceKind=model`；区分当前实例、保留实例及保留修订引用 |

沿用静态自包含GLB、20MiB/文件、全库20版本/200MiB限额。校准版本的私有文件也计入容量；没有为每个资源另开额度。上传需要来源说明和使用权声明；未校准可独立预览，不可放入新场景。目录、报告、内容指纹和校准进入独立`contentRevision`，旧版工程绑定修订改变不会改变这个身份。用途为设备、简化场景或环境，不能把资源用途当设备工程类型。

本批校准输入只接受米、右手Y向上、基点及非零水平正面向量。服务归一化正面并计算刚体矩阵，把基点移到原点、正面转向−Z；验证者及时间来自当前本人。禁止客户端提交矩阵、审核人或脚本，也不支持任意缩放/轴向转换。`verified`仅表示操作者已完成这一步，不表示模型匹配现场或达到测量精度。

文件先在私有目录受限处理，再与资源/版本/请求结果/审计一起登记；提交前重查库修订、权限和内容。相同本人/动作/UUID请求重放取回原结果；不同载荷拒绝。上传或校准的清理即使遇到文件系统错误也释放处理槽，返回明确存储错误，避免后续请求永久处于忙状态。提交已完成而返回阶段失败时，以同一请求重试可以取回原结果。

## 2. 首次锚定、移动与保存

`/scenes/check`新增真实只读预检，`/scenes/save`和`/scenes/open`扩展为配置可选GIS运行时后的未关联地理场景；没有配置时仍只支持局部场景。能力响应与实际配置一致，不返回假地理成功。坐标、字段和误差含义见[服务契约§6](../contracts/场景资源与多实例服务契约.md#6-坐标地形与首次地理锚定)。

1. 上传并校准项目模型；创建局部场景，可加入多个独立放置。
2. 选择固定地形和明确的局部/经纬度锚点、真北朝向及高度策略。预检先核对旧头、锁定与资源，再变换全部布局和初始相机。
3. 返回规范快照、固定资源身份、高程依据和锚定签名回执；预检不保存共享草稿，也不占用编辑锁。
4. 最终保存携带同一旧头、规范快照及回执。服务重查当前本人/授权、资源、实际GIS结果和旧头后原子提交；旧头、他人回执或修改后的快照均拒绝。

回执绑定项目、本人、授权修订、场景旧头、旧/新快照及资源摘要；不是写权限凭证。已保存地理框架不能由普通拖动偷偷更换。锁定对象不能在预检中移动或删除；首次锚定只把同一布局换成地理编码，不能借此绕过锁定。

普通地理位置修改先调用`check(kind=validate)`重新采样，回传规范快照保存；save仍严格核对固定三角网及采样值，不信任浏览器自报高度。重采样开关只存在服务内部，公共请求不能指定解释器、路径或跳过校验。已知基准的指定高程可位于地形覆盖外；贴地要求有效覆盖，NoData洞不能桥接。未知相对基准仍禁止绝对高程和地球坐标转换。

服务重建固定投影框架，分别处理场景原点与地形资源原点；安装朝向包含真北/投影方向修正，初始相机眼点和目标同时变换。当前是WGS84 UTM区域米制框架，不是严格ENU。模型安装朝向不等于运行偏航。

地理快照、派生校验/高程依据、固定模型及地形引用、头、请求结果和审计在同一SQLite事务保存。地形外键保护保留修订；模型校准内容身份也固定。GIS在写事务外执行，提交阶段再检查旧头、身份和当前授权，避免长时间持有写锁。几何子进程并发1，输入1MiB/输出2MiB，CPU30秒/内部墙钟60秒；Linux地址空间512MiB，父进程另有65秒及输出边界。失败、取消或退出后的迟到结果不提交。

## 3. 验证及边界

新增模型库、模型HTTP、几何、受限进程、空间保存及真实GIS HTTP的定向验证分别为26、13、28、12、23、14项，隔离Linux合并116项全部通过、无跳过。它们覆盖实际私有GLB/SQLite/回环HTTP及线程，认证为明确合成权限；真实栅格处理不替代实际OntoBase账号授权验收。实际运行时另核验两个GIS进程的软/硬地址空间均为536870912字节、CPU均30秒，不以配置字符串代替执行证据。

真实GIS HTTP夹具为32×32、EPSG:32649、EGM2008/米，经过实际GeoTIFF处理子进程和几何子进程。固定显示网格最大接触误差约0.0000038米，仅指同一浮点网格的数值接触；源地形近似误差未知、现场精度未核实、无垂直基准转换、外部资源抓取为0。不能把这个数值标成现场定位精度。

旧7号模型库只读复制了1个固定版本、3条旧关联，文件4669488字节；原服务/源库未改变。完整关联迁移还必须在逐实例关联可用后验证唯一兼容场景，不能复制绑定形成两份真值，也不能通过清空关联把迁移写成完成。

离线恢复工具为[model_store_recovery](../../tools/model_store_recovery.py)：只读预览先核验全部外键和已登记GLB，再列出未登记UUID文件及四类已知暂存。实际清理需要停服声明、期望报告摘要和写事务内重核；已登记模型、未知文件及业务表不清理。拒绝断链引用、损坏、符号链接和不支持的WAL格式，SQLite忙锁有界返回。文件删除不承诺跨文件原子性，中断或部分失败后重新预览；不自动在运行中扫描删除暂存。18项定向测试含实际SIGKILL后的SQLite回滚、孤立文件恢复、旧绑定/场景不变及失败重试。本轮不对原库执行清理。

完整后端基线346项在隔离Linux通过（194.173秒、无跳过），随后独立复核发现“父版本断链但历史/绑定仍引用”可能误判孤立文件，已增加外键完整性拒绝和回归。修复后只重跑受影响恢复18项（10.367秒），另329项对应源码摘要未变；当前共347个独立案例均有通过证据，实际执行364测试次，不宣称旧346项已覆盖后来修复。副本恢复删除1个54字节合成孤立文件后，注册GLB、3条绑定、4条审计、业务行和数据库文件指纹不变；未知文件及未知符号链接保留，忙锁约252毫秒拒绝。详[完整本机证据](../../output/q03-project-models-20261022/README.md)。
