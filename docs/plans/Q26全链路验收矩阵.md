## 13002 回执丢失回归

在 `ONTOVIS_ANALYSIS_TEST_DATABASE_URL` 指向独立临时 PostgreSQL 的环境中运行以下用例。

```sh
python3 -m unittest tests.test_work_order_workflow_integration.WorkOrderWorkflowIntegrationTests.test_simulated_13002_archives_once_after_losing_the_record_response
```

用例从 13002 模拟事件建单，采纳固定分析修订，在处置记录提交后丢弃 HTTP 回执。同一请求复用原编号确认结果，只保留一条记录。项目撤权后重放返回 403，归档后回读处置结果、初始工单版本和固定分析。浏览器验收另覆盖“检查结果”按钮、分派处理人、已撤权页面清理及查询成员。

2026-11-22 已复核前后台 `2e80028f` 及源端 `e0dedd54`。公网报警定位、相关工单筛选和驾驶舱查询通过，写入返回 403。三张原有同码工单的摘要和分析推荐在发布前后匹配。[执行 §258](开发执行记录.md#258-q-26-13002-断线回执与发布复验2026-11-22)。

## 执行顺序

1. 登记本次验证的入口、终端、浏览器、网络、项目和用户角色。记录实际发布、固定场景、模型、资料、分析和工单的修订。对原有数据的写操作使用隔离副本。
2. 验证正式入口链路和资料来源，同时覆盖空结果、过期修订、并发冲突、撤权和来源中断。以服务端回执、固定来源回读、实际界面和前后对账作为通过证据。
3. 记录本轮范围内的性能、完整失败样本和恢复结果。照片公网冷读 P95 ≤ 5 秒的 [Q-23 专项](../design/分析画布Q23操作设计.md#112-交互和时延目标)按用户决定暂停。核对已测试场景的权限、固定引用和回退。
4. 对照矩阵逐项登记通过、未通过或缺输入。当前进度为测试站检查点和验收准备，Q-26 与正式试点保持开放。
