# 受保护证据与旧入口授权评审

2026-10-21 · 下一批范围选择，未实施。前一批[简单登录与7号读取](公网会话与工程读取评审.md)已在vis.ontobase.ai完成，当前选择不会影响空间演示或已建立的五个演示身份。

## 需要确定的范围

建议先收紧Demo-PDS。原文授权必须覆盖对应旧入口；只给ONTOVis新增受保护入口，不能同时保留同一图纸的无鉴权旁路。收紧后，旧直链、未登录或不是该项目成员的访问者会被拒绝，已有使用者可能需要补项目成员权限。现有测试账户的Demo-PDS成员授权已经完成，不自动给其他账户或项目扩权。

| 方案 | 本批改变 | 影响 |
|---|---|---|
| 先仅Demo-PDS（建议） | 本项目旧图纸/PDF/图片及相关定位元数据按本人登录＋当前项目成员读取；为7号演示子对象接入其关联图纸页 | 本项目旧匿名直链失效；先验证成员及Web兼容，其他项目保留当前行为，不能宣称全产品资料隔离 |
| 全部项目统一 | 对上述资料路径统一应用当前项目授权；ONTOVis仍只接7号子对象关联页 | 未建成员关系的项目用户将被拒绝，须先核对全部项目成员与旧Web入口；不按用户名或系统管理员自动放行 |

这是访问范围及现有用户兼容选择，不请求再次提供账号密码、模型授权或三柜演示确认。选择后继续完成MagicPath证据页状态和服务切片；正式工程绑定/发布不随之开放。

## 已核对的实际缺口

依据测试部署同版源码a08c6412：`apps/api/ontobase_api/main.py`的`get_drawing`、`get_drawing_pdf`、`get_drawing_image`和`list_object_locations`没有逐请求项目成员依赖，图片仍返回`public, max-age=31536000, immutable`。已有严格授权的对象/安装API不覆盖这些旧路径，不将新登录完成等同于全产品资源隔离。已缓存到客户端/边缘的旧副本不能靠新鉴权自动撤回，需要核对缓存路径/策略并清理可控副本。

现有Web的图纸组织、批量审核、标题区域、操作历史、知识图谱等使用这些图片/PDF入口。实施前检查每个调用点；通过既有授权请求取得内容，清理对象URL/页面缓存，不把令牌放入URL。避免仅改后端导致本人登录后图片全部失效。

安装层级当前的evidenceRefs为`snapshot_only`的证据记录摘要，不是文档版本归档。7号子对象的来源仍是型号接口定义，演示父链不作为原文证明的现场物理事实。

## 选定范围后的实施切片

1. 在OntoBase自身后端为选定项目的旧入口统一检查当前活跃用户、实际图纸项目与当前成员；不接受客户端自报项目/文件路径。拒绝不泄露无权项目或资料的数量。
2. 补齐既有OB-C06的受控证据列举/打开子范围（路径尚待实现评审，不在此虚构已上线API）。从权威证据引用解析7号演示子对象的型号来源；只返回真实可访问关联页，不从柜名或几何生成引用。
3. 固定来源版本/实际文件摘要、页码及区域；没有可靠区域就整页，版本或原文缺失明确不可用，不悄悄切最新。文件仍由OntoBase保管，ONTOVis不直连数据库或对象存储。
4. 在同一MagicPath工作台补齐证据页：未开放、读取中、可读、无权、版本变化、原文缺失/失败；打开后仍分列分析子对象和CN空间宿主。本人退出/过期/撤权关闭原文、清内容与高亮；不增加批量资料或公开分享入口。
5. 定向验证两用户/跨项目拒绝、权限撤回、匿名旧直链、缓存、固定版本、缺原文、错误不报空成功、退出和迟到结果，并回归受影响的旧Web查看入口。使用合成隔离数据库和已授权真实只读联调，不运行Human Gold冻结验证，不修改识别结果。

验收证据、受影响项目和旧入口清单必须单列。R-07原文子范围通过也不等于受控退役、正式持久绑定、G1/G2/G3整门或现场工程核实通过。
