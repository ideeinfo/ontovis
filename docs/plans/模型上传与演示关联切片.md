# 模型上传与演示关联首切

2026-10-22（始于21日晚）。承接用户继续开发模型上传、三柜关联和子设备定位的授权；停用、退役暂缓。附件仅用于灰绿深浅配色，沿用原MagicPath模型中心与关联工作台结构，不另做产品壳。

## 页面与服务边界

模型中心保留模型、处理报告和版本信息，四步上传为选择文件、填写名称与来源/授权说明、实际上传校验、查看结果。首切接收不超过20MiB的自包含静态GLB 2.0；不做在线CAD转换、压缩扩展解码或后台任务平台。20MiB为本切片实际限额，替代旧原型200MB建议，不代表所有文件均可流畅渲染。

技术校验成功只表示可在受限预览中打开。新上传形成不可变模型版本，不替换当前模型或继承其工程关联。来源身份、坐标和现场等价仍待核实，版本内构件键不自动跨版本迁移。失败保留可读原因，不生成成功版本。

项目管理员可以为当前7号三个已存在的柜级UID选择构件并保存演示关联；不新建或修改OntoBase工程对象。服务端重新核验当前角色、精确UID/对象修订、完整机组父链、层级修订、模型指纹与关联修订；同一构件不允许同时作为两个柜体的主表示。子设备仍由完整祖先链定位最近已关联柜体，保持自己的身份与图纸。

## 首切接口

所有路径同源、当前本人会话、部署固定项目与机组；浏览器不能提供上游地址、项目权限或服务器文件路径。

| 路径 | 请求与结果 |
|---|---|
| POST `/api/workbench/models` | 空JSON；返回当前库修订、管理员上传权限、限额与模型版本列表 |
| POST `/api/workbench/models/upload` | 原始GLB字节；有界`X-Model-Metadata`携带会话/库期望修订、幂等请求ID、名称、来源/授权说明与使用权声明。流式接收至私有临时文件，资源受限进程校验，成功后原子保存版本、报告和追加审计 |
| POST `/api/workbench/model` | 原有空请求继续读当前模型；可显式选择`modelVersionId`读取新版本演示预览元数据 |
| POST `/api/workbench/model/content` | 期望SHA256；新版本另带`modelVersionId`、`expectedModelRevision`与`expectedViewRevision`。读取前后复核身份、授权和关联修订，返回no-store GLB |
| POST `/api/workbench/models/binding` | 明确版本/构件、柜级UID、期望对象/层级/模型修订和幂等ID；保存演示关联并追加审计。无工程确认、发布或现场控制 |

ONTOVis自有库保存在私有可写目录，模型文件、实际UID与审计不进入Git/MagicPath或静态站点。仅当前项目管理员写入；普通项目成员保持受保护读取。上传限并发、文件/几何/贴图/CPU/内存/时长和项目容量；文件内URI、扩展加载、脚本及任意归档不被执行或抓取。退出、失效或撤权拒绝迟到结果，已完成的文件上传可在模型中心重新读取；关闭页面不承诺撤销已提交文件。

具体页面在同一MagicPath组件续改；正式实现和部署状态、测试证据按执行记录更新，本文不把接口提案当作已上线。

## 本机实现与验证

页面已在原MagicPath组件修订463695831967600640完成，正式代码使用相同结构和配色。模型库固定项目/设备上下文并在启动时核验，SQLite与不可变GLB均在私有目录；仅项目管理员写入。只失去模型写权限时保留合法读取，失去项目成员权限时清理会话中的工程数据。

资源约束为20MiB、2000节点/500网格、50万三角形、16张且单边不超过4096像素/总计16,777,216像素的嵌入PNG/JPEG；Linux子进程192MiB地址空间、6秒CPU/12秒墙钟，并发校验1，库20个版本/总计200MiB。这里只支持GLB静态子集，不声称完整Khronos验证、自动优化或任意转码。当前已授权派生模型实际报告为181网格、113804三角形、24组源构件；同一已知指纹可附原有两柜示意，精度保留。

本机76项后端、20项前端、严格类型/构建及24项浏览器闭环检查通过。新增模型不会替换当前配置模型；每次在模型中心显式选预览。旧关联变化时显示需核实，停止高亮，不跳过失效的近层柜体改用远层设备。服务器部署与实际OntoBase验证另记，未据此解除工程发布阻断。
