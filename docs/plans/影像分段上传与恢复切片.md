# 影像分段上传与恢复切片

2026-10-25，Q-08 大文件与历史524的后续实现。沿用影像库、固定版本、同一MagicPath工作台与已部署的结果核对，不改模型/地形上传、网络配置或工程源。

## 问题与范围

既有公网3.87MB原请求重放虽成功，完整响应116—127秒，源站持续慢速接收请求体；该证据不能区分具体网络段或历史524的读/写超时原因。[Cloudflare官方说明](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/)当前列出默认125秒响应读取、30秒请求写入超时，并建议大处理状态轮询。本次用短的受控上传请求缩小单次风险，不通过放宽认证、提高全站时限或改共享隧道规避。

每段最多128KiB、总文件仍8B—64MiB。该固定入口先由Nginx以128KiB缓冲接收完整片段，再交后端核权、校验并推进清单，慢速请求体不占后端接收互斥；旧整包代理策略保持。最后在源站本地读取完整文件，沿用50秒受限GIS校验和原固定版本幂等提交；不是新通用任务平台，也不承诺任意低带宽下单段一定成功。旧整包入口保留兼容，新的工作台影像上传使用分段协议。

## 服务契约

全部为同源POST，要求会话版本、场景项目、Origin/Host和当前源项目权限，no-store。读状态只允许本人；开始、分段、完成、放弃均重验管理员写权限。上传ID不是授权凭证，不跨用户/项目访问。

| 路径 | 输入及行为 |
|---|---|
| `imagery/uploads/start` | 原metadata、expectedSourceSha256、bytes。本人同请求号/说明/指纹/长度幂等恢复原上传；不同内容冲突。已入库直接返回原固定版本，不再传文件。 |
| `imagery/uploads/status` | uploadId；返回当前uploadRevision、已持久确认receivedBytes、总bytes、原metadata/指纹和期限；已提交可回读原固定版本。 |
| `imagery/uploads/chunk` | application/octet-stream，单一Content-Length及base64 X-Imagery-Chunk，含uploadId、offset、expectedUploadRevision、expectedChunkSha256与会话/项目。只接受连续位置；重复的已确认区间逐字节/指纹匹配才只读返回当前状态。 |
| `imagery/uploads/complete` | uploadId、expectedUploadRevision；完整长度与全文件SHA通过后调用原入库方法，不创建新场景或改变旧引用。 |
| `imagery/uploads/cancel` | uploadId、expectedUploadRevision；只移除未发布的本次临时接收副本，不删除影像固定版本。完成中的互斥冲突重查结果，不冒称已取消。 |

响应为`state:receiving`及上传描述，或`state:completed`与原ImageryVersion。原`imagery/upload-result`仍按原请求/说明/源SHA核对最终结果。

## 持久化与失败

在当前项目私有影像目录内保存至多2份活动临时上传，各不超过64MiB，自创建起24小时，接收进度不延长期限；原库1GiB/20版限制保持。小型JSON接收清单只含来源metadata、本人标识、长度/指纹、已确认偏移、修订与期限，不含密码、cookie或可复用授权。不是工程事实存储；不增加业务表。

先写文件并fsync，再原子更新清单及目录同步。进程在文件写完/清单提交前中断留下的尾部不算成功，下一次受控分段从清单偏移重写；短于已确认偏移、指纹改变、符号/硬链接或未知目录形态拒绝，不能悄悄承认损坏片段。服务重启保留已确认部分，重新取得本人当前权限后才继续，绝不恢复旧会话授权或自行发布。

完成仍用原actor/requestId/metadata/sourceSHA幂等提交。入库后响应丢失或进程在临时清理前中断，先查原结果，保持同一固定版本；成功后清理临时文件，短期完成回执保留至期限。过期只清理已识别的临时上传，不动已登记版本、场景、旧模型或未知文件。单进程互斥与有界接收为当前测试部署范围，不冒称生产多进程能力。

## 页面状态

显示已确认字节进度及本地校验/提交状态。上传中可暂停；暂停只中止本次客户端请求，已确认部分保持，恢复先查服务端偏移，不把浏览器发送完成当源站接收完成。网络错误不自动无限重试，保留原文件与请求，显式继续；最终结果不明仍可只读核对。

本人的未完成上传列在影像面板，可重新选择同一文件继续或放弃临时副本；恢复前核对完整SHA与长度。刷新不保存文件字节/凭据，重新登录与选择相同文件后恢复原请求；不同文件明确拒绝。项目切换、撤权、退出和迟到响应仍由既有请求门清理。

## 验收

先跑接收状态/原子性/幂等/权限/冲突/重启/损坏与容量反例，再接真实HTTP及本机正式UI故障注入。受限Linux、候选及备份恢复按本批实际源码执行，不借旧测试数字冒称本轮。

公网先验证分段响应与中断恢复，再以明确标注的合成GeoTIFF验证15MB首次入库、64MiB边界和超限拒绝；合成文件不用于场景或工程事实，新增测试资源与原10版分列。三轮与不同体积覆盖不足时保留对应限制，不把一次通过写成全网稳定性。最终B0/B1必须包含当前登记/共享模型/项目库/旧模型和新的临时接收清单；保全全部新修订，原41模型/16景及身份保持。

## 本批公网发现与修正

初版256KiB流式代理在公网三轮小文件通过，但15MB恢复过程中出现约90.961秒片段及一次503，停在4MiB确认偏移，不能记作15MB或大文件通过。源站TCP仍在慢速接收请求体，当前证据不能精确定位共享隧道或外部网络的具体故障。后续收至128KiB，并只给该入口启用有界请求缓冲；套接字超时/断开按上传来源不可用返回504，不再误报存储失败。仍接受旧256KiB接收器遗留的未确认尾部，并从已确认偏移重写，不冒称旧尾部成功。
