# 场景资源换版实现

2026-10-22。承接[场景资源与多实例服务契约 V1.4](../contracts/场景资源与多实例服务契约.md)和[模型资源与地理场景保存切片](模型资源与地理场景保存切片.md)，登记本批模型、地形换版的实际服务能力。后端定向验证与实际浏览器换版闭环已完成；前端110项、类型与构建通过，最终显示样式、16组布局与源指纹复查通过，详见[执行记录§29](开发执行记录.md#29-模型与地形换版2026-10-22)。本批未部署到测试站或公网，不代表整个 Q-03/04 或工程关联迁移完成。

## 1. 当前接口与范围

新增 `POST /api/workbench/scenes/replacement-check`，确认仍通过 `POST /api/workbench/scenes/save`。复用本人 HttpOnly 会话、同源 JSON、`expectedSessionRevision`、当前固定项目及项目授权；不接受另一个项目、上游地址、服务器文件路径、处理命令或客户端自报免检参数。

换版预检、场景 check/save 的请求上限为 1MiB，采用严格 UTF-8 JSON 解码；重复键、非有限数、未知字段等拒绝。其余普通读取保持 16KiB，没有统一提高全部接口限额。模型、地形原件继续使用现有受保护资源入口。

预检请求为精确互斥类型，公共会话字段如下；`snapshot` 为现有完整 `EditableSceneSnapshot`，不另造部分补丁：

```ts
type ReplacementCheckRequest = {
  expectedSessionRevision: string;
  sceneId: string;
  expectedSceneRevision: string;
  snapshot: EditableSceneSnapshot;
} & (
  | { kind: 'model'; sceneModelInstanceId: string; candidateModelVersionId: string }
  | { kind: 'terrain'; candidateTerrainVersionId: string;
      strategy: 'keep_height' | 'resample_ground' }
);
```

首切只处理**已保存头布局**。请求快照必须与期望头在精确数值语义上相同；名称、位置、相机、显隐或其他草稿修改未保存时，返回 `409 SCENE_DRAFT_REQUIRES_SAVE`，先正常保存布局再换版。`1` 与 `1.0`、`0` 与 `-0.0`视作相同数值；不同小数不作容差合并，布尔值不当数字。既有首次 anchor 仍可携带未保存的局部编辑。

预检成功返回实际 `SceneCheck` 壳：

```ts
{
  sceneId, baseSceneRevision, proposedSnapshot,
  validation, heightProvenance, resourceRefs,
  spatialChange: { kind: 'model' | 'terrain', receipt },
  sessionRevision, projectName, capabilities, limits
}
```

影响清单在 `validation.impact`；`resourceRefs` 只列最终候选引用，旧新固定资源身份另由签名和影响记录保留。预检不写修订、审计或共享草稿，不持有编辑锁；不调用 save 即无换版写入。前端预览、取消恢复及确认已通过本机合成权威浏览器验证。

确认时回传原候选快照和 `spatialChange`，连同正常 save 必需的 `sceneId`、`expectedSceneRevision`、UUID `clientRequestId`、会话修订、`reviewedEngineering: []`、`rootBindingChanges: []`。`spatialChange` 公共白名单只有 `kind` 和 `receipt`，操作参数来自服务端已签名内容。既有实例不能再通过普通 save 直接更换模型版本；普通 save 也不能直接采用另一地形或框架。正常新增实例的保存能力保留。

当前仍为未关联布局：`rootBinding` 必须为 null，`componentBindings` 必须为空。无工程写入、关联迁移成功、构件自动匹配或现场控制能力；停用、退役不在本批。

## 2. 模型换版

仅替换指定稳定 `sceneModelInstanceId` 的固定版本，不复制该实例，不更新其他实例，不自动跟随资源最新版本。旧、新模型均须为当前项目真实资源，且就绪、已校准、可布置；旧 legacy 版本不伪造基点或校准事实。锁定实例返回 `409 INSTANCE_POSITION_LOCKED`，需先解锁并保存。

`validation.impact.kind=model_replacement`，包含目标实例、旧新版本及 `oldModel/newModel` 摘要：资源/版本 ID、内容修订、SHA-256、源报告包围盒及尺寸、基点、正面方向、构件数和明确确认标记。模型尺寸来自固定报告，不能据此宣称现场精度。地理场景还重查当前固定地形和实际几何；实例位置、安装朝向、稳定身份、显隐、相机及地形引用保持。

## 3. 地形换版与坐标边界

只对已锚定 `projected_site` 场景换地形。旧、新资源都核验当前授权、内容/报告指纹和私有制品；GIS 子进程接收最多两份服务端固定清单，最终引用只指向新地形。先严格验证旧采样，再推导全体候选，不部分提交。

| 策略／原高度 | 当前行为 |
|---|---|
| `resample_ground`／贴地 | 采用新固定显示网格采样，保留原 offset，更新地形版本/SHA和高度；新落点缺测或覆盖外拒绝整次采用 |
| `keep_height`／已知基准贴地 | 保存旧采样值加 offset 得到的高度，转为 absolute；保留“来自旧地形估算”的依据，不标成测量值 |
| `keep_height`／未知相对基准贴地 | 仅同一明确 `relativeReferenceId`，且保持场景高度原点时，采新值并反算 offset；仍为相对贴地，不转绝对高程；所需新采样无效则拒绝 |
| 任一策略／原 absolute | 保留完整原高度和来源声明；已知基准允许位于覆盖外或 NoData，诊断采样不足不强制贴地 |

已知基准 keep_height 转 absolute 后，新地形缺测不阻断保留旧有效估算高度。影响中的不可用诊断采样为 null，并附 `sampleIssues`；需要新地面采样的路径仍严格拒绝无效落点。当前不执行垂直基准转换：不同 datum、未知参考不同或投影转换不兼容均拒绝，不能把“都未知”当同一基准。锁定实例的实际高度变化超过 1e-6m 时拒绝；仅框架编码变化、保持实际高度可保留锁定。

`validation.impact.kind=terrain_replacement` 包含旧新四字段地形引用、框架修订、策略、逐实例旧新高度模式/采样/最终高度及差值。场景原点、CRS、datum、转换标识和相机数值保持，服务重建 anchor 与 `frameRevision`，统一更新实例框架引用；不改变经纬度、真北朝向、模型或稳定身份。

新换版 anchor 的整数值浮点作精确数值规范，避免浏览器 JSON 往返改变框架摘要；旧 anchor 的摘要与无补偿算术路径保持原样。未知相对基准换版因大数相减可能丢失高度原点低位，服务仅在新 anchor 内生成 `offsetCompensationM`，以 `math.fsum` 重建；其绝对值不得超过采样/offset 的 ULP 上界。首次 anchor 拒绝该字段，客户端不能借它提交工程高度修正；普通保存仍按固定框架重核，不提高地形精度或引入新垂直基准。

## 4. 回执、事务与来源

换版回执使用从现有场景目录密钥派生的独立 HMAC-SHA256 命名空间，与分页和首次 anchor 区分。签名绑定本人、项目、授权修订、场景旧头/旧快照、唯一操作参数、候选精确数值摘要及旧新固定资源摘要。完整资源清单取摘要，不把大量模型引用塞入回执；回执上限仍为 8192 字节。

项目成员可做只读预检；当前项目 admin 才可保存。服务在开始、资源读取、提交和返回边界核验会话/角色/授权。回执不是权限凭证；伪造、跨用户/授权/场景或改动候选均拒绝。保存从签名操作参数重新计算完整结果，比较候选及固定资源，不能只信浏览器预览。

GIS 在 SQLite 写事务外执行。提交使用 `BEGIN IMMEDIATE` 重查期望头、旧快照、旧新资源和当前授权；头变化返回 `409 SCENE_CHANGED`。快照、派生校验/高度依据、引用、头、幂等结果和审计一起提交，撤权或校验失败整次回滚。旧修订及其模型/地形引用保持不可变，外键继续保护历史；没有新增数据表或后台迁移平台。

幂等作用域为项目＋真实用户＋动作＋UUID。同载荷原请求先重放已提交结果，优先于旧头/回执检查，不重复推进修订或运行 GIS；同 UUID 换载荷返回 `409 REQUEST_CONFLICT`，重放仍查当前权限。资源或签名失效返回 `RESOURCE_CHANGED`／`SPATIAL_PRECHECK_INVALID`等明确错误，不模拟成功。

高度依据由服务端固定旧修订生成。普通保存和模型换版仅在同稳定 ID 的完整 `placement.height` 精确数值等值时延续旧依据，标为 `retained_height_basis`，保留 `basisKind/basisSceneRevision`；absolute 实例移动仍保留原采样位置，不能把旧估算改称新位置测量。高度值或来源任何字段改变、新增 ID 均不继承该依据。

地形换版采用有界摘要，避免每次递归复制全部前驱：

```ts
heightBasis = { kind, reviewedSceneRevision, height, terrainRef };
previousHeightProvenance = {
  kind: 'height_basis_summary', previousSceneRevision, basis: oldHeightBasis
};
```

`height`保留原依据白名单内的高度、采样经纬度等；`terrainRef`为原依据固定四字段或 null。keep_height 稳定沿用原估算依据，resample_ground 产生新地形依据。本次 `replacementStrategy/previousTerrainRef/impact`仍记录本次操作，旧全文由固定历史修订保存；摘要不冒充旧 note 全文，不靠提高全局 JSON 深度维持连续换版。
