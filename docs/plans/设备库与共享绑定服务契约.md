## 2026-10-28 D 批接续契约（已发布，待正常账号联合验收）
源端已部署 `ce74fd6315b5f6a2fb62bdb07f8f72ec61d8d795`。型号、项目应用和设备采用只经 OntoBase 正常业务 API 写入。下列 ONTOVis 接口均携带当前用户会话、项目和 `expectedSessionRevision`；不转发外部任意路径。

- `POST /api/workbench/equipment/applications`：`{offset,limit}`，代理当前项目应用分页（上限 50）。
- `POST /api/workbench/equipment/applications/detail`：`{applicationRevisionId}`，读取固定项目应用、规格、模板字段及该应用明确引用的工程定义。源端无权或失效时明确报错，不回填旧值。
- `POST /api/workbench/equipment/configurations/save`：沿用配置 ID、预期修订和请求 ID；`snapshot` 只接受 `{projectApplicationRef:{applicationId,applicationRevisionId,specificationRevisionId},models}`。名称、类型、根定义由服务端读取源端固定应用派生；构件映射仅限该应用明确的定义 UID 与修订。角色和项目采用不能在 ONTOVis 编辑。
- 旧配置首次接续可增加固定项目应用引用，保留已有模型映射与不可变历史。一个项目的同一应用固定修订对应一份共享绑定；已有引用不能原地改为另一修订。设备按源端当前采用查找共享绑定，历史场景仍按原固定绑定读取。旧配置尚未接续时保留旧采用只读解析。
- 原 `/configurations/assign` 与 `/photos/associate` 写入口关闭，返回 `SOURCE_MANAGED`；原表及历史继续可读。
- `/shared-photos/query`、`/shared-photos/regions`、`/shared-photos/content` 代理源端同名的设备共享照片服务。列表默认 12、区域默认 50；仅请求当前照片的缩略图/预览，原图由用户按需打开。显式适用和柜内成员来源由 OntoBase 聚合，保留原对象区域。
- `/equipment/resolve` 增加源端 `adoption` 和 `attributes`，已有对象身份、图纸、层级和历史引用格式保持。设备采用独立修订，不伪造实体变更。

错误：`SOURCE_APPLICATION_REQUIRED`（旧绑定待选择应用）、`SOURCE_APPLICATION_MISMATCH`（引用不符）、`DEFINITION_NOT_IN_APPLICATION`（定义不属于固定角色）、`APPLICATION_BINDING_EXISTS`（已存在对应绑定）、`SOURCE_MANAGED`（返回源端管理）；原并发、权限、模型和对象变更错误继续有效。

当前画布新增模型时，通过源端 `/equipment-applications/revisions/{id}/equipment` 分页固定采用设备范围，续页核对 `snapshotRevision`；超过现有画布500台上限明确拒绝，不截断成完整结果。旧画布保持原 `configurationRefs`。已接续配置的 `equipmentCount` 返回空，真实计数从 OntoBase 项目应用读取，旧私有分配表不再充当当前计数。

## 历史实现基线（0a60f09，已被上述接续规则替代的写入口不可再用）

### 数据边界

OntoBase 的 `asset.equipment_items` 是单台设备可变属性的唯一主记录，工程对象继续由 `asset.entities` 维护。原安装 UID 保留，旧实体行只作不可变身份及外键锚点；兼容读取使用 `asset.project_object_read_model`。设备名称、定义来源、活动状态不能通过旧实体写入路径维护。安装范围、物理关系、旧照片和历史引用继续可解析。

工程对象目录默认排除安装身份；显式安装范围查询和按 UID 解析保留兼容。设备目录默认仅返回活动整机，选中后批量读取本机关键子设备。停用不会删除历史身份、共享工程来源、图纸或已保存分析。

## OntoBase 设备与照片接口

项目内前缀为 `/api/v1/projects/{project_code}`；全部要求本人有效项目权限。读取遵循现有项目授权，写入要求项目管理员、当前实体及层级修订、业务依据和请求幂等键，产生审计记录。

| 路径 | 方法与用途 |
|---|---|
| `/equipment` | GET；名称搜索、游标分页、`rootsOnly`；不混入共享工程定义 |
| `/equipment/resolve` | POST；一次最多50个明确 UID，返回设备、安装上下文及活动关键子设备 |
| `/equipment/{entity_uid}` | GET；单台身份，包括退出活动台账的历史身份 |
| `/equipment/{entity_uid}/update` | POST；版本控制的设备名称编辑 |
| `/equipment/{entity_uid}/state` | POST；活动/停用；整机或仍有子项时不能直接停用 |
| `/equipment/photo-candidates` | GET；项目内现有照片、固定版本及显示版本，游标分页 |
| `/equipment/{entity_uid}/photos` | POST；将现有项目照片明确关联到本机，不上传或复制文件 |
| `/object-evidence/photos/resolve`、`/content` | POST；保留原固定引用，增加可选 `photoPurpose` |

`photoPurpose=object_location` 为共享工程对象定位，默认值兼容旧引用。`field_record` 为本机现场记录，必须有具体设备身份；空记录不回退到共享定义或其他设备。照片用途是关联属性，不能从文件名或拍摄地点推断。同一文件可有两个明确用途，关联、归属与显示标注仍分别保留。

## ONTOVis 设备层级接口

同源前缀 `/api/workbench/equipment`。请求携带当前会话修订及已进入的 `projectRef`，不能指定任意来源地址。项目设备目录补充本项目活动场景表示数量；搜索、分页继续由后端执行。

| 路径 | 用途 |
|---|---|
| 根路径 | 分页设备目录及是否已布置 |
| `/resolve` | 批量读取当前设备与内部台账 |
| `/definitions/children` | 分页展开权威柜内共享工程对象 |
| `/configurations` | 当前项目配置、采用关系、批量解析的工程对象及固定模型元数据 |
| `/configurations/detail` | 当前或指定历史配置修订 |
| `/configurations/save` | 保存共享配置；整机定义及构件目标必须属于当前项目且不是安装对象 |
| `/configurations/assign` | 将当前配置应用到明确整机；校验实体、安装层级及原采用修订 |
| `/photo-candidates`、`/photos/associate` | 固定范围代理到 OntoBase 的项目照片选择与本机关联 |

配置包含显示名称、设备类型、可选整机定义，以及每个固定模型版本的工程对象/构件键映射。无独立几何的对象允许保留空构件集合，通过工程归属或整机查看；不猜测精确构件。同一具体构件键不能分配给两个直接主对象。保存前批量解析对象，不对每台设备复制映射。

写入分别保存不可变配置修订和采用记录，带当前修订、幂等键及操作者。共享配置当前修订应用于全部实时采用者；旧场景保存时记录所用修订。场景里的逐实例构件覆盖对采用共享配置的整机关闭；旧关系保留读取，冲突可见。

## 场景、画布与照片

从场景“项目对象 → 设备”将已有设备拖到地形，使用其共享配置、固定模型和原设备身份。只新增场景表示；不创建设备、工程对象或单台映射副本。保存仍遵循现有场景权限及版本条件，预留风机不会因后台迁移自动放置。

选择共享对象时，指定当前风机表示，由服务端将定义映射解析为该设备内部对象。柜内传感器可定位到其所属柜体，同时保留传感器身份和定位精度。

新加入画布的模型引用保存 `configurationRefs`：配置身份、不可变修订及当时采用的设备身份。后续编辑共享配置不改变这些固定引用。旧模型引用仍沿原路径读取，不自动添加新配置关系；重新加入模型可使用当前配置。配对备份核对配置、模型和画布引用一起可恢复。

现场照片推荐及固定引用保存 `photoPurpose=field_record` 和本机选择条件，读取及文件打开继续核对归属；共享定位引用保留原行为与标注。卡片显示照片用途，文件缓存按固定内容复用，不跨设备借用关联。设备照片默认请求快速预览，可切换原尺寸；预览复用既有4096像素派生缓存，标注坐标保持同一比例。

## 本批边界

设备库领域及业务 API 位于 OntoBase；本批可操作入口是 ONTOVis“设备层级”的“项目设备”，可查看设备及关联现场照片。没有另行发布 OntoBase Web 的完整资产维护工作台，也没有新增序列号、更换履历或现场采集功能。

TU-3000 沿用来源几何；CN1、CT 保持示意代理，CN2采用既有控制器表示，叶轮/转子没有独立整组构件键，保留工程对象并使用整机位置。没有真实现场照片时保持空状态，验收中不把共享柜内照片伪装为现场采集记录。
