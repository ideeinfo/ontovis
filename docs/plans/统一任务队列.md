## 1. 状态与执行规则

| 状态 | 使用条件 |
|---|---|
| 待执行 | 当前前置已满足，可以开始本项 |
| 进行中 | 已实际开展，并在执行记录登记本批范围 |
| 待前置 | 表内依赖尚未完成；可准备资料，不能视为可交付 |
| 待输入 | 已推进不依赖外部输入的工作，仍缺明确资料或决定；登记具体缺口及受影响验收 |
| 已完成 | 本项范围内产物及适用验收完成，附实现/设计修订与证据；不扩大到整个来源WBS |
| 暂缓 | 用户明确暂不做；不因其他任务结束而自动恢复 |

- Q编号是唯一执行编号；WBS、SC和PREP/OB/OV仅作来源映射，不另起第二套进度或把同一工作量加总两遍。编号稳定，调优先级不重新编号。
- 一项只设一个主责角色，协作角色另列。P=产品/交互，BE1=架构与OntoBase，BE2=集成/服务，FE1=三维，FE2=工作台，QA=验证；尚未指派个人。多项可并行不等于同一人员可同时满负荷执行。
- 前置列区分任务完成与指定交付物：未加限定的Q编号需完成；写明“合同可用”“区域查询可用”等时，只需该交付物已验证并在原Q的执行记录留证，不等待其整包关闭。真实输入列在完成条件中，缺失时仍可开发合同/合成反例，整项不因此标为完成。
- 新页面和行为先在现有MagicPath项目形成可评审状态及服务契约。沿用已确认决定，不重复索要账号、项目、权限或现模型授权；不能从已有资料解决的新业务决定再请用户介入。
- 每次完成任务同时更新本表和执行记录：实际范围、代码/设计版本、真实与合成验证、剩余输入、下一项。部分交付留在进行中或待输入，不用百分比掩盖尚未通过的验收。
- 普通场景采用“保存后项目成员可查看”的规则，不增加发布审批。现场工程事实核实、目录批次发布和AI/数据策略生效分别按自身规则处理。
