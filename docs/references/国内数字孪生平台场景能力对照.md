2026-10-22。用于修订[场景管理与模型实例统一实施方案V2](../plans/场景管理与模型实例统一实施方案.md)，围绕地形、模型复用、设备关联和场景操作对照优锘ThingJS-X、图观、51WDP的官方资料。

## 3. 统一设计中的三个边界

**场景内容、对象分类、设备层级分别服务不同操作。** 例如将“7号风机”和“1号变压器”放入同一个显示组，只便于一起隐藏或移动；变压器是否属于这台风机，仍以OntoBase记录为准。模型内部的构件组也不能自动成为工程设备父子关系。

**复用模型和配置，逐实例确认设备。** 两台风机共用GLB、尺寸校准和CT/CN1/CN构件角色，每台单独选择机组及三柜UID；无几何子设备仍选中自身，以最近有效已关联祖先定位。将来共用颜色/动画规则时，也必须重新关联各台设备的测点来源。

**相机演示、运行显示和工程事实分别验收。** 相机能飞到机舱，只说明导航实现有效；模型爆炸、草地材质或转动效果不证明现场几何、地表覆盖或运行状态。真实数据进入后保留单位、时间和质量；未知状态不显示正常，镜头巡游不自动生成已完成巡检记录。

## 4. 首批和后续的取舍

首批SC-01—06交付一个可反复使用的完整闭环：建场景、上传地形、核对资源、重复放置、分别关联设备和三柜、定位无几何子设备、查看自己的图纸、保存重开。补入上述基础编辑能力后，仍沿用原工作台结构、灰绿双主题、默认收缩导航和按需展开说明。

随后SC-07解决多台设备布置和观察路线，SC-08补影像/地理图层，SC-09接有限配置复用与运行状态。首批不新增通用图层插件、可视化编程、素材商城、云GPU集群、任意CAD导入，也不建设完整告警/巡检工单系统。设备停用、退役继续暂缓。

三个平台公开资料共同表明，成熟场景工具不仅需要“能上传和摆放”，还需要可找到、可核对、可恢复的编辑流程。V2据此补操作闭环；首批限额、帧率和定位精度仍通过现有硬件及实际样本冻结，不采用宣传中的规模或搭建时间。
