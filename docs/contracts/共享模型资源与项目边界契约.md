# 共享模型资源与项目边界

Q-46 · 2026-10-24。本契约修订Q-44对模型资源的项目隔离约定；场景、地形、影像、工程对象及图纸仍遵循[项目上下文契约](项目上下文与场景基本信息契约.md)。模型目录交互承接[Q-45](../plans/模型中心目录视图切片.md)。

## 1. 操作逻辑

登录/恢复会话仍进入“项目与访问”，可直接进入“模型中心”，不需要选择项目。模型中心显示“共享模型库”，没有项目筛选按钮；名称、用途、缩略图/列表及独立预览保持。无项目权限的有效登录用户仍可浏览模型，场景和工程资料不会因此开放。

模型资源及固定版本属于当前连接的ONTOVis共享模型库。同一固定版本可用于多个项目的多个场景，每次布置只新增独立实例；不复制几何、不新增型号版本、不复用安装身份。模型中心“进入场景布置”在已有项目时打开该项目场景目录，尚无项目时返回项目目录；只有选择/创建场景和访问工程对象才使用项目。

模型使用去向仅聚合本人当前有权项目的场景，显示项目名和场景名。打开某项时重新核对该项目权限，以该项目和sceneId进入场景，不能沿用上一次选择的项目。

## 2. 服务与权限

既有同源POST、HttpOnly会话、Origin/Host、expectedSessionRevision、版本条件、幂等、no-store和受保护二进制检查保持。

| 路径 | 范围 |
|---|---|
| `/api/workbench/resources/models`及其`/legacy` | 共享目录、搜索用途/分页，不要求projectRef |
| `/api/workbench/resources/model`及upload/calibrate/content/metadata/thumbnail等原子路径 | 共享固定资源；前端不附加项目。旧客户端附带合法同连接projectRef时仅校验格式/连接，不作项目过滤；不返回伪造的模型所属项目 |
| `/api/workbench/resources/uses`，无projectRef | 按当前源权限聚合多个项目；游标绑定用户/会话、版本、用途范围、分页大小和所有可见项目授权/场景目录摘要；撤权或目录变化后旧游标失效 |
| `/api/workbench/resources/uses`，有projectRef | 场景侧栏查看该项目使用去向，继续核对应项目权限 |
| 场景、地形、影像、公开获取、工程对象、旧模型绑定及图纸路径 | 保持必填projectRef和原Q-44校验；不回落默认项目 |

共享模型读操作核对当前源`/api/v1/auth/me`中的本人有效身份。上传、校准、元数据和补图仍由后端校验维护权限：承接现有授权，当前任一有效项目的管理员可维护共享模型，普通成员/无项目用户只读；不按当前界面选项授权。写入及幂等重放重新核对实际项目目录/access和授权摘要，撤权拒绝写入。未增加源系统角色或用户管理接口。该单连接测试部署不表示已实现企业多租户模型授权。

二进制读取只复核身份与固定版本/内容摘要，不为每张缩略图枚举所有项目。项目使用去向在返回前再次核权；没有权限的场景名、数量、版本等不进入响应。项目级拒绝和模型级拒绝保留登录身份；401清理身份，迟到响应仍按会话/请求epoch丢弃。

Q-47按用户要求取消模型上传中的使用确认勾选项；新模型及追加版本只填写名称、用途和来源说明。为兼容现有上传服务，客户端继续发送既有`rightsDeclared:true`协议字段，该字段不再表示一次独立勾选动作，也不新增授权事实或改变素材的许可范围。后端维护权限、来源必填、GLB校验及版本条件保持；旧资源数据和地形/影像流程不变。

## 3. 存储与兼容

原配置的library_root作为共享资源物理存储，现有模型/固定版本ID、几何文件、缩略图、属性及历史业务行原地保留；旧library/project_model_assets里的project_code是兼容存储来源，不再作为模型中心入口范围。独立项目库继续保存场景、地形/影像、实例和工程引用。

新增单行`shared_model_scope(connection_id,scope_version=1)`和登记库`shared_model_store`固定资源连接；每项目`scene_model_scope`记录共享引用版本。场景实例保留原modelVersionId，不在各项目库制造versions或GLB副本。原scene_resource_uses保留全部行及场景外键/不可变触发器；移除无法跨SQLite库表达的versions外键，由保存/读取的共享内容身份检查及整组备份校验代替。固定版本不存在或指纹变化时拒绝操作。

迁移不得改写场景快照、修订、审计、实例ID、坐标、绑定、原模型表业务行或几何文件。测试站目前仅一个已登记旧空间，模型均位于原library_root。若发现其他旧项目库含独立模型版本，明确返回SHARED_MODEL_MIGRATION_REQUIRED并保留现场，不能静默隐藏、合并同名或重分配ID；须先核对冲突再迁移，不把此异常伪装成空库。

## 4. 备份与发布

`tools/project_store_backup.py`必须同时保存登记库、共享模型库、各项目库及已配置的旧模型配对资源；登记已启用共享库而未提供library_root时拒绝备份。已有配对部署将共享资源随legacy组保存；无旧安装的新部署使用清单sharedModels组，不依赖伪造安装上下文。校验每份历史快照的模型ID集合与资源清单一致、每条共享SHA/contentRevision指向真实固定版本。

上线前停写B0，迁移后及最终重启保存B1并verify/新目录恢复；失败先保全当前B1，不以B0覆盖新写入。旧备份格式仍可读，新扩展清单应由识别共享模型的工具恢复；不得回退到不了解共享引用/旧写冻结门的后端。OntoBase业务数据库保持只通过API读取。
