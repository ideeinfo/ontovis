# 项目演示工单闭环

2026-10-25。用户要求增加简单工单，先为 Demo-PDS 生成约20条，走通报警、知识图谱排查、CN2/CN1柜体与照片对象定位。用户本轮纠正项目柜码：CN2为机舱信号柜，CN1为机舱动力柜；旧模型组件CN只作为历史演示代理标识保留。本文冻结本批页面与服务范围；实现和验收结果另记执行记录。外部真实源仍未提供，本批不回写外部工单、报警或工程事实。

## 页面与数据

既有工作台增加“工单”入口，沿用当前项目、权限、主题和语言。左侧显示报警/工单搜索、状态和20条演示任务；右侧依次显示报警、诊断图谱、排查清单、工程对象与照片、流转记录。小屏改为纵向排列。项目切换、退出和撤权清除旧详情、图片URL及迟到响应。

首批仅 Demo-PDS 可由管理员初始化固定批次，一次事务创建20条独立报警工单，重复请求不重复建单。故障类型来自已有 OntoBase RCA 目录的13001/13002/13003/13004/13033/13035/13058；次数不是20种厂家故障码。报警时间、观测、排查记录及处理结果均标为演示。知识链采用演示诊断规则，保留手册页码及原图谱适用范围、缺口，不把其他项目图谱的确认状态转成 Demo-PDS 事实。13058的低压柜/信号柜术语缺口保留。

报警关联目标、项目定义归属与安装空间宿主分别记录。原20条工单及7号演示安装身份、旧模型组件CN/CN1引用保留；不重写历史命令回执。当前CN2/CN1入口通过OntoBase完整项目主位号读取独立柜级定义；既有演示安装树继续标为假定，不因新增定义自动变为现场工程事实。

实际只读核对：原1136个项目对象中，CN1/CN2前缀分别有180/264个已记录对象，均为unclassified、未分配安装范围，主标识为electrical_tag/needs_review；原先仅有演示柜，无独立柜级定义。六张真实柜体照片已存在，信号柜正面已有90处定位。用户随后明确授权先补充柜级对象与设备层级，并确认这些前缀对象的柜级归属。

本批柜级补充由OntoBase受控API完成：新增两个definition/cabinet对象、登记现有对象为直属成员，依据标为user_declared。原成员UID、scope、类型、标识状态和图纸/照片记录保留，只推进涉及对象修订。每批最多50、管理员/版本/幂等/审计/事务回滚控制；跨项目、其他柜级、安装对象、自包含/柜套柜及失效标识拒绝。完整源契约见[柜级定义接口](https://github.com/ideeinfo/ontobase/blob/codex/ontovis-fixed-photo-evidence/project_docs/specifications/PROJECT_CABINET_DEFINITIONS.md)。

选择CN2/CN1后显示“柜内对象”，每页50、服务端游标；完整位号输入仍保留。POST `/work-orders/locate` 可携`referenceRds`或`memberCursor`，两者互斥；前者必须位于精确柜级范围且已登记为该柜成员，后者只能用于柜级读取。分页、工单和项目切换均按当前权限重读；切换清空旧对象/照片。图谱参照器件仍按同项目唯一完整主位号读取，不自动变成绑定或故障因果事实。

完整主标识读取兼容RDS/electrical_tag，原needs_review状态明确显示，不提升为accepted。重解析UID后再核对同一主标识；别名、短码、其他范围、重复对象或退役标识不连接。固定照片可复用当前正式图纸对象的既有待审核主标识关联，须有该UID的同项目正式图纸位置且没有其他对象占用完整范围键；没有正式位置的待审标识不连接。只读取原有固定版本与标注，不制造照片/区域、不确认适用性或现场安装。

长照片打开完成后，照片面板自动滚到第一处已有来源标注；来源坐标和区域类型保持。浏览器回归需使用标注位于下部的长图，确认框同时处于照片滚动区和当前视口；无标注/读取失败不制造定位。

## 流转与授权

状态：待受理 → 诊断中 → 排查中 → 待复核 → 已关闭；复核可退回排查。诊断展示本身不确认根因。排查转复核需完成清单、提供演示处理记录；关闭需复核记录。所有流转保存操作人、时间、原状态/新状态和备注，可刷新回读，不执行现场控制。演示关闭只表示演练完成。

所有入口为受保护 POST，携带 expectedSessionRevision 与完整 projectRef。服务端从部署连接和当前项目授权确定存储范围，每次读写前后重新检查本人会话与项目权限；写入只允许当前管理员。初始化要求列表快照；流转要求 expectedOrderRevision 与 UUID requestId。同一请求/内容返回原回执，不同内容复用请求ID或过期工单版本返回409，权限失败不重放成功回执。提交前最后核权失败必须回滚。

拟实现路径：`/api/workbench/work-orders`、`/work-orders/seed-demo`、`/work-orders/detail`、`/work-orders/action`。列表分页最多50、搜索≤200字符；详情、清单、事件及工单均有固定上限。数据保存到既有项目私有library.sqlite3，随整组备份恢复；其他项目空态可读，禁止初始化Demo-PDS批次。不同项目相同工单ID仍不得相互读取、改写或获取照片。

## 照片与定位

复用[固定照片源契约](https://github.com/ideeinfo/ontobase/blob/17b92bef882b8a466f1aa0aa1088ddabde2bdb93/project_docs/specifications/ONTOBASE_FIXED_PHOTO_EVIDENCE_CONTRACT.md)：固定 contentVersionId、sourceRevision、显示资源及displayRevision，打开前后核对当前对象/权限和内容摘要。仅在同一显示资源上叠加来源区域；普通照片使用oriented_display_normalized，球面照片保留球面区域/视角。缺可用区域保留准确缺口，不生成假框；缺文件、无关联、旧版本失效和源接口未部署分别显示原因。旧关联不自动换新。

照片区域是来源标注、适用性待核实；它不证明独立安装对象的现场一致性，不提供柜内三维精度或根因确认。完整流程验收必须记录真实存在的关联、固定版本和实际内容读取；无照片依据时保留明确阻断，不能用示意图冒称现场照片。

## 验收

验证20条唯一且初始化幂等、项目/连接隔离、当前权限与版本冲突、事务回滚、重复操作回执、状态必填条件、重开回读。浏览器逐步完成至少一条CN和一条CN1演练；核对图谱节点、清单、对象身份、照片内容与区域、刷新后记录，以及退出/项目切换清理。合成测试与实际工程读取分别记录，不以模拟源测试替代真实照片验收。
