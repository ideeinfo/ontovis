# 项目驾驶舱上下文与动态数据契约

V1.0，2026-10-30。**拟议契约，尚未新增下列驾驶舱接口、数据表或实时接入。** 设计范围见[详细设计](../design/项目驾驶舱详细设计.md)；实施顺序见[分期计划](../plans/驾驶舱功能补齐与实施分期.md)。现有服务通过代码及当前指南确认；设计字段不能被当成已存在 API。

## 1. 权威边界与最小数据模型

| 信息 | 权威维护位置 | 驾驶舱职责 |
|---|---|---|
| 项目访问、安装设备/型号定义/工程身份、设备层级、适用资料/工程证据 | OntoBase 既有 API | 按当前授权及固定修订读取，不直写源库、不重建一份设备台账 |
| 模型固定版本、场景、布置、模型构件绑定及几何精度 | ONTOVis 既有模型/场景服务 | 选表示、取景、定位、模式/动效与精度状态 |
| 遥测、设备状态、原始报警确认/解除 | 首个确认接入的数据源；具体来源待项目确认 | 受控只读接入、归一化、身份映射、按质量显示；不冒充源系统 |
| 气象观测/预报 | 已授权气象源或现场观测源 | 时间/覆盖/单位校验、观测与预报隔离、视觉映射 |
| 本人分析、固定资料、助手回执、工单与采纳记录 | 既有分析/工单领域 | 复用原持久化、权限、版本及恢复机制 |
| 主题、显示密度、最近视点 | 本人项目查看偏好 | 只保存允许的查看状态，不包含资料正文和临时下载地址 |

首批不引入独立 Portfolio 表：portfolioId 就是现有 sceneId。仅在实际功能需要时增加项目驾驶舱展示配置（场景顺序、默认视点、默认图层），与个人查看偏好分开。项目配置修改需既有项目维护权限、expectedRevision 和幂等键。

运行姿态配置归 ONTOVis，引用固定模型版/构件键/设备身份，保存轴向、枢轴、单位、旋转方向、允许范围及证据。设备物理参数如厂家额定转速归源端适用参数；不要为动画把工程事实写进前端常量。

## 2. 上下文载荷（设计类型）

下述是边界 DTO 示意，正式实现应复用项目实际 UID/修订类型及错误封装，不直接复制成第二套基础类型。

```ts
type CockpitContext = {
  projectId: string;
  view: 'assets' | 'scene' | 'device' | 'analysis';
  scene?: { id: string; revision: string };
  equipment?: { installationUid: string; revision: string };
  representation?: {
    instanceId: string;
    modelVersionId: string;
    bindingRevision: string;
    componentKey?: string;
  };
  alarm?: { sourceId: string; eventId: string; revision: string };
  time: { mode: 'live' | 'event' | 'replay'; from?: string; to?: string; timezone: string };
  analysis?: { id: string; revision: string };
  returnViewId?: string;
};
```

- URL 只包含可校验标识和必要视图选择；不放凭据、资料正文、签名下载地址、整个相机矩阵或另一项目私有分析内容。
- 所有标识在服务端核对是否属于同一项目，安装设备与共享定义不能互换；未解析身份保留 unresolved，不按名称猜 UID。
- representation 是“设备在某个固定场景修订中的表示”。同 UID 可以有多个表示，必须保留 instanceId 和绑定修订。
- time 为 UTC ISO 时间戳加项目时区；事件时间窗冻结。示例 ±10分钟仅为默认分析窗口，不是报警触发时长，也不代表现场采样周期。
- 返回书签含地理/局部坐标系、目标、朝向、距离、已加载/临时显隐、选择、筛选和时间模式；只恢复仍然有效的内容。跨模型版本不能盲目套用旧构件键。
- 书签本地会话内按项目隔离；退出、撤权清理。需跨会话持久化时走本人偏好服务，字段有界，禁止保存工程证据副本。

## 3. 读取与导航端点

现有 `apps/workbench/src/analysisSources.ts` 的 AnalysisEntry 包含项目、对象、数据集、工单、固定分析等入口；现有 `/api/workbench/analysis-sessions/start` 是有副作用的启动服务。驾驶舱增加报警入口类型和解析流程时，必须保持原版本、权限及幂等语义。

| 候选能力名/路径（均拟议） | 目的 | 副作用 |
|---|---|---|
| GET `/api/workbench/cockpit/catalog` | 当前项目可读场景、去重统计、地理摘要、已授权告警摘要 | 无；复用现有项目/场景读取 |
| GET `/api/workbench/cockpit/scene-context` | 固定场景修订的表示、绑定、精度、动态配置和允许订阅范围 | 无 |
| GET `/api/workbench/cockpit/alarm-context` | 固定事件→安装设备→可访问表示→适用资料候选；返回解析依据及缺口 | 无，不创建分析 |
| 扩展现有 analysis-sessions/start 的明确报警入口 | 用户点“进入分析”后创建/继续本人固定事件分析 | 有；原子、幂等、权限及固定事件校验 |
| 复用既有分析保存/助手/工单采纳接口 | 保存修订、主动问答、提交人工选择的步骤 | 有，保持原契约 |
| 项目驾驶舱展示配置（如首批需要才新增） | 默认场景顺序/视点/图层，不能修改底层场景 | 有，维护权限+CAS+幂等 |

实现前以现有路由结构命名，能扩展现有读取的不要新增冗余端点。聚合接口不能拥有比下游更大的权限；计数与分页候选都按授权集合生成，不能先返回总数再隐藏无权限名称。

`alarm-context` 至少返回 resolved / ambiguous / unmapped / unavailable 四类结果。resolved 包含依据种类、安装 UID、固定来源修订及候选表示；ambiguous 返回有权查看的候选及原因，要求用户选择；unmapped 可继续只读事件分析但没有几何定位；unavailable 不泄露存在性或对象名。

## 4. 事件一致性和统计

唯一事件键使用 `(sourceId, eventId)`，更新由 source revision/sequence 识别；同一事件在多个场景引用时只统计一次。报警码+时间文本不能充当全局事件身份。源事件未提供稳定身份时，接入层必须先冻结可追溯的映射规则，不能由前端随机生成每次不同ID。

报警字段：sourceId、eventId、revision、installationUid或明确未映射标识、code、severity、sourceState、occurredAt、updatedAt、receivedAt、metric/threshold/units、acknowledgement（仅源提供时）、quality及来源适用范围。源状态与分析状态、工单状态分列，禁止把工单已完成反写成源报警已解除。

项目设备数按安装 UID 去重，未解析实例数量另列；场景设备数按该场景固定修订的有效绑定统计。数据质量是维度，不是又一种设备数量。首批不推导可用率/发电量/健康分，除非有明确分母、时间范围和权威数据。

## 5. 动态数据样本

```ts
type VisualSample = {
  projectId: string;
  installationUid: string;
  sourceId: string;
  streamEpoch: string;
  sequence: number;
  metric: 'rotorRpm' | 'nacelleHeadingDeg' | 'bladePitchDeg' | 'operatingState';
  value: number | string | [number, number, number] | null;
  unit: string;
  sampledAt: string;
  receivedAt: string;
  validUntil: string;
  quality: 'good' | 'uncertain' | 'bad' | 'missing';
  origin: 'observed' | 'simulated' | 'replayed';
  mappingRevision: string;
};
```

上述质量词是 ONTOVis 边界枚举，不声称与任何供应商协议完全等价。接入首源时保存原质量值和归一化依据；单位/时区/有效期缺失即不能判为新鲜。

消费规则：

1. 后端验证项目、安装 UID、订阅权限与映射修订；浏览器不能选择任意上游 URL 或凭据。
2. `(sourceId, streamEpoch, sequence)`用于流内去重与顺序控制；换流世代重新建立快照，不能用上一世代高序号屏蔽新数据。
3. 乱序或重复不推进最新姿态；可留历史趋势但不能回拨实时视图。sampledAt 和 receivedAt 分开显示，网络刚收到不等于数据新鲜。
4. 新鲜度以服务端校时的 now 与 validUntil 判断；缺失/未来超限/坏质量拒绝驱动动画。原始质量与消费状态 fresh/stale/offline 分开存。
5. 临时断流：有界重连、退避、游标补齐；仍未恢复时明确 stale/offline。不得无限重试或补齐全部历史到浏览器。
6. 切场景、暂停订阅、离开驾驶舱、登出或撤权即取消；带 contextEpoch 的旧回包一律丢弃。
7. 视觉动画可按帧更新，数据订阅按源实际频率；不因60fps画面向后端每秒发送60个请求。
8. 旋转姿态积分用单调时钟，长后台间隔钳制 Δt 并重置插值基准；rpm=0、负值含义、传感器合理范围由设备适用配置决定，未知负值不得直接反转。
9. yaw 最短路径差可用 `((target-current+540)%360)-180`，并处理源提供的累计角/回零规则；pitch 每叶片独立，缺值不补造。

首批不新增“协议插件市场”或全量历史库。选择一个实际有用户、有授权的数据源和一类设备完成读入、映射、撤权、回放验证，再决定扩展。已有模拟 SSE 保持来源标记，不能把它改名为现场实时源。

## 6. 气象契约

建议 WeatherSnapshot 包括 projectId、sceneId/coverageId、sourceId、observedAt、receivedAt、validUntil、origin(observation/forecast/simulation)、forecastValidAt、quality、phenomenon、cloudCoverPct、visibilityM、precipitationMmPerHour、temperatureC、windSpeedMps、windFromDeg、stationHeightM、coverageGeometry或明确覆盖描述、sourceRevision。数值可空，未知不写0。

- phenomenon 是内部归一化类别：clear/cloudy/overcast/rain/snow/fog/thunderstorm/unknown；映射表按首个源的原始代码冻结并测试。
- cloudCoverPct 接受0–100；windFromDeg归一化0–360；单位转换保留原值及来源。越界、不确定、质量差的数据只显示状态，不强行钳成“正常”。
- 温度和降水不由天空颜色反推。缺少气象数据仍可显示地形默认光照，但明确“环境示意”。
- 场站有效覆盖/高度必须可追溯，不能将地面气象站风速当成所有风机轮毂测点值。场景气象与单台设备测量分开展示。
- 观测有效期由源及项目接入配置确认，不在产品中硬编码统一5分钟。天气类别相邻变化可设视觉过渡/去抖，但卡片立即显示实际数据时间，不延后隐藏重要状态。
- 预报、回放和模拟必须有持续模式标签；退出回放回到实时需重新取快照，不能继续消费历史游标。

## 7. 模型动效配置（拟议）

每条配置绑定固定模型版本和明确的安装/型号适用范围：yawNodeKey/yawPivot/yawAxis、rotorNodeKey/rotorPivot/rotorAxis、bladeNodeKeys/pitchAxes、安装矩阵、零位偏置、旋转方向、允许范围、数据metric映射、配置修订、校验人及证据。轴在模型局部坐标，转换顺序固定为安装→机舱→转子→单叶片。

保存先检查节点存在、层级闭环、枢轴合理范围、单位和版本，再用维护权限及CAS提交。模型换版不自动沿用同名节点；配置失效时关闭对应动效，保留静态设备。未核验配置只可在明确模拟预演中使用。

透视/爆炸配置也是显示配置，不能修改源模型、工程层级或现场状态。爆炸距离和分组须有边界，全部可复位，不提供不受控脚本执行入口。

## 8. 分析和工单写入条件

“进入分析”携带 requestId、项目、固定事件键/修订、明确选定设备/表示、固定时间窗和当前上下文世代；服务端重新核对。相同 requestId 重试返回同一结果；不同用户不能复用对方私人分析。已有分析的来源更新需要明确新修订，不修改历史分析来适配最新报警。

助手只接受已保存分析修订和本轮资料白名单。项目策略决定能否使用、允许提供商和外发内容，驾驶舱不能自行扩大。超时/取消后先读原回执，不自动重复调用。来源/E编号与轮次绑定。

工单追加复用既有 expectedRevision 与 requestId；需要分析来源读取权限及目标工单写权限，两者独立。原建议和人工修改内容、来源版本/引用、采纳条目稳定ID都保留。部分校验失败整批不写，冲突不静默重试。删除/停用来源后保留必要历史说明，不能绕过当前授权读正文。

## 9. 错误和清理

复用项目既有错误封装，拟议语义包括：401会话失效、403无权限、404不可见/不存在、409修订冲突、422映射/单位/几何配置不合法、429源端受限、502/503上游不可用。错误里不带凭据、私有URL、原始上游报文或被拒绝对象的详细信息。

权限拒绝清除场景资源引用、派生参数、订阅缓冲、资料缩略图与分析上下文；同一浏览器其他有权项目不受影响。网络暂时错误与撤权严格区分，不能短暂5xx就强制清空全部工作。

## 10. 必须通过的契约验证

同设备多场景去重；同码不同设备/事件不混合；安装UID与定义UID不混用；跨项目ID注入拒绝；固定修订冲突；无权限计数/缓存/迟到回包；重复requestId不重复建分析/追加步骤；流世代切换/乱序/补齐有界；rpm0/359→1/后台恢复；气象观测与预报隔离；映射失效关闭动画；工单追加不改状态；固定E引用不随新轮重排；更改时间窗后旧回答仍固定到旧来源。
