# 项目型号与模型关联契约

2026-11-02首切，按用户“进行关联”授权实施；部署状态以工作区交接和执行记录为准。首切仅关联已有项目应用、设备配置及场景布置；后续获准的夏李项目配置、设备采用及通用热切换单列在后两节，不重建工程对象。

## 身份与保存

OntoBase负责组织型号规格、规格固定修订、项目应用及其固定修订；ONTOVis负责项目应用到共享模型固定版本的配置。三类身份分别保存：

- `projectApplicationRef`：`applicationId`、`applicationRevisionId`、`specificationRevisionId`，来自正常用户有权读取的源端API。
- `configurationId / configurationRevision`：沿用ONTOVis既有设备配置修订、CAS、幂等和审计。
- `modelAssetId / modelVersionId / contentRevision / sha256`：独立固定几何；appearance/detailed只是当前资源声明，不构成跨版本构件映射。

写入复用 `/api/workbench/equipment/configurations/save`。每个新配置固定项目应用修订及两个已校准模型版本；`models[].mappings=[]`只表示型号与几何关联，不推断内部角色、真实安装或设备采用。已有两份教学配置和历史修订保持。没有修改源端型号参数、来源质量或已采用设备。

本次20组修复先生成只读计划：模型 `modelCode`、源端规格 `code` 和项目 `applicationKey` 必须在忽略大小写后完全相等、唯一匹配。不得以显示名称、厂商相近或几何相似推断对应关系；任何重复、不一致、失效固定版本或源端变化均停止该项。计划的固定ID及SHA保存在本机output，不进入Git。正常账号经ONTOVis接口提交，不能运行已停用数据脚本、签发容器管理员Token或写源端数据库。

## 选型目录

保留既有 `/api/workbench/project-turbine-definitions` 路径，按请求项目授权读取当前项目应用和已保存配置，返回`catalogueKey=application:<applicationRevisionId>`以及配置和应用固定引用。没有根工程对象时`definitionEntityUid=null`，不将应用ID伪装成对象ID。

目录只采用源端当前、活动的风机项目应用。历史配置仍可读取，当前应用变更后旧配置不自动跟随新修订。合法旧对象关联继续作为兼容项；已有当前项目配置覆盖相同根对象时不重复返回该旧项。源端列表、应用修订、配置head及模型资产状态在返回前复查；撤权、变更或删除不能混成一份目录。

外观版和完整版由配置内的固定模型及资源形态声明提供，目录按已校准、较新版本优先；回收站模型不提供布置入口。目录的全局`pairMap`继续为空、`pairingStatus=unverified`；下文的设备定位热切换通过该设备实际采用的配置判断，不消费全局配对表。

## 页面与布置

沿用场景“模型资源 → 风机型号 / 全部模型”的卡片与落点弹窗。卡片使用应用修订作为唯一键，显示源端型号名称及“项目型号 · 声明关联”。型号没有对象定义仍可通过其已关联几何布置。

场景落位继续核对固定内容修订/SHA、校准、项目写权限和场景版本条件，保留原场景保存流程。几何布置不自动创建工程设备、替设备采用新型号或建立角色映射。

目录入口不依赖异步数据：首次渲染立即显示“风机型号／全部模型”，默认型号页；读取时仅在列表区域显示进度，不先显示全部模型再跳回型号页，不把未读取当作零项。两类目录独立加载，型号请求失败可重试且不阻止查看全部模型，回收站仍显示已删除资源。

目录投影按一次完整请求在前后核对项目权限及权限修订；内部每个步骤继续检查当前会话，源端请求仍通过本人授权API。模型内容校验、源端应用/本地配置/模型状态复查保持，不为每个模型重复请求项目访问接口；没有跨请求或跨用户的授权缓存。

模型基本信息区分“模型型号声明”和“项目型号关联”。旧`definitionEntityUid`编辑标为“工程对象定义（兼容关联）”；没有工程对象的项目应用不会混入该字段。项目型号与几何的维护复用“设备层级 → 选择项目采用 → 保存构件绑定”。共享模型中心没有项目上下文时，不硬编码Demo-PDS或泄露其他项目目录。

## 设备定位的通用热切换（2026-11-02，已发布）

热切换是产品通用规则，不绑定夏李、TU-3000、文件路径、文件名、模型型号字符串或某一组SHA。固定SHA只用于校验请求的内容身份；单模型模拟动作的已校验轴向配置属于独立能力，不能反过来成为配对身份。

既有`scenes/locate`增加可选布尔`preferDetailed`，同时要求精确的`representationChoice={sceneModelInstanceId,modelVersionId}`。默认调用保持原契约；驾驶舱进入设备、选择设备结构项或点击报警时请求该能力。

1. 只有当前场景head中的指定外观实例可自动切换。安装设备必须在OntoBase实际采用相应项目应用修订，且ONTOVis几何配置明确包含该外观固定版本及唯一的完整版固定版本。若配置含多份外观或完整版，不按名称、时间或几何相似程度猜测配对。
2. 两版分别校准到同一设备根的米制标准坐标，均为活动、可布置资源；地理场景还要求地理布置校准。两版原始模型坐标和校准矩阵允许不同，各自使用自己的已验证校准。
3. 服务端只生成当前设备的只读显示投影：实例ID、根设备身份、落点、朝向、高度、可见性和场景修订保持；只替换模型固定版本。外观构件键不带入完整版，使用完整版自身共享配置，按已采用设备的源定义关系解析到各自安装对象。
4. 响应`representation`包含`sourceModelVersionId`、投影后的`instance`、固定`modelRef`和该版模型元数据。定位边界、模型选取、隔离、报警标签和反向选取均使用同一版模型与其绑定。源定义定位仍保留原选中身份，并返回实际安装宿主。
5. 配置修订或设备采用关系在读取中变化，拒绝混合结果；请求前后维持本人项目权限、会话及固定资源复查。没有有效配对时保留原表示；有配对但完整版未校准时阻断。历史场景保留该场景的固定表示，不跟随当前型号自动换模。
6. 前端只保存当前设备范围内的临时显示投影。切换结构项时可用已读绑定先预定位，同时重新校验工程修订；迟到、失败、撤权、切换设备/场景/会话时清理。离开设备页恢复场景原外观表示，用户无需保存，也不新增场景或型号修订。
7. 资源加载器复用同一固定版本的几何缓存；只替换当前实例，其余实例继续使用外观版。进度按实际显示版本统计。已有可验证模拟轴向的两版切换时延续本机模拟转角和偏航；其他设备的模拟时钟保持。

本节不自动创建规格、项目应用、设备采用或工程对象；实际型号迁移与场景重布置按独立计划、权限、版本条件和预览结果执行。该通用能力已随前后端`6388ea6`发布；任意身份的压缩机合成场景、实际夏李15台正常账号API及公网报警定位分别通过。返回场景清除设备选择和隔离、恢复原外观版全场取景；未绑定工程对象的完整版仍可依据已加载资源元数据使用透视/爆炸查看。

## 面向用户的“项目配置”

用户可理解为：标准规格规定共同参数，项目配置记录某个项目实际使用的设备结构。夏李使用“TU-3000 3.0MW · 夏李项目配置”，沿用标准规格固定修订的参数，纳入现有13类构件；同一配置供15台风机共用，无需逐台维护。

当前源端禁止改变原型号的结构。因此实施方式为：通过既有规格预览/保存API建立独立记录，在来源中记录标准规格及其固定修订；再建立项目应用、复用既有整机及13类工程定义，显式让15台现有安装设备采用。不会创建另一套安装对象、替换设备UID或重建物理层级。已有共享资料需要按原文档固定版本和适用部件关联到新记录，保留原关联；不上传或复制文档原件。

标准后续修订不会自动覆盖项目配置。需要核对参数与结构差异后再保存新的固定修订，并明确采用；其他项目可继续使用原标准规格，也可建立自己的项目配置。热切换仅消费已经批准并实际采用的配置，不代替上述业务动作。

夏李已完成实际应用：标准规格的6项已知参数保持，15台风机及195个下级安装对象沿用原UID、属性和物理层级，通过正式预览/保存API追加210条采用记录；6条共享资料关联固定到原文档版本。原标准规格、教学配置及旧采用历史保留。场景布置为1、4–16、18号共15台外观实例，2、3、17、B1不布置；原12台实例ID/位置保留，新增15/16/18号，当前隐藏验收三角形移出布置，历史与资源保留。

13类构件中12类有独立几何，共180组实际安装构件绑定经逐台API验证；“叶轮/转子”为组合角色，没有独立几何键，沿用宿主定位，不记为独立绑定。场景位置仍为图示配准参考，新增落点按既有固定地形重采样，不构成工程定位精度验收。公网已确认15台模拟、报警到完整机舱、型号/单台参数、3张照片与预览、50项下级图纸清单及返回全场；见[执行§184](../plans/开发执行记录.md#184-夏李项目配置15台外观布置与通用热切换2026-11-02)和[本批证据](../../output/xiali-standard-layout-20261102/README.md)。
