# 项目型号与模型关联契约

2026-11-02首切，按用户“进行关联”授权实施；部署状态以工作区交接和执行记录为准。复用已有项目应用、设备配置及场景布置，不新建工程对象或设备采用。

## 身份与保存

OntoBase负责组织型号规格、规格固定修订、项目应用及其固定修订；ONTOVis负责项目应用到共享模型固定版本的配置。三类身份分别保存：

- `projectApplicationRef`：`applicationId`、`applicationRevisionId`、`specificationRevisionId`，来自正常用户有权读取的源端API。
- `configurationId / configurationRevision`：沿用ONTOVis既有设备配置修订、CAS、幂等和审计。
- `modelAssetId / modelVersionId / contentRevision / sha256`：独立固定几何；appearance/detailed只是当前资源声明，不构成跨版本构件映射。

写入复用 `/api/workbench/equipment/configurations/save`。每个新配置固定项目应用修订及两个已校准模型版本；`models[].mappings=[]`只表示型号与几何关联，不推断内部角色、真实安装或设备采用。已有两份教学配置和历史修订保持。没有修改源端型号参数、来源质量或已采用设备。

本次20组修复先生成只读计划：模型 `modelCode`、源端规格 `code` 和项目 `applicationKey` 必须在忽略大小写后完全相等、唯一匹配。不得以显示名称、厂商相近或几何相似推断对应关系；任何重复、不一致、失效固定版本或源端变化均停止该项。计划的固定ID及SHA保存在本机output，不进入Git。正常账号经ONTOVis接口提交，不能运行已停用数据脚本、签发容器管理员Token或写源端数据库。

## 选型目录

保留既有 `/api/workbench/project-turbine-definitions` 路径，按请求项目授权读取当前项目应用和已保存配置，返回`catalogueKey=application:<applicationRevisionId>`以及配置和应用固定引用。没有根工程对象时`definitionEntityUid=null`，不将应用ID伪装成对象ID。

目录只采用源端当前、活动的风机项目应用。历史配置仍可读取，当前应用变更后旧配置不自动跟随新修订。合法旧对象关联继续作为兼容项；已有当前项目配置覆盖相同根对象时不重复返回该旧项。源端列表、应用修订、配置head及模型资产状态在返回前复查；撤权、变更或删除不能混成一份目录。

外观版和完整版由配置内的固定模型及资源形态声明提供，按已校准、较新版本优先；回收站模型不提供布置入口。`pairMap`继续为空、`pairingStatus=unverified`，不恢复自动换模。

## 页面与布置

沿用场景“模型资源 → 风机型号 / 全部模型”的卡片与落点弹窗。卡片使用应用修订作为唯一键，显示源端型号名称及“项目型号 · 声明关联”。型号没有对象定义仍可通过其已关联几何布置。

场景落位继续核对固定内容修订/SHA、校准、项目写权限和场景版本条件，保留原场景保存流程。几何布置不自动创建工程设备、替设备采用新型号或建立角色映射。

模型基本信息区分“模型型号声明”和“项目型号关联”。旧`definitionEntityUid`编辑标为“工程对象定义（兼容关联）”；没有工程对象的项目应用不会混入该字段。项目型号与几何的维护复用“设备层级 → 选择项目采用 → 保存构件绑定”。共享模型中心没有项目上下文时，不硬编码Demo-PDS或泄露其他项目目录。
