# 场景删除与恢复契约

2026-10-26。用户要求修复场景无法删除，并检查各处“草稿”措辞。本切片提供项目内可恢复删除：正常列表与项目场景数不包含已删除场景，回收站提供恢复；原场景身份、内容修订、模型/地形/影像引用与文件完整保留。

## 操作与权限

沿用当前同源POST会话、完整projectRef与expectedSessionRevision。项目admin可删除或恢复本项目场景；读取仍需当前项目访问权。新增路径为`/api/workbench/scenes/delete`及`/api/workbench/scenes/restore`，输入严格限定sceneId、expectedSceneRevision、expectedLifecycleRevision、clientRequestId。请求上限沿用小请求边界。

内容头修订及生命周期版本都必须匹配。生命周期版本从0开始，每次删除/恢复加1，避免删除后恢复的旧页面再次误删。写入、目录版本、审计与幂等回执同一SQLite事务，提交前再次核验当前会话/权限；失败完整回滚。同一主体/动作/requestId及相同内容重放返回固定回执，重放仍核验当前权限，不将历史回执解释成当前场景状态。

新增scene_lifecycle表，仅在首次删除/恢复时登记场景状态；原场景默认active。state为active或deleted，不物理删除业务行。删除后open、head、保存和检查均返回SCENE_DELETED；恢复重新开放原内容。保存请求携带expectedLifecycleRevision，服务在预读和最终提交时同时比较，防止删除/恢复期间开始的旧保存提交；从未变更生命周期的旧场景可省略该字段并视为0。列表state默认active，可指定deleted，分页游标绑定状态及目录修订。模型使用去向将已删除场景全部计入保留引用，不能继续跳转，提示先从回收站恢复。

## 页面

正常列表及场景详情提供删除，说明将进入回收站并可恢复；有未保存修改时先保存或放弃。回收站只提供恢复。未知结果重试沿用原requestId，冲突需重新读取；不通过前端按钮状态代替后端授权。没有永久清理入口。

“草稿”只用于确有需要的状态表达。现有场景基本信息按钮改为“应用”，设备关联提示改为保存后生效，冲突提示表述为“当前修改已保留”；内部变量、协议和历史文档不因产品措辞改名。

## 验收与发布

覆盖删除/恢复/旧内容回读、跨项目与只读拒绝、撤权回滚、并发及旧版本冲突、幂等、分页失效、项目计数与保留资源。实际浏览器只对明确新建的验收场景演练，不删除用户既有场景。发布前后使用现有包含分析数据的整组备份，恢复到全新库/目录验证生命周期状态、原业务行和文件。写入删除状态后，不直接回退到不识别该状态的旧服务。
