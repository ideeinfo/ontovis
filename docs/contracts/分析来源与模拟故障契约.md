## 1. 固定来源引用

所有接口沿用同源会话、`expectedSessionRevision`、完整`projectRef`及当前项目权限。分析属于当前稳定用户UUID；项目管理员也只能向自己的分析登记来源和关联工单。客户端不能提供owner、工程映射UID替代规则、任意URL或资料正文。

路径前缀为`/api/workbench/analysis-sessions`，以下请求上限16KiB。登记来源不增加分析内容修订，当前画布保存格式仍只接受原人工笔记与关系。Q-23实施时再接来源卡片快照校验，不提前放宽成任意JSON。

| 后缀 | 输入（公共会话与项目字段以外） | 行为 |
| --- | --- | --- |
| /evidence/register | analysisSessionId、expectedAnalysisRevision、requestId、sourceKind、selector | 当前来源读取后登记不可变句柄；返回evidenceRefId/sourceKind/sourceRevision；按头修订、owner及幂等请求提交 |
| /evidence/detail | analysisSessionId、evidenceRefId | 当前权限下读取固定来源；缺失、版本变化、受限或上游不可用时不返回旧源正文 |
| /evidence/content | 同detail | 复用既有受保护图纸、照片或模型内容读取；照片只发一次源内容请求，不额外串行核验元数据 |
| /link-work-order | analysisSessionId、analysisRevision、orderId、expectedOrderRevision、requestId | 指定已保存分析修订；工单固定引用、事件、完整快照及幂等回执同事务提交；不关闭工单或消警 |
| /simulation/catalogue | 无业务参数 | Demo-PDS的固定版本模拟数据目录及缺证反例 |
| /simulation/detail | datasetId、datasetRevision | 项目内只读报警和趋势回放，不创建分析或来源句柄；见[查看契约](模拟报警查看契约.md) |
| /simulation/qualify | faultCode | 当前工程对象—柜级—图纸—已有照片区域核对；只标记测试分支资格，不确认工程根因 |

| sourceKind | 登记selector | 固定依据与读取边界 |
| --- | --- | --- |
| object | entityUid、expectedEntityRevision | 服务端读取对象及其实际上下文，固定实体/层级修订 |

引用存入独立PG的`analysis_evidence_refs`，绑定session和request，数据库禁止更新/删除。每会话100条、全库10000条/描述参数8MiB；描述不缓存原件正文。当前权限在返回/提交前复核；源读取不占PG写事务锁。相同requestId/内容重放原句柄，不同内容409。句柄摘要标识固定描述，不等于源系统已经确认工程适用性。

## 2. 工单历史与固定分析关联

`/api/workbench/work-orders/snapshot`只读取明确的`orderId/orderRevision/snapshotSha256`。引用和后续业务操作保留当时完整工单、诊断、事件、资料目标及已有分析关联；从未保留的旧版本明确不可用，不能以当前状态补写历史。

新表`work_order_snapshots`与`work_order_analysis_links`不可更新/删除。关联需当前项目管理员、当前工单版本和本人指定分析修订；版本、分析SHA和权限均由后端核对，重放也不绕过授权。后续分析保存r2不会改变已关联r1，后续工单操作也不改变引用时快照。关联只推进工单记录版本、增加事件，不改变执行状态或代替人工复核。

## 3. 模拟故障源

固定来源`ontovis-simulated-faults`仅在Demo-PDS可用，`sourceKind=simulated`、`mode=replay`持续返回。回放窗口为2026-10-25 00:00:00Z—00:03:00Z，epoch为`pds-electrical-rehearsal-v1`；数据集修订由固定配置及窗口摘要生成。发生/恢复使用同一事件ID的两个版本，保留原严重性、源/接收时间、序号和水位；未声称源SCADA已确认。

| 故障码/分支 | 测试预设 | 当前用途 |
| --- | --- | --- |
| 13001 / sensor_bias_high | 传感器72°C、独立参照约24°C | 已核对现有对象、CN1归属、图纸及原照片标签，可作所选分支的来源链正例 |
| 13002 / sensor_bias_low | 传感器−18°C、独立参照约24°C | 同上；预设为测量偏差测试条件，不认定现场温度或根因 |
| 13003 / status_feedback | 浪涌保护状态接点异常 | 对象与模块通道可解析；缺已有照片区域时为缺证负例 |
| 13004 / status_feedback | 人工断开断路器，过流保持未动作 | 同上；不认定实际跳闸或雷击原因 |

温度分支同时提供传感器/独立参照；供电、反馈和过流也有明确单位与类型。每条曲线181个1秒样本，第90秒为bad/null，不插值补齐。未映射或无照片不阻断模拟数据读取，资格核对是独立操作；工程卡片仍分别核对各自来源。

实际源核对发现`105A3/IX.1`和`IX.2`是模块内地址，按固定地址落到现有CN1-105A3模块，不创建虚构独立通道UID。柜级定义没有照片关联时，沿用已有器件的柜体照片标签关联，不重复登记柜级照片或补造区域。照片元数据`not_checked`不会阻断打开，内容由既有受保护读取验证。定位粒度保持来源标签，不能宣称全部器件已在照片识别。

13001/13002的X91跨页链、13033/13035缺证及13058术语缺口继续为负例；`wholeFaultDiagnosisComplete=false`和`engineeringConfirmation=false`保持。实时SSE、断线补数、逐实例报警呈现、策略及助手仍按Q-17/18/22/24实现，正式测试可用本模拟源；真实源接入与现场适用性后续另验。

## 4. 迁移与整组恢复

PG schema名保持`ontovis_analysis_v1`以兼容既有配置，元数据版本由1显式升至2；新增第五张不可变来源表，原storeId、owner、会话、修订、回执逐行保持。升级工具要求停服、排他目录租约、预期storeId及PG锁；运行时不自动升级。运行账户仅新增该表SELECT/INSERT，不获修改历史或schema权限。

备份同时识别旧四表v1和新五表v2，恢复采用匹配版本并生成新存储身份。完整配对还核对模型固定版本与文件、工单完整快照SHA、工单事件和固定分析修订；悬空引用拒绝发布成功清单。恢复只写新库/新目录，不能用旧备份覆盖现库；原件仍在OntoBase或既有私有资源库，不复制进分析正文。
