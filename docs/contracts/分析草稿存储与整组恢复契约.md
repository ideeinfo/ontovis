## 1. 已实现范围

[analysis_drafts.py](../../apps/api/analysis_drafts.py) 采用专用 PostgreSQL schema `ontovis_analysis_v1`，显式初始化，运行时不建表、不自动降级。与自有项目登记可位于同一个 ONTOVis 独立库；不写 OntoBase 业务库。

| 表 | 内容与限制 |
| --- | --- |
| store_meta | 固定源连接和存储身份；不可覆盖 |
| analysis_sessions | 固定UUID、完整项目范围、owner UUID、名称/过程状态、头修订；身份和所有者不可更改 |
| analysis_revisions | 规范化JSON文本、SHA、操作者、create/save/restore、恢复来源及时间；数据库触发器禁止更新/删除 |
| analysis_requests | 完整项目/主体/requestId、请求摘要、固定操作回执；与修订同事务且不可覆盖 |
| analysis_evidence_refs（v2） | 本人会话、来源类型、服务端固定描述与SHA、请求指纹；不可覆盖；不缓存原件正文 |

只接受人工分析卡、笔记、人工关系和布局；拒绝源卡、工程对象上下文、额外URL/正文/凭据字段。固定来源句柄现由独立受控接口准备，详见后继契约；画布内容校验仍保持首期格式，Q-23再接来源卡。不能把浏览器自报身份存成权威证据。保存的前三种状态在界面显示为分析中、待现场核查、待复核；结论确认/归档尚不开放。

调用者必须从可信服务会话提供稳定主体UUID、当前项目角色和授权回调；本候选不接收客户端owner。项目admin只能写自己的草稿；读取也限定本人、连接与项目。每次读写及重放在返回/提交前再检查授权，撤权引发事务回滚。HTTP 从源 `/auth/me` 取得稳定用户 UUID，并与当前登录主体绑定；用户名相同而 UUID 变化时失效。客户端不能指定 owner。真实 HTTP 与临时 PG 已通过合成授权反例；真实账号验收另记于执行记录。

创建产生r1；保存必须命中期望头修订；恢复旧版追加新修订，原内容/摘要保持。相同requestId、相同内容返回原回执；不同内容409；当前已撤权不能重放成功。修订、头指针和回执同一事务提交；并发保存只有一个版本获胜，不覆盖对方。

快照256KiB、50卡/100人工关系、单笔记4000字；每会话最多1000修订、每项目最多1000会话。本隔离候选全库最多10000修订、规范化快照正文合计8MiB，写前串行核对；拒绝超过后无法完整导出的写入，不清理旧版本。该限额是候选验收边界，正式上线前需按实际用量完善容量与归档，不作生产容量承诺。

## 2. 备份与恢复

[analysis_draft_backup.py](../../tools/analysis_draft_backup.py) 负责旧四表v1、新五表v2的匹配导出与新schema恢复：只读一致快照、原JSON文本与SHA、连续修订/头指针、owner/项目/回执/恢复来源一致性；新存储身份，原会话/修订/主体/时间保留。清单和内容显式摘要核对，拒绝已有目标、符号链接、改动内容、缺失版本或回执。独立分析备份不替代完整工作台备份。

[analysis_workbench_backup.py](../../tools/analysis_workbench_backup.py) 已补齐完整配对：

1. 明确停服条件；按实际版本对分析四表或五表持共享表锁，现有工具持本机目录与项目登记占用保护，读取期间阻止写入。活动工作台拒绝备份，不把传入停服标记当作服务已停的唯一证据。
2. 整组包含 `workbench/` 的登记、全部业务库/保留文件，`analysis/` 的全部分析修订，以及顶层清单；核对连接一致，分析项目须已在登记中存在。待准备/阻断项目的既有草稿仍保留，不以不可用状态丢弃数据。
3. 恢复前核对全部子清单/字节/范围；只写全新目录与没有两套目标schema的自有数据库。复用原登记恢复与文件核对，原项目UUID、场景/模型/工单数据不迁义；分析修订/请求回执完整回装。
4. 数据库与文件不能跨系统原子提交。任何中途失败保留已产生的目标供诊断，撤下顶层清单或 `recovery.json`；已存在部分schema也不能重用。成功回执明确 `recovered_not_activated`，不自动启动服务或将其当正式启用许可。
5. 正式消费端使用同一独立数据库，并以 `ONTOVIS_ANALYSIS_STORE_ID` 显式绑定已验证的存储身份；存在分析 schema 而未配置身份、身份不匹配或连接不匹配均拒绝启动。旧登记快照命令遇到分析 schema 会拒绝遗漏草稿。此切片不是多HTTP进程、分布式任务或在线备份能力。整组快照的共享表锁需要离线所有者权限，不扩大运行账户的历史表写权限。

运维参数只从既有环境变量读数据库连接，命令及回执不打印凭据。候选命令示例（路径需使用操作者实际新建的目标）：

```sh
python -m tools.analysis_workbench_backup snapshot --project-root "$project_root" --library-root "$library_root" --model-root "$model_root" --destination "$new_backup" --service-stopped
python -m tools.analysis_workbench_backup verify --backup "$new_backup" --manifest-sha256 "$manifest_sha256"
python -m tools.analysis_workbench_backup restore-new --backup "$new_backup" --manifest-sha256 "$manifest_sha256" --destination "$new_restore" --service-stopped
```

默认数据库变量 `ONTOVIS_REGISTRY_DSN`；恢复必须由操作者配置为全新自有目标库，不能沿用在线库。无旧模型配对时省略 `--model-root`。不得将旧B0覆盖新写入，也不得复制/伪造登记标记跳过目录身份。

## 4. 首期 HTTP 与页面

沿用同源会话、`expectedSessionRevision` 和完整 `projectRef`。所有路径以前缀 `/api/workbench/analysis-sessions` 开始。列表和读取只返回本人当前有项目权限的草稿；项目 admin 可写自己的草稿。

| 后缀 | 已实现输入 | 行为 |
| --- | --- | --- |
| 空 | q、status、limit≤50、cursor | 名称/前三种进度过滤；游标绑定本人、登录修订、项目、过滤及列表快照 |
| /create | requestId、snapshot | 新建r1；首次使用时准备自有项目空间 |
| /detail | analysisSessionId、可选analysisRevision | 当前头或固定历史；仍核验当前主体与项目授权 |
| /save | analysisSessionId、expectedAnalysisRevision、requestId、snapshot | 条件保存；冲突409；回执和头版本原子提交 |
| /restore | analysisSessionId、expectedAnalysisRevision、requestId、restoreRevision | 固定历史追加为新修订 |
| /revisions | analysisSessionId、before、limit≤50 | 倒序有界修订摘要；nextBeforeRevision继续分页 |

创建/保存请求上限264KiB，快照仍256KiB。只接人工笔记/关系/布局和时间范围；源对象、报警、工单上下文与来源卡仍拒绝。没有确认、归档或分享路径；后继工单固定关联路径见[来源契约](分析来源与模拟故障契约.md)。仍返回`canConfirmConclusion=false`、`sourceCardsEnabled=false`，v2增加`sourceReferenceApiVersion=1`和按当前权限返回的`canLinkWorkOrder`。

工作台“分析画布”入口提供本人列表、新建、笔记/人工关系、固定/拖动/整理/撤销、平移/缩放、保存及历史恢复。未知保存结果保留冻结请求及 requestId 重试；冲突保留本地修改，可另存副本或明确放弃后重新读取。跨页面/项目离开有未保存提醒，权限丢失清理当前内容；只读视角调整不算未保存编辑。页面不提供自动推理或现场事实确认。

本批测试：13项合同、24项登录会话、9项部署；18项PG存储、8项配对恢复、12项实际HTTP、19项登记回归分列通过；完整前端357项和构建通过，最终定向36项包含在相关前端范围内。浏览器已验证实际PG创建r1、保存r2、恢复r3、并发409与另存副本、离开提醒、拖动/撤销。全部隔离数据明确标为合成，线上账号结果另记。
