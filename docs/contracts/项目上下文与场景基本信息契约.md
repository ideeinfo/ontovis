## 1. 权威项目来源

已存在的 OntoBase 接口（核对版本 `cb0414658016d507356333ff907e4df2f8c433c3`）：

| 实际接口 | 已有语义 | ONTOVis用途 |
|---|---|---|
| `GET /api/v1/projects` | 全部有权active项目；配置的系统管理员可见全部；无分页 | 项目目录，不在本地伪造或只保留Demo-PDS |
| `GET /api/v1/projects/{code}/access` | 项目名、本人role/capabilities/accessRevision | 选中项目的访问摘要及每次读写权限核验 |
| `GET /api/v1/projects/{code}/objects` | 分类分组、搜索、分页，可限定installationContextId | 项目对象树和设备选择目录 |
| `POST /api/v1/projects/{code}/objects/resolve` | 最多50个UID，按项目及当前权限核验 | 保存时核查对象归属/版本 |
| `GET /api/v1/projects/{code}/installations/{id}`及其`children/ancestors` | 真实安装范围及父子链 | 选中设备的物理树和路径 |
| `POST /api/v1/projects/{code}/object-evidence/resolve`及`content` | 对象自身/明确型号来源的受保护资料 | 保持分析对象身份的图纸查看 |

项目目录返回 `project_code/project_name/description/status` 等字段，**没有project UUID**。源表主键是project_code；`projectRef`映射为 `{ontobaseConnectionId, projectCode}`，名称不进入身份键。当前项目目录范围不能擅自突破源系统成员权限；停用项目不再允许新访问，本地保留其数据等待权限/状态恢复。

“项目→安装范围”的物理树总览需要拟增 `GET /api/v1/projects/{code}/installations?limit=&cursor=`：只读、有界、游标绑定当前用户/项目/accessRevision/安装目录快照；返回 `items`（复用public_context形状）、`nextCursor`及安装目录修订。复用原工程表，不新增物理关系。该路径目前**不存在GET实现**，不得与现有同路径POST创建安装范围混淆。初期已有分类目录加选中对象物理树可先复用；全项目物理树总览必须等此接口验收。

## 2. 本地持久结构（已实现）

```text
project_workspaces
  workspace_id              TEXT PRIMARY KEY        # 本地生成的存储身份
  ontobase_connection_id     TEXT NOT NULL
  project_code              TEXT NOT NULL            # 源系统主键
  storage_key               TEXT NOT NULL UNIQUE     # 服务端生成，不接受客户端路径
  legacy_context_id         TEXT NULL                # 只供旧模型兼容入口
  state                     TEXT NOT NULL            # preparing / ready / blocked
  block_reason              TEXT NULL                # 来源/作用域冲突，非某个用户的撤权
  created_at                TEXT NOT NULL
  UNIQUE (ontobase_connection_id, project_code)

workspace_scope             # 每项目私有库内一行
  id                        INTEGER PRIMARY KEY CHECK(id=1)
  workspace_id              TEXT NOT NULL UNIQUE
  ontobase_connection_id     TEXT NOT NULL
  project_code              TEXT NOT NULL
  scope_version             INTEGER NOT NULL
  UNIQUE (workspace_id, project_code)

scenes                      # 原表增量调整
  workspace_id              TEXT REFERENCES workspace_scope(workspace_id)
  project_code              TEXT NOT NULL            # 原字段保留
  # 升级SQLite通过insert/update触发器强制workspace_id非空
  # 并核workspace_id与project_code同时匹配workspace_scope
  ...原sceneId/名称/头修订等字段保持
```

登记库以registry_meta记录schema_version=1及connection_id；整组备份清单记录登记库摘要、所有workspace与库的对应关系；这不是一套新工程项目表。登记与目标库必须验证连接、项目及workspace一致后才能服务。不同项目不能映射到同一storage_key，不能通过目录名或场景名称反推归属。

登记库和私有库不假设跨库事务：同一连接＋项目首次初始化在单进程内串行，并由登记唯一约束防重复；先持久登记preparing及稳定存储键，再初始化、校验scope，最后置ready。preparing不提供业务服务；失败或重启后检查原目录/库后恢复同一workspace，不能重试生成另一份空间。发现scope冲突保留原目录、置blocked，禁止覆盖；只有全部就绪后才能执行原创建/上传幂等动作。目录扫描不得触发初始化。多进程写服务仍在本批范围外。

旧 `library.context_id` 改为可空旧兼容值；现有Demo-PDS原值不改。新项目不制造占位安装UUID。迁移在副本中生成明确schema迁移记录，并运行外键及所有引用完整性核对；不修改不可变的scene_revisions快照JSON/ID。当前资源表无需批量增加项目列，物理库和workspace_scope共同给出其唯一项目范围。

当前单一OntoBase连接继续使用部署配置；登记固定其逻辑身份。换源系统必须换连接身份，不能用同名项目自动继承旧空间。源系统当前无法提供项目不可变UUID，因此不宣称可以自动检测所有“删除后以相同代码重建”的情形；确认的项目删除/来源冲突需持久置blocked，保留旧空间并阻断自动重挂。单个用户的403、普通成员目录缺项或暂时源故障不能证明项目删除，不能据此把其他成员空间全局置blocked。

## 3. 会话与项目请求

身份登录只验证当前用户是否有效，不再把固定Demo-PDS的access当成整站登录条件。会话轮询仅维护身份；项目访问以对应access为准。无项目权限是目录空态，不是登录失败。

所有下列ONTOVis接口仍走同源POST、HttpOnly会话、Origin/Host检查、`expectedSessionRevision`与no-store。下列路径已实现：

| 路径（`/api/workbench`前缀） | 请求变化 | 响应/约束 |
|---|---|---|
| **新增** `/projects` | `q?, cursor?, limit?` | 权威目录过滤后的项目摘要，`projectRef/displayName/sourceDescription/status/sceneCount/workspaceState`；默认50、最大100。游标绑定会话用户、筛选和项目目录摘要，源失败不返回空成功 |
| **新增** `/projects/access` | `projectRef` | 当前项目名、role、capabilities、accessRevision和可用状态；仅查看，不改变会话的全局项目 |
| 扩展 `/scenes` | 必填`projectRef`，保留q/cursor | 仅该项目场景；每条带归属摘要，项目目录无需加载场景内容 |
| 扩展 `/scenes/create` | 必填`projectRef`，原`displayName/clientRequestId`，可选`description` | 当前权限验证后创建；项目缺失/不可用不回落默认值；首个修订保存在该项目库 |
| 扩展 `/scenes/open/head/check/save/replacement-check/locate`及同族业务路径 | 必填`projectRef`，原有sceneId/修订/业务体保持 | 服务端在对应空间中查sceneId并核scene归属；不扫描其他库尝试命中 |
| 扩展资源/地形/影像/公开数据/缩略图/任务/使用去向路径 | JSON体或既有上传元数据头内必填`projectRef` | 资源、后台任务和异步结果均固定到请求空间；切项目不改任务所属项目 |
| 扩展对象/目录/图纸路径 | `projectRef`；可选`sceneId`，保留对象/context/修订条件 | 有sceneId时必须匹配其持久归属；场景外“设备层级”按选中项目访问 |
| 扩展旧模型/旧迁移入口 | 显式`projectRef`及原模型选择 | 无legacy context时返回不可用状态；绝不回落7号；已迁移旧写仍由冻结门拒绝 |

`projectRef`只允许两个已知字段，连接ID必须等于服务端配置的可用连接。项目代码先经权威目录/access和本地登记核实，再组成上游路径；URL必须编码，不接受上游URL或路径片段。场景响应携带服务端核实的 `projectRef/workspaceId/projectName`；前端不能把任意选择框值当持久归属。

错误处理需区分身份与项目：401处理身份失效；项目403/不存在对外统一无权或不可用，只清对应项目私有内容并回目录，不触发全站登出；其他有权项目仍可用。api.ts已将项目级拒绝与身份失效拆开。409保留会话/场景/分页/请求冲突语义。已实现 `PROJECT_REQUIRED`（422）、`PROJECT_SCOPE_MISMATCH`（404，不披露另一项目名称）、`WORKSPACE_SCOPE_INVALID`（409，保留现场、停止写入）；沿用现有错误字典的显示映射。不将源503错误显示为“无项目”。

### 多标签、游标和重放

- 不新增全局 `selectedProject` 到服务端会话。A/B标签的请求分别携带作用域，可并行访问各自有权项目。
- 幂等作用域包括连接＋项目＋本人＋动作＋clientRequestId；projectRef在分派前验证，幂等记录位于对应项目物理库中，跨项目不复用。同一请求号在不同项目不命中对方结果，重放前仍核当前权限。
- 分页游标、几何预检回执、图纸凭据、资源内容/缩略图修订与缓存均绑定workspace/连接/项目以及原有用户/授权/版本条件；不能只因UUID或SHA相同就跨项目复用。
- 所有已有业务路由必须完成作用域盘点；发布时不能留“缺项目就默认Demo-PDS”的兼容写入口。旧前端写请求缺projectRef应明确拒绝并提示刷新，不清空服务器数据。
- 选择新项目后取消旧请求并递增前端epoch；迟到的会话相同但项目不同的响应也必须丢弃。保存结果未知状态先核对原项目请求结果，再允许离开。

## 4. 场景基本信息

```ts
// 已实现：只给既有EditableSceneSnapshot增加一个可选字段。
interface SceneBasicInformation {
  displayName: string;   // 已有；去首尾空白，1—200个Unicode字符
  description?: string; // 新增；0—2000个Unicode字符，纯文本，可显式清空
}
```

- 名称不允许控制字符；说明允许换行，不允许其他控制字符/HTML执行。前后端按Unicode字符统一计数，避免JS UTF-16与Python长度不一致。
- 旧快照缺description时只按空白显示；读取不新增字段/新修订。显式编辑说明才写入。能力返回 `sceneInfoWriteVersion:1`，具有description的头修订要求新版写入声明并保留或显式修改该字段，防旧写静默擦除。
- 不新增独立scene_info真值表或快速改名端点。列表“基本信息”先open最新修订，编辑器共用同一草稿；check/save沿用原`expectedSceneRevision/clientRequestId/reviewedEngineering/rootBindingChanges`及环境写能力要求，已增加 `sceneInfoWriteVersion:1` 条件。
- 成功保存原子新增场景修订、更新`scenes.display_name`/更新时间/目录修订并记scene_audit。只改名/说明时模型固定版本、实例ID、工程引用、坐标及其他快照字段不得变化；不能因改名重新上传GLB或校准。
- 并发改名/布局必须报头修订冲突；不自动用旧完整快照覆盖他人布局。名称无需唯一，保持已有规则；稳定定位依靠sceneId及projectRef。
- 所属项目不放进EditableSceneSnapshot的可写字段。普通save拒绝project/workspace变更；前端显示只读项目。没有无归属新场景，也没有同时属于多个项目的场景。

## 5. 对象与安装树边界

场景工程引用继续为`{ontobaseConnectionId,projectCode,entityUid}`。实例根关联与构件关联的对象必须属于场景项目；每个实例的关联按权威对象独立解析并核验有效安装上下文，保留现有对象引用及EngineeringExpectation结构，不在实例上另增一份安装上下文真值。不得把启动配置中的旧7号context默认套给全项目对象；同一合法安装范围内的多个对象可以具有相同context。

源对象目录是全项目业务分类视图；真实物理关系来自installation children/ancestors。分类节点和型号定义不会生成安装关系。无几何子对象可通过最近有效祖先显示，资料请求保留子对象自身身份。更换项目时不能通过保留旧树内存来“续用”工程引用。

保存/定位/资料时服务端重新验证项目访问、对象与安装范围归属、实体/层级/来源修订；前端选择限制只是体验。错误项目、跨项目UID、错context、撤权、已停用项目均拒绝；合法零对象项目返回空目录，不回退旧7号。

## 6. 迁移和验收要求

- 只把当前库登记到其已记录的连接及project_code；源目录无法确认时保留库、阻断映射，不自动创建项目。新增scope和scene外键不制造业务修订；历史快照/环境/云/影像/设备/三柜/图纸引用保留。
- 备份schema需同时覆盖登记库与所有项目库；验证workspace映射、连接身份、每库项目、旧写冻结、资源与历史引用、schema版本。restore在新目录执行；恢复后重新核权，不能从备份恢复旧成员权限。
- 测试以两项目/两用户/多标签及无安装新项目为核心；对每种读取/上传/下载/后台任务/保存/重放做错项目反例，加入A项目撤权后B标签持续可用、初始化部分失败及并发重试，不能只验证场景列表过滤。
- 只改基本信息的保存对比须证明除displayName/description和场景修订/审计/目录摘要外无业务内容变化；历史打开仍显示历史名称。
