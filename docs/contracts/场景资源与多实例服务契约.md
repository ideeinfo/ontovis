## 1. 已实现范围与新增边界

扩展前的[工作台服务](../../apps/api/workbench_server.py)、[HTTP边界](../../apps/api/session_http.py)和[模型库](../../apps/api/model_library.py)仅支持固定设备上下文。当前同一服务内已接入项目资源、地形、整快照多实例和工程关联；旧单机兼容入口保持原语义，完整迁移仍待执行。普通JSON读取限16KiB，模型上传20MiB；场景save/check/replacement-check单独放宽为1MiB。实际通过与未完成项见上列切片，不另建身份平台或通用适配层。

| 现存路径，均为POST | 本轮处理 |
|---|---|
| `/api/workbench/models`、`/models/upload` | 保留旧列表/上传行为；Q-03把版本归入项目资源，迁移后不再依赖7号才可管理文件 |

| `/api/workbench/models/binding` | 仅旧单机兼容入口；迁移后写入唯一兼容场景，同一关联不得同时维护两份真值；多实例不得猜默认实例 |

本切片服务器仍固定一个受控OntoBase连接和项目（首测Demo-PDS），客户端只引用服务端返回的连接ID/项目代码，不能提交上游URL、令牌或服务器文件路径。资源管理由项目授权决定，不由任何特定风机的安装用途决定。项目对象与物理链仍只通过OntoBase API读取。

## 2. 请求、权限与并发约定

- 新JSON路径均为同源POST，`Content-Type: application/json`、当前HttpOnly会话Cookie和`expectedSessionRevision`必需；沿用Origin/Host/跨站检查。未知字段、重复JSON键、非有限数值、越界值和重复实例ID均拒绝。响应为`Cache-Control: no-store`。
- 项目成员可读，当前项目`admin`可创建资源、校准版本和保存场景；无写权限返回明确只读能力。锁定是位置编辑状态，不能当权限。其他角色不在本批新增。
- 所有业务写入带UUID `clientRequestId`。幂等键作用域为“项目＋真实用户＋动作＋请求ID”；记录规范业务载荷摘要。重试同载荷先返回已提交结果，不再增加修订；不同载荷返回`409 REQUEST_CONFLICT`。会话修订是传输条件，不计入业务摘要；每次重放仍查当前会话/读权限，写类请求也查当前写权限，不向已撤权用户回放旧内容。
- `sceneRevision`、`libraryRevision`、资源/坐标修订是不可解释的不透明字符串，不从数字大小推导新旧。保存必须携带读到的`expectedSceneRevision`；相同名称不承担身份。
- 写入开始与事务提交前检查本人会话、当前项目成员/角色和授权修订。角色或授权变化拒绝整次提交；不能保存成功后再标待核实。工程对象/层级期望修订另行比较，不能由场景修订代替。
- 场景创建/保存/引用计数/幂等结果/审计在本地同一事务提交。文件先写私有暂存、校验与落盘，再登记可读固定版本；未登记的孤立暂存可清理，不能清理已有引用的制品。Q-03须补迁移、崩溃恢复和复制库验证。
- 仍为单进程测试SQLite，写事务串行比较；不宣称跨OntoBase与ONTOVis的分布式事务。外部核验到本地提交间的剩余窗口有记录，之后的权威变化使关联待核；运行定位继续重新验证，不能永久信任保存时结果。
- 读取在返回前再次检查会话和授权。前端用`contextEpoch`丢弃切场景、选对象、退出之后的迟到结果；该字段不授予权限。

## 3. 记录与引用

| 记录 | 固定字段及规则 |
|---|---|
| `ModelAsset` | `modelAssetId, displayName, purpose, assetRevision, versions[]`；用途仅`equipment / simplified_scene / environment`，不是工程分类 |
| `ModelVersion` | `modelVersionId, modelAssetId, contentRevision, sha256, bytes, state, report, calibration, components`；内容、目录和校准一经就绪不可变；校准变化生成新版本，可引用同一文件指纹 |
| `Calibration` | `state, unit=m, axes=Y_UP_RIGHT_HANDED, basePoint[3], forward[3], modelToCalibrated[16], verifiedBy, verifiedAt`；输入只含单位、轴向、基点和水平正面向量，服务端计算刚体矩阵及本人/时间；已校准指操作者核对，不等于现场精度已确认 |
| `TerrainVersion` | `terrainVersionId, contentRevision, sha256, source, license, horizontalCrs, verticalDatum, relativeReferenceId?, heightUnit, bounds, resolution, noData, transformId, processing, artifacts[]`；原件与派生固定指纹 |
| `Scene` | `sceneId, projectCode, displayName, headRevision, updatedAt, instanceCount`；创建即有空的已保存修订 |
| `SceneSnapshot` | `sceneRevision, displayName, coordinateFrame, terrain, instances[], initialView, defaults`；整体不可变，含完整地形/放置/关联/视图；服务器另存派生`bindingIssues/heightProvenance`，不包含真实测点或现场控制参数 |
| `SceneModelInstance` | `sceneModelInstanceId, displayName, modelVersionId, placement, visible, positionLocked, rootBinding, componentBindings[]`；稳定ID跨场景修订保留，移除后不复用给另一设备 |
| `EngineeringRef` | `{ontobaseConnectionId, projectCode, entityUid}`；`entityUid`不可由名字/RDS/目录点推断，型号定义不能冒充安装设备 |
| `Binding` | 工程引用、实际`installationContextId`、对象/层级修订、`purpose/status/geometryQuality`与核验来源；这些事实由后端返回，不接收浏览器自报已确认 |

`componentKey`只在`modelVersionId`内解释。源身份仍为`sourceModelKey + sourceElementId + placementId`；Three运行时ID、节点序号与名称不跨版本。实例拾取键为`sceneId + sceneModelInstanceId + modelVersionId + componentKey`。一个对象可对应同实例内多个构件；同一实例同一构件只有一个主要工程对象。整设备绑定作为未关联构件的兜底。

模型原件读取与某一设备绑定修订解耦：有权用户可查看固定模型资源，即使某个实例关联待核。关联失效停止该对象高亮/定位，不把合法资源本身报成不可读；撤掉项目权限时二者均清理。

### 上传与列表边界

- 模型继续`model/gltf-binary`原字节；新增`X-Model-Metadata`限定字段为`expectedSessionRevision, expectedLibraryRevision, clientRequestId, displayName, purpose, sourceNote, rightsDeclared, modelAssetId?`。不带资源ID则新建资源，带ID则追加版本。保留现行20MiB与静态GLB校验限额；校准未核对可独立预览，不可加入新场景。旧7号入口兼容保留，不自动认定其校准已确认。
- 地形使用`image/tiff`原字节和`X-Terrain-Metadata`：`expectedSessionRevision, clientRequestId, displayName, sourceNote, licenseNote, rightsDeclared, verticalDatum, heightUnit=m`；可选`aoi=[west,south,east,north]`，`UNKNOWN_RELATIVE`另需`relativeReferenceId`。字段头为base64 UTF-8 JSON，沿用8192字节头/6144字节解码上限。水平CRS必须在原件内，当前不接收`suppliedCrs`等覆盖别名；高程声明补来源，不能覆盖文件已存在的冲突。缺失水平CRS明确拒绝，不接收客户端重投影命令或下载URL。
- 原始上传长度必须已知，拒绝Transfer-Encoding或多个Content-Length。所有私有原件和制品不得进静态目录，内容返回明确类型、长度和指纹，不支持未授权直链。首次地形任务结果仅为可用资源，采用到场景需要另一次保存。
- 列表默认50/最大100；游标绑定用户授权、项目、筛选、版本快照和排序，不能换条件续页。库/场景变化导致分页快照失效时返回`409 SNAPSHOT_EXPIRED`，不静默漏项。使用去向只返回当前有权场景；撤权后的数量不得泄露别的项目。
- 首切不提供模型/地形物理删除接口。服务和未来清理任务都必须拒绝删除当前或保留修订引用的版本；`RESOURCE_IN_USE`返回可读使用去向。移除场景中的实例不等于删除资源。

**V1.2资源接入补充：** 旧模型目录返回`libraryRevision`和`items[]`，每项含`modelVersionId, displayName, sourceNote, sha256, bytes, modelRevision, legacyBindingCount, calibrationState, canPlace, sourceRightsDeclared, canImport`及可选`importedResource={modelAssetId,modelVersionId}`。`import-existing`只复用原`model_uploaded`审计中明确为真的使用声明，无记录时明确拒绝，不让客户端自报补齐；同一旧版本只生成一份导入资源，同请求幂等重放取回原结果，其他重复导入返回`MODEL_ALREADY_IMPORTED`。新资源复制固定私有文件/报告/构件目录和显式代理标记，`sourceModelVersionId`指原版本，原版本、绑定、场景和审计保持不变；新版本仍需校准才能布置。此操作不是旧工程关联迁移，也不因文件可复用就确认现场身份。未导入旧版继续通过既有模型中心查看，不能伪造成项目资源预览响应。

场景响应另含从当前项目授权摘要取得的`projectName`，不依赖默认设备或隐藏对象页读取。

地形目录摘要为`terrainVersionId,contentRevision,displayName,sha256,createdAt,sourceHorizontalCrs,verticalDatum,coverageWgs84`；旧报告缺项明确为null，不默认坐标系或覆盖。游标绑定项目、本人/授权、查询、限量及当前固定版本目录摘要；新增版本使旧分页失效。目录不扫描GIS或返回服务器路径，固定报告/制品仍按后续version/content核验。本段为产品接入时补齐的服务目标，实际通过范围以执行记录为准，不把未完成端点写成已部署。

## 5. 场景保存合同

`/scenes/save`请求顶层固定为：

```ts
interface SaveSceneRequest {
  expectedSessionRevision: string;
  clientRequestId: string; // UUID
  sceneId: string;
  expectedSceneRevision: string;
  snapshot: EditableSceneSnapshot; // 下列白名单模式，非任意JSON路径补丁
  reviewedEngineering: EngineeringExpectation[];
  rootBindingChanges: RootBindingChange[]; // 只列根关联确实变化的实例
  spatialChange?: { kind: 'anchor' | 'model' | 'terrain'; receipt: string }; // 原样回传服务端预检回执
}
interface EngineeringExpectation {
  ref: EngineeringRef;
  expectedEntityRevision: string;
  installationContextId: string;
  expectedHierarchyRevision: string;
}
interface EditableSceneSnapshot {
  displayName: string;
  coordinateFrame: CoordinateFrame; // 仅接受本场景/地形预检产生且可复核的框架
  terrain: { terrainVersionId: string; expectedContentRevision: string } | null;
  instances: EditableInstance[];
  initialView: { eye: [number, number, number]; target: [number, number, number] };
  defaults: { background: 'plain' | 'sky'; lighting: 'neutral' | 'dusk'; terrainMaterial: 'solid' | 'grass' };
}
interface EditableInstance {
  sceneModelInstanceId: string; // UUID；新增时客户端生成，后端校验唯一及不可复用
  displayName: string;
  modelVersionId: string;
  placement: { position: LocalPosition | GeographicPosition; height: HeightStrategy; headingDeg: number };
  visible: boolean;
  positionLocked: boolean;
  rootBinding: { objectRef: EngineeringRef } | null;
  componentBindings: { objectRef: EngineeringRef; componentKeys: string[] }[];
}
type LocalPosition = { mode: 'local'; xM: number; zM: number };
type GeographicPosition = { mode: 'geographic'; longitude: number; latitude: number; transformId: string; frameRevision: string };
interface RootBindingChange {
  sceneModelInstanceId: string;
  from: EngineeringRef | null;
  to: EngineeringRef | null;
  clearOldComponentBindings: true;
  reviewedRemovedBindingsDigest: string; // check返回，服务端按旧头重新计算
}
type VerticalDatum = 'EGM2008' | 'EGM96' | 'WGS84_ELLIPSOIDAL' | 'UNKNOWN_RELATIVE';
type LocalFrame = { mode: 'local_plane'; frameRevision: string; origin: [0, 0, 0]; unit: 'm'; axes: 'X_EAST_Y_UP_Z_SOUTH' };
type CoordinateFrame = LocalFrame | {
  mode: 'projected_site'; frameRevision: string; horizontalCrs: string;
  verticalDatum: VerticalDatum; transformId: string;
  originEasting: number; originNorthing: number; originHeight: number; // 三项均为米
  convergenceRuleId: string; anchor: GeographicAnchor;
};
type HeightStrategy =
  | { mode: 'local_relative'; relativeHeightM: number }
  | { mode: 'terrain_ground'; terrainVersionId: string; terrainSha256: string;
      sampleLongitude: number; sampleLatitude: number; sampledHeightM: number;
      offsetM: number; verticalDatum: VerticalDatum; samplingRule: string }
  | { mode: 'absolute'; valueM: number; verticalDatum: VerticalDatum;
      sourceNote: string; verticalTransformId?: string };
```

框架中的`originHeight`是显示Y=0采用的场景垂直基准高度，不是默认为0的椭球高；地形及实例必须转换到同一声明基准才作Y差值。`terrain_ground`的采样字段是预检输出的回传条件，保存时服务器重采样核对，不能直接信任浏览器高度。`convergenceRuleId`固定投影网格方向到真北的规则版本；收敛角定义/正负号由Q-02以已知正北点和东西偏离点数值测试冻结，Q-01不写死未经验证的符号。


`CoordinateFrame`与`HeightStrategy`的精确互斥字段见§6：local位置必须配local_plane及local_relative高度；geographic位置必须配projected_site和同一转换/框架修订。`headingDeg`归一化到[0,360)，局部平面时相对−Z方向，地理框架时为真北朝向。初始相机采用当前框架的Three显示米制坐标，不能提交ECEF裸矩阵；向量有限且相机/目标不可重合，边界在Q-04实测后返回。

`EditableSceneSnapshot`只允许：场景名称、固定坐标框架/地形引用、实例数组、初始视角和枚举背景/光照默认值。实例只允许：稳定ID、名称、明确模型版本、位置/朝向、默认显隐/位置锁定、整体设备引用、内部构件键集合与工程引用。几何、物理父链、工程用途/已确认状态、运行测点/转速/偏航均不是可写字段。

整体保存覆盖本修订的全部布置与关联，首切不开放任意JSON Patch。前端显示实际增删改摘要；复制实例必须生成新ID并清空整设备、内部关联和未来测点。移动/旋转保持其稳定ID。浏览时临时显隐/相机只存在个人状态，除非明确“设为初始视角”或在布置模式编辑默认项，不混入共享快照。

保存顺序如下，任一步失败都保持旧头修订且不记录成功审计：

1. 验证载荷、预算、会话/当前写权限、幂等重放；检查`expectedSceneRevision`。
2. 校验所有资源版本当前可读、就绪及校准、每个位置在相应坐标/高程约束内；实例ID唯一，删除/复制和锁定变化合法。
3. 核验快照内所有工程引用：连接/项目正确、精确UID、当前可关联安装对象、设备上下文、完整祖先链；浏览器`reviewedEngineering`必须覆盖这些对象和上下文，服务器实查修订逐项相同，不能取最新版本替用户接受变化。
4. 校验两层绑定：整设备身份、内部引用在其自身或已记录子树，同构件唯一，同实例根变更时核对下述`rootBindingChanges`及旧内部绑定清空条件；设备上下文用途与假定状态由权威结果生成。禁止把模型父子关系写回物理链。
5. 本地事务内再次比较场景头、授权和所有使用的固定本地资源版本；提交前再检查本人会话/项目授权及权威对象/层级期望条件，写快照/使用引用/审计/幂等结果，推进场景头。

返回`{sceneId, sceneRevision, headRevision, savedAt, validation, sessionRevision}`。成功即供有权项目成员读取。`validation`保留演示/代理/假定关系等必要标识，不把它们升格为现场确认。工程API不可用时，可继续本地编辑，但有工程关联的保存不能以旧缓存冒充核验成功。

同一请求并发到达最多提交一次；两个不同请求同时保存同一头只有一个成功。网络断开结果未知时，先以相同请求ID/业务载荷重试；不要自动生成新请求ID重复保存。`409 SCENE_CHANGED`返回当前头及有权摘要，不代替客户端草稿；首切提供“保留本地编辑／重新载入后重做”，不实现自动合并或强制覆盖。只读用户不显示保存成功。

锁定实例仍可定位、看图纸和修改关联，只有位置/朝向/高度变更需要同次明确解除锁定；不得绕过锁定字段直接提交位移。删除锁定实例也先解除位置锁定并显示移除确认，不因行内隐藏跳过操作。

**根关联改变的可判条件：** 服务端按`expectedSceneRevision`读取旧根及旧内部关联；每个根变化的实例必须恰有一条`rootBindingChanges`，`from/to`分别等于旧根/新快照根，且`clearOldComponentBindings=true`。`reviewedRemovedBindingsDigest`须等于服务端对该旧实例全部内部关联（构件键排序、工程引用、旧修订）规范化计算的SHA256，UI应先展示check返回的移除清单再确认。首切根改变这一保存要求新快照的该实例`componentBindings=[]`，新根下内部关联之后显式重新选择；不靠最终快照猜“用户同意清空”，也不允许顺带保留旧柜体。新增实例首次关联同样声明`from=null`，旧集合为空。摘要只是防止误接受变化，不授予权限；缺条目/重复条目/多余无变化条目均拒绝。

## 6. 坐标、地形与首次地理锚定

### 首切坐标框架

首切遵循V2的局部投影米制路径，不把它标为严格ENU。交换WGS84经纬度顺序明确为`[longitude, latitude]`；高德GCJ-02等不能当作WGS84输入。场景含以下二选一框架：

- `local_plane`：`frameRevision, origin=[0,0,0], unit=m, axes=X_EAST_Y_UP_Z_SOUTH`，这里“东/南”仅为平面轴约定，尚无真实地理方向。位置只有`x, z, relativeHeight`，显示“未设置位置”，禁止展示虚假经纬度。
- `projected_site`：`frameRevision, horizontalCrs, verticalDatum, transformId, originEasting, originNorthing, originHeight, convergenceRuleId, anchor`；未知相对基准另含`relativeReferenceId`。`anchor`保存本节完整锚定输入，服务据此与固定地形重建框架；资源和场景原点可以不同。首切目标投影取覆盖中心所在WGS84 UTM分区，记录完整EPSG/转换版本；跨UTM分区、极区、跨日界线或超出经Q-02验证的区域尺度先拒绝并要求裁切，不静默套用另一投影。有效区域/长度范围由Q-02验证；`horizontalCrs`不能空着默认为Web Mercator。Three显示`X=E−E0, Z=−(N−N0), Y=H−H0`，仅将投影轴映射到显示轴。

地理放置的业务真值保存WGS84经纬度及明确高程策略；`transformId + frameRevision`锁定双向投影处理。投影位置为同一记录的派生值，服务端重算核对，不允许浏览器同时提交互相矛盾的经纬度和X/Z。拖拽命中点通过同一转换反算，再由该记录驱动定位；近景相机局部数值不回写工程坐标。

### 高度字段

| 界面名称／`height.mode` | 持久字段与计算 | 不允许的行为 |
|---|---|---|
| 局部高度／`local_relative` | 无地理参考时的`relativeHeightM`，相对于场景平面；局部编辑可继续 | 不标成海拔，不伪造垂直基准 |
| 贴地／`terrain_ground` | 固定`terrainVersionId, terrainSha256, sampleLongitude, sampleLatitude, sampledHeightM, offsetM, verticalDatum, samplingRule`；`H=sampledHeightM+offsetM` | NoData/覆盖外拒绝；源4邻双线性仅生成派生网格顶点，实际贴地按固定显示网格同对角三角面采样，缺测单元不补0；视角/LOD不重采样；隐藏地形不停止采样约束 |
| 指定高程／`absolute` | `valueM, verticalDatum, sourceNote`；必须能与场景高度基准一致，或有已核验明确转换记录 | 不把未知基准强行当同一基准，不把EGM2008正高当WGS84椭球高 |

Q-02细化采样：`sourceVertexSamplingRule=pixel-centres-four-valid-clamped-centres-v1`只用于派生网格顶点，源值在像元中心，四邻均有效，采样域不外推半像元外缘。当前贴地使用`samplingRule=mesh-triangle-tr-bl-cell-mask-v2`，与固定显示网格相同的右上—左下对角线及三角面插值；四顶点及保守源单元覆盖掩码均须有效，降采样不能跨过中间NoData洞生成面或允许贴地。保存该网格版本/指纹和规则，不能在稀疏显示网格上继续取更高分辨率源双线性高度而宣称接触误差≤2cm。源面到降采样网格的近似误差单独列为未测/实测值，不与浮点显示接触误差混合。

`absolute`的`verticalDatum=WGS84_ELLIPSOIDAL`明确指椭球高h；其余如EGM2008为正高H。源高程单位非米必须记录换算。首次仅有未知基准的地形可作相对起伏/贴地显示，但框架标`verticalDatum=UNKNOWN_RELATIVE`、禁止绝对高程与ECEF/ENU/工程量测；不能用`wgs84`一个词同时表示水平坐标与高程。

以后接入地球/ECEF/ENU时，以已确认的格网和版本执行`h=H+N`，不隐式抓取网络格网。严格ENU与Three局部坐标关系为`(E,N,U)=(X,−Z,Y)`，但只能对已经建立ENU框架的坐标使用；不能把当前投影米制坐标直接套该公式充作严格ENU。若缺椭球高/大地水准面转换，则该地球转换路径不可用，区域场景仍可用。

安装朝向为真北0°顺时针，投影处理显式包含子午线收敛角及正面校准；保存同一`transformId`供重算。整模型安装朝向独立于运行偏航、风叶转速。首切不开放每实例非均匀缩放或自动随坡倾斜。

### 首次地理锚定与换地形

`check`和`replacement-check`请求按下列互斥类型校验，不能把`anchor`塞进普通validate或把模型/地形版本混填：

```ts
interface GeographicAnchor {
  localAnchor: [number, number]; // 旧局部平面的[xM,zM]，局部高度基准为0
  geographicAnchor: [number, number]; // [longitude,latitude]
  trueNorthHeadingDeg: number;
  anchorHeight: { mode: 'terrain_ground'; terrainVersionId: string; offsetM: number }
    | { mode: 'absolute'; valueM: number; verticalDatum: VerticalDatum; sourceNote: string };
  heightStrategy: 'keep_relative_to_anchor' | 'resample_each_ground';
}
interface CheckBase {
  expectedSessionRevision: string;
  sceneId: string;
  expectedSceneRevision: string;
  snapshot: EditableSceneSnapshot;
}
type CheckSceneRequest = CheckBase & (
  | { kind: 'validate' }
  | { kind: 'anchor'; snapshot: EditableSceneSnapshot & { coordinateFrame: LocalFrame };
      candidateTerrainVersionId: string; anchor: GeographicAnchor }
);
type ReplacementCheckRequest = CheckBase & (
  | { kind: 'model'; sceneModelInstanceId: string; candidateModelVersionId: string }
  | { kind: 'terrain'; candidateTerrainVersionId: string;
      strategy: 'keep_height' | 'resample_ground' }
);
```

预检返回`{baseSceneRevision, proposedSnapshot, impact, issues, reviewedEngineering, rootBindingChanges, sessionRevision}`；`impact`有受影响实例、旧/新资源与高度、将清空的关联摘要。它不占写锁、不提交，也不能绕过最终保存全部检查。anchor成功返回的`proposedSnapshot.coordinateFrame`含可复核的锚点与转换来源；`proposedSnapshot`内所有实例均已转为地理位置。`keep_relative_to_anchor`将旧局部高度加到锚点高度，来源注明“基于锚点的相对布局”，不当作实测基础标高；`resample_each_ground`对各新位置采样、原局部高度成为offsetM。任何实例位置无效都返回问题，不部分提交。

**V1.1首次锚定回执细化：** 当前未关联设备的切片返回`{sceneId,baseSceneRevision,proposedSnapshot,validation,heightProvenance,resourceRefs,spatialChange,sessionRevision}`；空间影响清单位于`validation.impact`，尚无工程审阅结果。anchor预检可包含尚未保存的局部编辑，服务先按旧头核验锁定、实例身份和资源，再变换全部布局及初始相机。返回`spatialChange={kind:'anchor',receipt}`，确认时连同`proposedSnapshot`原样回传保存。回执签名绑定项目/本人/授权修订、场景旧头、旧快照、预检结果及固定资源身份摘要；不保存共享草稿或保留锁，也不授予写权限。保存重查当前权限、旧头、固定资源及实际GIS结果；回执失效返回`409 SPATIAL_PRECHECK_INVALID`并要求重新预检。普通保存无回执仍不可改变框架或采用另一地形，不能把坐标编码变化误当锁定对象的任意移动。

只读`check(kind=validate)`会依据新位置重算贴地采样字段并返回规范快照；实际save严格核对固定采样，不接收浏览器自报高度。重采样开关只在服务内部设置，客户端不能往snapshot或公共请求中夹带`resampleGround`。已知基准的指定高程可在地形覆盖外；贴地与未知相对基准始终受有效覆盖约束。

已有局部实例首次添加有地理参考地形时，不能默认把整个布局落在地形中心。`/scenes/check`请求附显式锚点候选：`localAnchor[x,z]、geographicAnchor[longitude,latitude]、trueNorthHeadingDeg、anchorHeight、heightStrategy`。返回整体刚体变换、转换后的所有实例/高度及覆盖问题；用户确认预览后用同一场景修订一次保存新的框架与全部放置。锚点未确认时继续`local_plane`，经纬度编辑不可用；已保存框架不得被一次拖动隐式更改。

换地形通过`/scenes/replacement-check`返回每个实例旧/新采样值和差值、NoData/覆盖外。策略固定为`keep_height`或`resample_ground`；指定高程默认保持，已改变基准必须有显式可用转换。失败不替换地形；预览取消恢复模型版本/位置/关联/相机；确认保存仍检查期望修订、地形版本和权限，预检不是免检凭证。

**V1.3换版回执细化（已实现未关联布局范围，见[换版实现](../plans/场景资源换版实现.md)）：** 首切换版只对已保存布局进行，`snapshot`必须与期望头在精确数值语义上相同；有其他草稿改动返回`409 SCENE_DRAFT_REQUIRES_SAVE`，页面保留修改并提示先保存。首次anchor携带局部草稿的既有能力保持。模型候选必须为当前项目可布置的已校准固定资源，锁定实例先解锁；旧legacy模型不伪造基点/校准事实，先走明确的资源接入与迁移。模型与地形预检返回现`SceneCheck`壳，影响清单放在`validation.impact`，`resourceRefs`为最终候选引用；`spatialChange={kind:'model'|'terrain',receipt}`只含类型和签名，不让客户端附免检参数。

换版签名绑定本人/项目/当前授权、旧头/旧快照、精确数值规范的候选、旧新固定资源摘要和唯一操作参数；保存从签名参数重算完整结果，核对后一次提交，仍在GIS外持写锁前后重查。`keep_height`的旧估算来源由服务生成、随修订保存；不接客户端自报来源覆盖旧事实。普通保存不能直接换模型版本、地形或框架。已接受请求的原UUID重放优先于旧头/回执核验，响应丢失不会重复推进；确定拒绝失效预检后允许取消并重新预览。

**V1.4数值及来源补充：** 新地形换版生成的ground anchor允许服务派生`offsetCompensationM`，仅补偿旧相对高度原点在大数相减时丢失的浮点低位，绝对值不超过sample/offset的ULP上界；有该字段才使用三项精确求和。首次anchor公共输入明确拒绝该字段，旧无补偿框架的算术及摘要保持兼容，不是工程调高或精度提升。新换版锚点规范精确整数数值后再计算框架摘要，禁止容差合并不同小数。

高度依据采用有界`heightBasis={kind,reviewedSceneRevision,height,terrainRef}`；`previousHeightProvenance={kind:'height_basis_summary',previousSceneRevision,basis}`只保留上一修订标识和原依据摘要，不递归复制完整记录。相同实例高度未改变的普通/模型保存和keep-height继续保留原估算依据，重采样生成新地形依据；后续普通保存不能把旧估算洗成实测或无来源的指定高程。

当前工程关联仍明确不支持，不能把空关联布局记作工程迁移成功。首切模型影响包括旧新尺寸/基点/朝向/构件数及目标实例；地形影响包括每实例旧新采样/最终高度/差值，指定高程可在覆盖外保持，缺失采样值为null并附问题码，不能为了计算差值强行贴地。需要新地面采样的路径任一点无效即拒绝采用；锁定实例重采样造成实际高度变化先拒绝并要求解锁。预览取消恢复原快照和当前镜头，不写修订或绑定。此段冻结实际实现规则，实际通过范围另见执行记录。

换地形后的每个高度策略必须与新快照一致：

- `resample_ground`：原贴地实例改为新`terrainVersionId/Sha256`、新采样值并保持原offsetM；覆盖外/缺测拒绝整次采用。原指定高程默认不动，不强制贴地。
- `keep_height`且旧基准已知：先求旧`sampledHeightM+offsetM`，在同基准或已核验的显式垂直转换后，转成`absolute`固定该高程；sourceNote与服务端`heightProvenance`保留“来自旧地形估算”、旧版本/采样/偏移，不冒充测量。不得让新场景terrain指向V2，而实例仍叫terrain_ground却引用V1。
- `keep_height`且旧为`UNKNOWN_RELATIVE`：只有新旧地形具有同一明确记录的`relativeReferenceId`、场景相对高度原点一致且新落点有效时，才用新地形采样，反算`newOffsetM=oldFixedHeightM−newSampledHeightM`，继续标相对贴地；不转绝对高程。相对参考不相同/无法核实、新落点缺测或覆盖外时拒绝该策略，保留旧地形；可另走显式重新锚定预览，不能把“都未知”当基准相同。
- 原`absolute`值及其来源保留；若新框架基准不兼容且无已核验转换，整次采用拒绝。前端重开必须显示实际保存后的高度模式，不能继续显示已经取消的“贴地”。

下列分“已有限额”和“Q-02/03待实测候选”；技术实现必须在响应`limits`中返回实际生效值，不能把候选数字写成已通过性能承诺。

处理状态为`queued → processing → ready / failed / cancelled`，每次变更推进`jobRevision`。`ready`必须有固定输出版本/报告；校验或权限失败不生成就绪版本。文件上传成功、任务排队、原件技术可用、坐标可用、现场精度已核实是不同状态。任务可返回当前阶段和实际已完成计数，不编造持续增长进度。

关闭上传页不承诺取消已接收任务；用户显式取消按任务竞态处理。重启后未完成任务标为可重试失败，不将半成品当ready。会话/写权限在处理开始及输出登记前复核，撤权后不登记成功；后续以新会话重试仍需当前授权。任务列表不返回凭据、文件路径或处理命令。

误差报告分别列数值转换误差、栅格采样误差、源数据精度和现场配准残差；未取得独立控制点时现场残差为未知，不以本机Demo视觉相近作为验证。不能用放大地形起伏修正设备位置。

## 8. 两层关联、定位与换版

根关联选择同项目可读的安装对象，可为风机、变压器或不同层级的设备；不要求`objectKind=cabinet`，不要求三柜完整。模型版本角色仅是提示；UID、实际父链和每实例测点均不得从另一实例复制。

内部构件关联的对象必须是根设备自身或其完整已记录后代；每条声明同时核对对象和所属上下文修订。改变根设备的保存请求必须清空旧内部关联，再核验新关联；不能保留一部分旧柜体混在新机组。允许完整子链内多个构件表示一个对象，高亮合并边界。

定位请求必须固定`sceneRevision`，所选分析对象使用完整工程引用。服务先检查当前场景的直接表示，再逐级检查完整物理祖先链；顺序不受上次看的实例影响。没有直接表示时才使用最近有效祖先，同层有多个独立实例则返回选择清单；发现失效近层关联、链不完整或身份变化时停止，不能跳过它去更远的设备。

```ts
interface SceneLocationResult {
  sceneId: string;
  sceneRevision: string;
  selectedObject: EngineeringObjectSummary; // 始终是用户选择的对象
  status: 'located' | 'choose_representation' | 'unavailable';
  mode: 'direct' | 'ancestor' | null;
  hostObject: EngineeringObjectSummary | null;
  sceneModelInstanceId: string | null;
  componentKeys: string[];
  modelVersionId: string | null;
  geometryQuality: 'source_candidate' | 'proxy_schematic' | null;
  relationshipStatus: 'confirmed' | 'assumed' | null;
  worldBounds: [number[], number[]] | null;
  choices: RepresentationSummary[];
  reason: string | null;
  contextEpoch: string;
}
```

`worldBounds`必须应用完整模型校准、实例变换和场景框架，不能直接使用资源局部包围盒。根设备整模型定位返回全模型边界；内部构件返回集合边界。隐藏的可读实例仍参与定位，前端临时显示并可恢复个人显隐；无权对象不参与搜索。默认只定位当前场景，其他有权场景列为可选入口，不自动离开。`representationChoice`精确为`{sceneModelInstanceId, modelVersionId}`，不接受裸实例、null或构件键。只有用户明确选择，或从该实例内部的设备树发起时携带，且仍需根子树验证；内部视图切到项目对象列表后重新进行全场搜索，不能沿用上次实例。

子对象图纸解析使用`selectedObject`而非`hostObject`。当前/型号来源和无图纸空态沿用已有证据契约，不因祖先有图就替换所选对象自身证据。图纸读取不以拥有有效几何或完整空间父链为前置；对象自身来源与权限合法时，即使定位失败也可独立查看。退出、撤权和对象切换取消迟到内容，保留当前合法相机或清理失效高亮；镜头从当前位置平滑切换，不先复原整机。

更换模型版本先展示尺寸/基点/关联影响，不自动按同名或同`componentKey`迁移。稳定源身份相同且唯一时仅产生候选；用户审阅候选仍须当前工程修订核验。新快照未完成关联的对象停止直接定位，旧修订和其他实例保持旧版本。预览取消无任何持久写入；最终变更通过普通场景保存一次提交。正式工程用途的迁移确认在Q-11，本首切允许明确演示/待核实场景继续。

### 待核关联必须保留定位阻断

`/scenes/open`和预检返回服务器生成的下列问题；它们不属于EditableSceneSnapshot白名单，客户端省略/清空问题字段不能消除阻断。模型换版提交时从旧头派生并随新修订持久化第一类；工程变化则按当前权威读取生成第二类，不改写旧快照历史：

```ts
type BindingIssue = {
  sceneModelInstanceId: string;
  objectRef: EngineeringRef;
  installationContextId: string;
  blocking: true;
} & (
  | { kind: 'model_version_changed'; previousModelVersionId: string;
      previousComponentKeys: string[]; sourceSceneRevision: string;
      code: 'COMPONENT_MISSING' | 'MIGRATION_REQUIRED' | 'SOURCE_ID_AMBIGUOUS' }
  | { kind: 'engineering_changed'; expectedEntityRevision: string;
      expectedHierarchyRevision: string;
      code: 'IDENTITY_CHANGED' | 'ENTITY_CHANGED' | 'PARENT_CHAIN_CHANGED' }
);
```

保存新模型版本时，旧有效关联没有经当前版本构件/当前工程修订显式重新核验的，必须生成相应`model_version_changed`问题；不能通过把componentBindings删空让它看起来从未关联。后续普通保存继承未解决问题；新快照中增加经过当前权威核验、用户明确选择的同对象合法构件集合，才解决该对象问题。显式更换根设备并完成§5的清空确认时，才清除该实例旧根下的问题，历史与审计保留。首切不提供“忽略失效后继续祖先兜底”的按钮。

有效绑定与问题可在同一实例并存。例如V2仍能表示CT，但CN缺失，CT可定位；CN或其无几何子对象沿近父到CN时，先发现CN的blocking问题，立即返回`BINDING_NEEDS_REVIEW`，不能继续定位机组根。若同一最近对象在其他独立实例还有有效表示但本场景也有未解决问题，先返回需核实/明确选择结果，不能随机避开失效表示；用户显式选择另一个有权有效表示后仍核实其子树和修订。

问题引用/历史仅向当前有权用户返回。工程对象无权读取时不得泄露旧名称/UID或使用去向；模型文件的合法读取仍按资源项目权限独立判断。换版预览取消不生成问题、不推进修订；旧保存修订仍保留原模型和当时关联，打开旧修订也按当前授权/工程变化核验，不能借历史跳过撤权。


## 9. 状态与错误映射

除`located/choose_representation/unavailable`等正常业务结果外，错误JSON保留既有`code`；可追加仅限当前有权范围的`details`，不返回堆栈、路径、SQL或原始上游错误。

| HTTP／代码 | 页面状态与动作 |
|---|---|
| 401 `SESSION_EXPIRED` | 退出态、清理私有工程/图纸/高亮；重新登录，不保留他人可读的私有草稿缓存 |
| 403 `NOT_FOUND_OR_FORBIDDEN` / `SCENE_WRITE_FORBIDDEN` | 清理无权读取范围；仅失去写权限时切只读，当前合法读取仍可用；不显示保存成功 |
| 404 `NOT_FOUND_OR_FORBIDDEN` | 不存在/越权资源统一可读空态，不暴露其他项目名称 |
| 409 `SESSION_CHANGED` / `ACCESS_CHANGED` | 停止当前提交/迟到内容；重读当前会话与权限，不能自动替换用户工程选择 |
| 409 `SCENE_CHANGED` | 有更新，保留本地草稿；显示当前头，显式重载后重做，不自动覆盖 |
| 409 `ENGINEERING_CHANGED` / `IDENTITY_CHANGED` | 关联待核，停止相应定位；重读对象/路径并由用户重新审阅，不能改UID凑成功 |
| 409 `RESOURCE_CHANGED` / `SNAPSHOT_EXPIRED` | 保留草稿或筛选，重新选择固定版本/从首屏重读；不默默用最新资源 |
| 409 `REQUEST_CONFLICT` / `RESOURCE_IN_USE` | 修正请求ID复用或查看引用位置；不得删除历史仍引用的文件 |
| 409 `SCENE_DRAFT_REQUIRES_SAVE` | 保留当前修改，保存后再更换资源；不代用户提交草稿 |
| 409 `MODEL_ALREADY_IMPORTED` | 重新读取目录并选择对应资源，不重复复制旧模型 |
| 409 `MODEL_CALIBRATION_REQUIRED` / `SPATIAL_PRECHECK_INVALID` / `TERRAIN_SAMPLE_CHANGED` | 校准资源或重新预检位置；不接受过期锚定结果或浏览器自报地面高度 |
| 413 `SCENE_LIMIT_EXCEEDED` / `TERRAIN_LIMIT_EXCEEDED` | 保留已填元信息，显示实际超出项，不创建半成品成功记录 |
| 422 `INVALID_REQUEST` / `INVALID_TERRAIN` / `CRS_REQUIRED` / `VERTICAL_DATUM_CONFLICT` | 标出具体字段/报告，保留其他输入；未知CRS不得默认为WGS84 |
| 422 `OUTSIDE_COVERAGE` / `NO_DATA` | 保持上次有效位置，可换有效落点或查看资源；禁止无效贴地 |
| 422 `MODEL_SOURCE_RIGHTS_REQUIRED` | 原上传缺少可复用的使用声明记录；保留旧查看入口，不自动补许可事实 |
| 429 `TERRAIN_BUSY` / `MODEL_BUSY` / `SCENE_GEOMETRY_BUSY` | 明确队列满或处理忙，等待后重试，不重复创建任务；当前未承诺Retry-After响应头 |
| 502/503/504 `SOURCE_UNAVAILABLE` / `PROCESSING_UNAVAILABLE` | 已保存场景保持原修订，保留本地编辑；不把源系统错误解释成没有设备 |

位置不可用等正常业务结果只返回必要原因，例如`NO_REPRESENTATION / AMBIGUOUS_REPRESENTATION / INCOMPLETE_PHYSICAL_CHAIN / BINDING_NEEDS_REVIEW`。不能把这些结果计为成功定位或通过现场验收。
