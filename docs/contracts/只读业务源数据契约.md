# 只读业务源数据契约（Q-16 准备稿）

2026-10-25。承接[有效需求 RQ-13/14/21](../requirements/有效需求基线.md)和[实时接入设计 §6](../design/技术栈与实时接入设计.md#6-外部监测系统实时接入)。这是报警、环境测点与工单的逻辑合同及反例准备，尚非已实现API、连接器或真实协议冻结。用户已明确“暂无真实源”；I-04的实际源系统、协议与字段样本待后续，不重复索要或推定现场协议，不据此声明真实接入通过。

## 1. 连接身份和工程映射

连接配置由服务端绑定 sourceConnectionId、项目范围、sourceKind（measured/simulated）、允许的数据类型及只读能力；源payload不能决定租户、项目、连接身份、工程UID或权限。模拟与实测使用不同连接ID和数据分区，quality=good也不改变simulated属性。一个源可提供报警和环境数据，工单可来自独立源；实际选哪一种协议由已有出口能力决定。

规范外部键为“服务端连接范围＋sourceConnectionId＋externalAssetId＋pointId/事件或工单ID”，完整保留源标识，不截短或从名称、机组编号、RDS片段猜测工程UID。映射配置独立记录其修订、外部键、目标工程引用、核验依据及状态；目标为现有 ontobaseConnectionId/projectCode/entityUid，保存与读取仍通过OntoBase API核权和核身份。

映射状态为 verified/unmapped/ambiguous/invalidated。只有当前有权、当前核实的verified映射可附工程对象；未映射记录保留源对象和原因，不能借用柜体或其他机位UID。可先作为标注“无工程资料绑定”的监测对象展示。对象合并、范围/权限改变使映射待复核，不能静默canonical重定向；物理祖先只用于已批准的空间代理与可见报警汇总。

## 2. 时间、质量和顺序

| 字段/规则 | 必须保留及处理 |
|---|---|
| sourceTimestamp / ingestedAt | 前者来自源测量或事件，后者由接入服务捕获；均含时区、存储为UTC，界面按用户时区展示。两者不互相填补；缺源时间明确unknown |
| sourceEpoch / sequence | 保留源实际启动/会话标识与原序号，并声明序号适用于连接、事件还是单点。无可靠epoch时不把序号变小当重启，先重建快照/水位 |
| quality / qualityRaw | 规范good/bad/uncertain/unknown并保留原质量码及映射规则版本；未知码保持unknown，不转成正常 |
| 时钟与陈旧阈值 | 源/点配置明确允许时钟偏差、采样周期与staleAfter；当前设计的max(3×周期,10s)仅为试点候选，真实阈值随源冻结 |
| 未来/非法时间 | 标time_invalid，保存待核验记录，不推进正常最新值或水位；后续合法消息仍可接受 |
| 迟到、乱序和缺口 | 同一可靠epoch按已确认的源顺序规则处理，旧消息不覆盖最新值；缺号、游标过期或无法比较顺序均显式gap/needs_snapshot，不假定完整 |
| 数值、单位 | 保留原值/原单位/类型；拒绝NaN/Infinity等非JSON有限值。换算需固定规则版本与可核实单位，未知单位不推算。越界与坏质量分开记录 |

最新值展示还需考虑当前授权、映射、连接状态和陈旧时间。断连可保留仍有权的最后值并标stale；未知/坏值/过期/断连分别展示，不能沿用正常色掩盖缺口。撤权清除不可再访问的数据。实时姿态仅使用质量good、时间有效、未过期且映射有效的数据。

## 3. 三类业务记录

| 类型 | 固定身份/最小业务字段 | 幂等与只读边界 |
|---|---|---|
| 报警 | sourceEventId、源版本/序号、externalAssetId、原始严重性及其映射版本、active/cleared/unknown、源确认状态、发生/更新/恢复时间 | 优先“连接＋源事件ID＋可靠版本/epoch序号”去重。同键同内容重放；同键内容不同保留冲突，不静默覆盖。版本字符串不能未经源规则就字典序比较；无可靠ID/顺序只作弱去重并明确限制。ONTOVis已查看不等于源SCADA确认 |
| 环境测点 | externalAssetId、pointId、value/valueType、原单位、源/接收时间、qualityRaw及规范质量、epoch/sequence、映射修订 | 同点同epoch旧数据不覆盖新值；未来时间、坏质量及未映射不会驱动实时姿态。相同序号不同值为源冲突；不从实时缓存补造历史曲线 |
| 工单 | sourceWorkOrderId、源修订/更新时间、原状态/优先级、关联的原始外部对象、主题及源详情引用 | 首期仅拉取、分页、核对版本及展示。没有创建、派发、确认、取消或回写；AI草稿保留在自身会话，不产生外部工单事实。源详情链接受允许域和当前权限控制，不携长期token |

严重性unknown、质量unknown、已恢复、已查看、源已确认是不同维度。子设备报警仍属于实际子设备；祖先汇总仅计算当前可见范围内去重事件数/最大严重性，不能据此确认柜体整体故障或泄露无权子对象数量。

源快照与增量用可核实水位衔接；没有源历史能力时明确历史不可用。Q-17的持久outbox、消费确认、SSE/断线补数和背压在Q-13运行基础及本合同接入后实现；本准备稿不宣称端到端零丢数或exactly-once。

## 4. 固定反例清单

以下是设计验收输入与预期，尚未运行连接器或持久化服务；实现时须在同一合同下自动化验证，并另做真实源联调。

| # | 输入/变化 | 应有结果 |
|---|---|---|
| 01 | 同连接同事件ID/版本且内容相同重放 | 只计一次，保留源时间与原严重性 |
| 02 | 同幂等键但内容不同 | 源冲突，保留证据，不静默替换 |
| 03 | 不同连接使用相同外部ID | 独立记录，不能跨连接去重 |
| 04 | 模拟源与实测源标识相同 | 分区隔离，模拟标志持续可见 |
| 05 | payload自报另一个项目/工程UID | 不用作授权或工程映射，越界字段拒绝/隔离 |
| 06 | 同名设备、别名或截短RDS匹配到多个UID | ambiguous，不选择第一个 |
| 07 | 无工程映射 | 保留外部对象、无工程资料绑定 |
| 08 | 映射指向合并/失效对象或访问被撤销 | invalidated/待复核，旧工程详情不可继续读取 |
| 09 | 同epoch收到较旧序号/源时间 | 不覆盖最新值，记录迟到/乱序 |
| 10 | 序号归零但无可靠epoch | needs_snapshot，不猜重启或清空水位 |
| 11 | 有可靠新epoch且完成恢复快照 | 独立水位，之后按该epoch规则接收 |
| 12 | 一条远未来时间后跟合法新消息 | 前者time_invalid且不推进水位，后者可处理 |
| 13 | 缺时区/无效时间或源时间未知 | 明确拒绝或unknown，不拿接收时间冒充测量 |
| 14 | 坏/未知质量、越界、未知单位 | 分别标明原因，停止正常实时驱动 |
| 15 | NaN/Infinity、类型与值不符 | 参数拒绝，不传播到姿态/聚合 |
| 16 | 断连超过staleAfter | 最后值标stale，不继续显示正常 |
| 17 | 快照期间新增报警或增量有缺号 | 水位衔接或显式gap/补快照，不能无声丢失 |
| 18 | 子设备报警，祖先可见范围含无权对象 | 保留子设备身份，仅汇总有权去重事件 |
| 19 | 本地已查看/AI生成工单草稿 | 不改变源确认状态，不派发外部工单 |
| 20 | 源无历史/游标已过期 | 显式历史缺口或重建快照，不回退伪造历史 |
