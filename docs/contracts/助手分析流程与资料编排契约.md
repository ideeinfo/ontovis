# 助手分析流程与资料编排契约

2026-11-04设计更新：[工程助手统一能力设计](../design/工程助手统一能力设计.md)拟将检索与画布成员解耦，并接入完整画布/业务操作，见[新逻辑合同](工程助手检索与操作契约.md)。新设计尚未生产接入；本文以下仍准确记录当前线上“所选固定资料摘要问答”的行为，不应混用两套范围。

2026-11-03。承接既有按能力设置、固定资料引用、多轮会话与人工采纳契约。本轮改造针对资料用途不透明、模型失败混报和侧栏操作过多；不增加现场控制、未选资料外发或自主多 Agent。

## 一轮分析

1. **确定问题与范围**：用户围绕已保存画布提问；默认选择最多六份不同类型资料，可调整至项目/能力共同上限（最高八份）。型号、安装身份、版本和权限由原后端校验。无需打开摘要才能发送。
2. **读取资料**：按已选固定引用读取，最多两并行；有余量时依问题中的故障码检索固定手册。返回的摘录、质量与缺口共同保存。读取成功不等于资料内容足以回答。
3. **组织一次模型请求**：固定规则和能力目标置于系统指令，用户问题、逐项 E 引用/类型/摘要以及仍适用的最近对话置于结构化数据。资料文字是证据，不能覆盖系统规则。模型先回答问题，再比较支持与冲突，指出无法闭合的链段或依据，最后给出需人工核对的下一步。
4. **校验并显示**：验证返回格式、非空结果和 E 引用；保留四个结果区：已知情况、待验证假设、资料缺口、建议核查。引用可定位原固定资料。结构校验只保证格式与引用存在，不证明论断正确。
5. **继续或采纳**：底部继续提问；加入笔记和整理工单放在按需展开的操作中，仍由用户明确选择。驾驶舱查询不提供写入操作。

## 资料怎样进入提示词

| 类型 | 提供给模型的内容 | 用途及不能推断的内容 |
|---|---|---|
| 报警 | 故障码、状态、事件时间、确定性计算的持续时间、模拟标记 | 描述发生了什么；不能当作现场确诊，也不能把手册触发延时当作事件时长 |
| 趋势 | 单位、固定时间窗、样本数、坏质量数、极值和末值 | 对比测量表现；统计量不足以证明时序相关性，坏质量不能补造 |
| 工程对象/图谱 | 精确对象的有限关联、关系类别和复核状态 | 描述已读链段，候选接线不能升级为已确认连接；缺少链段须指出 |
| 文档/手册 | 固定发布知识节点、有限关联、证据页与实际摘录 | 解释阈值与规则；只有元数据时不能宣称读过全文，缺少原因/步骤时不能补造 |
| 图纸 | 当前仅固定版本和页码等元数据 | 供用户回看定位；未读图面和全量端口，不能推导完整接线链路 |
| 照片 | 定位区域、用途、适用范围等元数据 | 未发送像素，不能判断外观或现场状况 |
| 模型 | 模型报告、绑定和精度摘要 | 提供空间上下文，示意几何不是内部精确位置或现场证据 |
| 工单 | 固定版人工记录、假设/步骤/结果及省略范围 | 区分已登记与待登记；未登记不能推断现场未执行 |

最近对话只是上下文，不能作为新证据；取消选择的资料不会通过旧轮次再次发送。没有可读资料则不调用模型；部分缺失可以回答其余资料的范围，缺口必须显示。

## 交互约定

- 主视图只保留对话工具栏、资料范围入口、逐轮问答和底部输入。模型、对话历史、摘要和图谱按需展开；资料默认收起。
- 空对话说明四类回答预期，并给出可编辑的问题起点。选择图纸/照片时在资料范围中明确“仅元数据”，不把“已选”表现成“已理解原文”。
- 进行中的读取/分析/校验只显示后端实际阶段，不显示虚构百分比或模型隐含思维过程。成功轮次显示已核对引用和资料数，详细读取过程按需查看。
- 失败区显示准确错误类别与下一步。模型拒绝、上游限流/拒绝、连接或超时、返回截断、格式错误、引用无效分别处理；历史通用错误只说明未保留具体原因。
- “修改后重试”只把原问题放回输入框，不自动发送或更换服务；已有选择保持。提交结果未知时仍只能先检查原运行，不能重复调用。
- 底部输入固定在助手面板内，对话区域滚动；后台与驾驶舱沿用相同排版及主题，驾驶舱继续只查询。

## 单流程与并行边界

当前采用一个确定性编排流程、最多两路资料读取和一次模型整理。不以资料类型划分独立自治 Agent，也不让用户选择 OntoBase/ONTOVis。工程权威读取由 OntoBase 提供，Vis 控制画布上下文和交互，模型连接继续沿用 OntoBase。

多 Agent 是后续选项：只有独立任务（例如完整电气链路核验与真实时序诊断）具备稳定工具、评估样本，并证明确有收益，才考虑并行专业分析、统一证据汇总和争议呈现。本轮不实现。

OpenAI 的 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)区分结构约束、拒绝和截断；本轮保留服务端校验，不能将结构符合视为工程真实性保证。

验收应覆盖混合资料、仅元数据、部分缺失、空返回/错误JSON/拒绝/截断/无效引用、取消与不确定提交、失败回填、深浅主题、窄屏和长对话。实际模型验证只证明该次运行及固定来源下的结果，不代表真实现场 RCA 完成。
