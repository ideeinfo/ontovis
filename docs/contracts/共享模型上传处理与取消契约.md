# 共享模型上传处理与取消

2026-11-16，Q-09。覆盖模型中心和场景资源中上传新模型或更新已有模型文件。

## 接口

- 共享模型目录返回 `capabilities.modelUploadJobVersion=1` 时，前端在现有 GLB 上传元数据中发送 `processingJobVersion=1`。仍使用 `POST /api/workbench/resources/model/upload`、单文件 20 MiB 及既有文件和模型库限制。未带标记的客户端沿用原同步上传。
- 接收文件后返回任务 ID、修订和状态，ID 沿用本次上传的 `clientRequestId`。内容或元数据改变且复用同一 ID 时返回 `REQUEST_CONFLICT`。同一提交的确切内容可以回读终态，也可使用原 ID 检查丢失的回执。
- `POST /api/workbench/resources/model/upload-job` 输入 `jobId`。本人有效会话可读取自己的任务。成功状态携带同一固定模型版本及摘要。任务内容不暴露本机路径、原始文件或其他人员的提交。
- `POST /api/workbench/resources/model/upload-job/cancel` 输入 `jobId` 和 `expectedJobRevision`，仅任务所属的当前模型维护者可执行。队列转入处理态产生修订冲突时先回读，再按用户本次取消意图提交。已有终态可重复回读。

## 处理与保存

共享模型库增加一张任务状态表，复用原单个模型处理名额和 GLB 隔离校验预算。接受、处理、完成、失败和取消均有明确的任务状态，处理期间显示实际阶段。取消可终止并回收校验子进程。文件登记、固定版本、审计、幂等回执和任务完成在同一事务中提交，取消先落盘时拒绝迟到结果，提交先完成时返回已保存版本。保存前复核原模型库版本和当前授权。

服务开始时把遗留活动任务标为中断，并清理对应临时文件。关闭服务时通知活动校验退出。已保存结果通过旧有固定版本接口读取，原有版本、使用去向、校准及场景引用保留。任务表随既有配对备份保存。

上传界面区分发送文件和校验。提交结果待确认时提供状态检查，取消确认后可再提交。仅在模型处理任务已可读时提供取消按钮。
