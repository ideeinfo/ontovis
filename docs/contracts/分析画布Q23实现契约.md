## 推荐与关系修正（2026-10-27）

先加报警再加工程对象时，固定模拟报警按当前项目主标识生成“模拟报警对象”连线。选择对象后，模型推荐与连线共用绑定依据：有效同一UID绑定为实线，回收站绑定为虚线历史参考，主标识与构件名称匹配为虚线候选；点击关系保留明确构件锚点，不被旧镜头覆盖。推荐行、模型查看器和右侧关系均说明依据。

当前报警对象清单仍由Demo-PDS演练规则提供，资料关联与模型机制可复用；不能将演练清单称为通用知识图谱诊断推理。当前真实场景绑定已在回收站，且项目定义与安装UID不同，未自动恢复或等同。详细算法、边界、分页和性能范围见[推荐与关系依据契约](分析推荐与关系依据契约.md)。本次不新增表、权限或HTTP路径。

## 1. 页面与存储

项目中心进入项目后，可从“数据与告警”“工单”“设备层级”进入分析，也可从“分析画布”打开本人已有分析。报警入口按故障码映射推荐对象及其直接资料，名称搜索仅用于补充资料，不先下载整个项目目录。

`schemaVersion=2` 保存九类卡片：object、drawing、document、photo、model3d、trend、alarm、work_order、analysis。来源卡只存本人会话内已登记的固定 id/revision；来源 kind、连接、项目和摘要由后端验证。旧 schemaVersion=1 笔记继续可读，后续保存可升级；回收站通过显式离线迁移将数据库存储版本升级至3，分析内容格式仍为2，不新增任意 JSON 扩展。列表独立开关、可恢复删除及版本条件见[画布列表与回收站契约](分析画布列表与回收站契约.md)。

工程对象卡的工程分类优先显示来源 `classification` 的标准代码及当前语言名称；没有标准分类时才退回 `objectKind`，与对象目录共用显示规则。`objectScope` 另列为项目定义、安装对象或定义/安装范围未标注，不能用范围缺失覆盖已有工程分类，也不从分类推断范围或复核状态。内嵌及展开查看共用同一实现；读取沿用现有来源响应，不新增分类查询。

每分析最多50张卡、100条人工关系、10个分区、20个上下文对象；卡宽240—1440、高176—1200，画布25%—150%。所有卡支持四边四角缩放，Shift等比、固定、多选、整理、移除和撤销。照片视角保存 zoom/centerX/centerY，三维保存 eye/target/componentId；这些是显示参数，不改变原件或工程坐标。照片使用50%—1600%的整图基准、指针锚定滚轮和左键平移，关闭前保留最后视角。

笔记可分别编辑观察、原因假设、检查步骤、检查结果、反证与缺口、下一步，总长4000字。人工引用、原因假设、支持与反证必须有依据；不允许客户端声明源工程关系。分析状态保持分析中、待现场核查、待复核；不在标题或操作名反复显示“草稿”。

## 2. 已实现 HTTP 增量

前缀 `/api/workbench/analysis-sessions`，沿用同源会话、`expectedSessionRevision`、完整 `projectRef` 和当前成员权限。所有写入只允许本人且具有项目管理员权限，写入前及提交前检查权限、版本与幂等请求。撤权后不重放成功正文。

| 后缀 | 请求要点 | 结果与边界 |
| --- | --- | --- |
| /start | entry、requestId | entry为固定模拟数据集/修订、工单编号，或对象UID/修订/timeTo；同一事件继续已有分析，独立同码事件建立新分析并继承可读历史 |
| /recommendations | entry、section、可选q/cursor/offset、所选对象 | objects/materials/drawings/photos/documents/models/orders/alarms/trends，首批对象最多8、其他12；报警优先当前事件，趋势只列当前事件的固定信号描述，不预取样本；直接关联与名称匹配理由分列 |
| /evidence/register-batch | analysisSessionId、expectedAnalysisRevision、items | 最多12项，每项key/requestId/sourceKind/selector；逐项结果，重复固定描述复用句柄，独立请求回执不可变 |
| /evidence/batch | analysisSessionId、evidenceRefIds | 最多12项；读取本人描述后释放PG连接，再读取受保护来源；受限项无旧正文，最终权限变化拒绝整次返回 |
| /evidence/preview | analysisSessionId、evidenceRefId、options | 固定资料的对象/端口/连接/引用或文档知识图谱；图纸每页最多200项、图谱每页100节点 |
| /evidence/relationships | analysisSessionId、evidenceRefIds | 最多50个本人固定引用、200条来源关系；返回目标定位锚点，缺证分列 |
| /evidence/preview-content | analysisSessionId、evidenceRefId、可选pageNumber | 照片快速显示版本或文档指定页；每次核对当前权限与来源，原图读取沿用content |
| /history-candidates | 当前entry（固定数据集或工单） | 同连接/项目/本人及故障码语义范围的有界候选，给出对象/事件匹配理由 |
| /import-history | 当前会话/头修订/未保存snapshot、historySessionId/historyRevision、requestId | 登记独立引用并返回合并布局，保留本地当前调查；用户保存后才增加内容修订 |
| /copy | analysisSessionId、snapshot、requestId | 服务端验证并重登记新会话引用，不复制跨会话专属句柄；用于冲突后的另存副本 |

create/save/copy/import-history/register-batch请求上限264KiB，其余分析入口16KiB，Nginx与HTTP处理器一致。快照正文仍最多256KiB。保留单项来源、修订恢复、固定工单关联接口；新写入不改变工单处理状态。

## 3. 文档及原件

文档固定 `documentId/contentVersionId/sourceSha256/pageNumber`，通过既有OntoBase API读取受保护页图和目录，页/章节跳转登记新固定页引用；原卡不会静默换到最新版本。当前接入正文、页码、目录、已发布知识图谱与证据页；图纸的对象/端口/连接/引用按固定文件版本读取。没有可信图纸热点时显示整页，不制造OCR区域。模型节点仅按实际几何/代理定位，柜级代理持续标为示意。

13001案例使用原有对象、柜级归属、真实图纸与照片标签、既有TU-3000模型和固定工单快照；另通过OntoBase API登记自编的《13001模拟测量偏差试验说明》，明确是软件演练资料，不冒充厂家手册或现场检修规程。模拟测点保留90秒质量缺口、30/150秒发生恢复和真实UTC窗口。当前r4追加实际厂家故障码手册及已发布知识、跨页图纸和绑定模型的演示安装对象；X91之后仍缺工程依据，定义到安装对象及1B4到知识节点的确认映射仍缺失。

## 4. 同码复用与并发

历史索引按本人、项目、故障码及sourceConnectionId筛选，优先同事件、同对象、同分支，最多20项。新事件保留独立事件/趋势/笔记，历史卡标为参考并绑定原analysisSessionId、revision、SHA；历史笔记正文只读。重复进入同一事件不重复复制。多个候选可显式选择，不从标题猜故障码。

保存期望头修订，不覆盖另一客户端修改；冲突保留本地内容，可另存或明确重读。恢复历史追加新修订。工单只关联明确保存的rN，后续rN+1不自动改写工单链接。

## 5. 请求预算和资源释放

每个工作空间轻量来源最多4个并发、重文件最多2个；批量读取避免逐卡串行等待。PG分析连接名额为2，元数据描述读完即释放连接，原件传输不占数据库连接预算；不增加数据库账户连接上限。当前权限在请求边界核对，源API仍独立保护资料，写事务保持提交校验。

固定字节缓存最多20项/96MiB、额外解码缓存最多2张；各个已打开查看器独立持有图片元素，缓存淘汰不会关闭其他卡片，当前分析离开/身份或权限范围变化后取消请求并释放URL。热打开复核当前可读性但不重传相同原图。照片快速版本最长边4096，原件不变；服务端派生缓存最多12项/32MiB，单个渲染任务，命中缓存前仍核对来源可读性。图纸、照片、文档和三维均按卡片独立开关，可同时打开多张；收起一张、大预览打开/关闭和保存不关闭其余预览。多三维按需加载、独立保持构件与视角；视野外的重内容不持续运行。加载较慢时提供状态、取消和重试，不以空白等待代替反馈。没有新增外部埋点。

## 6. 恢复与后续对话

离线工具 `analysis_canvas_upgrade.py` 仅新增查询索引，要求停服务、预期storeId、排他目录租约及PG锁；不更改业务行或放大服务账户权限。整组备份同时验证原场景/模型/工单、五张分析表、固定来源、历史原修订和别名回执；恢复只能到新库/新目录。

自然语言阶段复用有限画布动作及带项目/会话/所见修订/选择/固定引用的上下文；按钮和后续对话没有两套保存语义。当前不连接LLM，不以静态回答冒充助手，不开放结论确认或设备控制。通用图邻域、真实实时流、跨人协同及完整文档全文检索仍属后续相应任务。
