# 工程助手检索与操作契约

2026-11-04 · 对应[统一能力设计](../design/工程助手统一能力设计.md)。**本文件为待实施逻辑合同；标为“新增”的工具名和字段不是已经开放的HTTP接口。** 不改变现有业务表、API及已保存记录，实施时逐项落实版本。

## 1. 上下文与能力

运行输入包含用户问题、客户端幂等键、当前界面模式、请求项目范围、可选画布ID、已保存修订、草稿修订及摘要、所选对象/卡片、明确排除的资料。草稿仅携带结构与已注册引用，源内容由服务器读取。新建画布允许尚无保存修订，但不能省略项目与草稿身份。

后端独立生成当前 `AccessContext` 和能力快照；客户端角色、自然语言、模型响应、源文档均不能扩大它。有效能力是用户现有权限、当前模式、已接入业务动作、项目策略、模型资料规则的交集。后台可编辑，驾驶舱读和导航；工具执行、内容读取、模型调用、变更提交及回读分别重校。

`ContextSnapshot`新增概念：

| 字段 | 用途与校验 |
|---|---|
| `projectRef` | 连接ID+项目代码；服务器核对实际成员范围 |
| `canvasRef?` | 已有画布ID、savedRevision；不跨项目重用 |
| `draftRef` | 页面草稿ID、draftRevision、draftDigest；不能仅用r8判断是否未改 |
| `mode` | `workbench`或`cockpit_query`；服务器端能力校验，不依赖按钮隐藏 |
| `selection` | 确切卡片/对象引用；“这两项”通过上一轮固定结果解析 |
| `searchScope` | 服务器验证的项目/目录/类型/状态/时间条件；默认当前项目，不隐式扩大 |
| `exclusions` | 本轮/对话显式排除项；与单纯移除画布卡不同 |
| `authorityVersions` | 访问、策略、模型连接、画布、来源版本及取消标记 |

能力描述固定在代码与现有服务边界，不建立运行时插件市场或任意API代理。每个已接入动作包含名称、明确参数schema、读取/草稿/保存/业务写入类别、前置条件、目标版本、回执读取和撤销说明。能力目录是实际模块的有限映射，不允许模型发明工具。

## 2. 检索与本轮证据

### 2.1 新增逻辑工具与既有实现基础

### 2.2 搜索响应

`SearchResult`包含状态、实际查询范围、匹配字段/关系、结果候选、已查数量/完整性、分页游标、来源快照、截断原因和剩余未查部分。候选含稳定身份、标题、版本、来源系统、模拟/真实、设备/型号/时间适用性、权限内可用操作。

状态至少区分 `complete`、`partial`、`empty`、`unavailable`、`not_connected`、`not_allowed`、`ambiguous`、`cancelled`。不能将403、502、预算截断、当前画布未选等转换为empty。无权时不泄露不可见项目/对象的名称、存在性或数量。

历史查询以当前故障码作为匹配条件，设备/型号作为精确过滤或排序依据；“同故障”默认解释为“同故障码候选”，没有确诊信息时不宣称同根因。当前报警窗口不自动用作历史工单检索窗口。用户显式指定“去年”“本机”时才施加对应条件，并显示实际解析的UTC范围/设备身份。

### 2.3 运行证据与画布引用分离

现有 `AnalysisEvidence` 按分析会话注册引用，助手从已保存会话取 `evidenceRefIds`；新版增加运行内的受控证据集合。查到资料可先只供本轮阅读，不自动修改画布。每个片段记录固定descriptor、来源revision、内容摘要、读取方式、页/区域/节点/边、权限复核与外发类别。不得直接把候选目录文本当全文证据。

用户要求加入画布时，将本轮固定来源通过原证据注册服务注册到该分析，再用返回句柄创建卡片。保存前再次核验；不能把浏览器传入任意源URL或用户手填JSON当证据。删除卡片不删除运行证据；明确排除、撤权或资料不再适用时后续模型上下文重新过滤。

运行证据的保留期、大小与访问方式需沿用助手运行记录的私有存储机制，不能借此新建一套未授权全库缓存。来源撤权后阻断回读及后续外发；对历史结果的引用可保留不可访问占位。

## 3. 模型协议

继续使用 OntoBase 已配置连接。Vis负责上下文/本地业务与画布编排，OntoBase负责其权威数据及现有AI服务，不让用户手工分配产品职责。

新增版本化的规划与回答协议，输出只有下面的类型化内容：

- `answer`：直接答案、类型适用的分区、逐条E引用和局限。
- `tool_requests`：从本次能力快照中选择的读取动作及合法参数。
- `clarification`：必要的单个消歧问题及已授权候选。
- `operation_proposal`：明确目标、动作、前置版本、原因、改变摘要；不包含可执行代码。

用户指令授权动作，模型仅解析。服务端把原用户轮次与解析后的动作关联，拒绝来源文档中的“删除/发送/更改设置”等指令变成权限。新增来源、外发内容和配置变化都受现有策略控制。

简单确定性查询/命令可跳过规划模型；模型每次只看本题必要工具和资料。单轮3次模型/8次读取/2并行/120秒为待评估上限，新旧策略明确分版。回答类动作可以部分成功；写入提案必须完整验证后才能执行。解析失败不执行任何动作，不能自动增加调用或换模型。

## 4. 画布动作合同

### 4.1 操作批次

新增 `CanvasOperationBatch`：批次ID、原用户轮次ID、目标画布/草稿、基准savedRevision/draftRevision/digest、操作列表、影响摘要、前置条件、提交状态及逆向操作。操作列表使用确定枚举：

| 分类 | 具体动作 |
|---|---|
| 资料卡 | 加入已注册证据、移除卡、更新固定引用、重命名卡片显示名 |
| 笔记 | 新建、追加、替换指定段、删除；人工文字改写显示差异 |
| 位置与展示 | 移动、调整大小、固定/解锁、卡内视图、聚焦、全览、整理布局 |
| 关系 | 新增/修改/移除人工引用、支持、反证、假设关系；源关系仅由可信来源加载 |
| 分组 | 新建/修改/解散分组、增减成员、分组布局 |
| 上下文 | 标题、允许的进度、明确时间范围、趋势切片/对照 |
| 生命周期 | 保存、另存、恢复修订、回收/恢复、导入历史、保存后关联工单 |

纯视图操作不产生业务保存。助手不能用状态字段绕过当前后端尚未开放的 `concluded`。现有50卡/100关系/10分组、单条笔记4000字符上限保持，超限要求缩小范围或另建画布；不得静默截掉用户要求的项目。

### 4.2 权限与原子性

服务器先校验批次身份、作用范围、精确目标、固定来源与预算，产生可应用回执；客户端仅应用与当前草稿前置条件匹配的批次，进入与手工操作同一个undo栈。服务器持久化写入仍走原保存服务及权限/版本比较。前端执行完毕不能只凭模型文字记成功，应返回实际动作结果。

同一批次一次应用，校验失败不进行半个本地编辑。注册证据成功但加卡因草稿冲突失败时，回执是“资料已准备，未加入画布”，不声称完成。注册句柄不等于已保存画布，不删除来源来补偿。

指向固定卡片的移动/删除：用户明确指名可解锁该目标后执行并在批次中保留原固定状态；普通“整理全部”不移动固定卡。删除有笔记或关系的卡片显示影响，并在撤销中完整恢复；批量模糊“清空”先展示具体清单。

### 4.3 保存与重复提交

保存调用沿用客户端请求ID与expected revision。相同请求ID相同内容返回原回执；相同ID不同内容拒绝。错误/超时后先查询同一回执，确认失败才允许新请求。不得用新ID自动重试未知写入。

“加入并保存”串联两个可追溯步骤；保存冲突不抹掉已应用草稿，不声称所有步骤成功。跨工单与画布没有跨库原子事务时以分项回执表达：“画布已保存r9，关联工单未成功”；重试仅针对未完成项，并重新核对工单版本。

撤销从精确操作批次生成逆向动作，不替换整张旧快照；若目标随后被人工编辑，需要差异核对。撤销不删除已保存历史，恢复内容通过新草稿与新修订保存；历史保留仍遵循原产品规则。

## 5. 系统业务动作合同

模型选择的动作必须映射到现有业务服务或已有页面表单，不能透传任意路由。工单受理、记录、提交、退回、关闭、重开遵循各自状态机；关闭和复核等最终业务动作不由AI推断完成，用户通过对应确认界面提交。新增工单如果系统只有演示批次生成而没有正式创建接口，返回“当前未接入创建”，不能生成虚假的正式编号。

场景保存、模型版本/校准/绑定、设备采用、照片关联、资料上传/知识处理、AI配置等都显示具体目标与差异。已有能安全直接执行的明确命令复用同一服务，不强迫每一步弹确认；破坏性、共享范围、批量、工程审核或安全敏感动作在产生副作用前展示必要确认或转原业务界面。助手的能力配置不能由本次运行自行修改以绕过限制。

所有成功描述必须来自业务回执，至少带对象ID、版本、已改字段、部分失败/剩余项和可用撤销方式。某个页面已打开不等于该操作已成功；不能以“请前往...”伪装已完成业务动作。

## 6. 状态与恢复

运行状态：接收 → 解析范围 → 检索 → 读取 → 整理/形成动作 → 校验 → 应用草稿或等待业务确认 → 回读 → 完成/部分完成。

等待用户选择、冲突解决与结果未知是独立状态；等待期间不继续调用模型。取消先阻止新调度，再确认已执行范围；已经提交的保存仍返回其事实。浏览器断线不重复创建运行，回到页面读取同一运行；离开当前画布不会把旧操作应用到新画布。

| 状态 | 用户看到的内容 | 允许下一步 |
|---|---|---|
| 未搜索 | “尚未查询工单库” | 发起当前范围查询 |
| 空结果 | “在项目P，按条件C，已完成查询，未匹配” | 修改条件/扩大已授权范围 |
| 部分结果 | 已查范围、候选及尚未完成部分 | 在剩余额度内继续或另起运行 |
| 无权/未接入 | 可理解的范围或能力限制 | 切换有权范围/原功能入口；不透露隐藏资料 |
| 来源不可用 | 哪类来源失败、其他结果是否有效 | 只重试失败的只读步骤 |
| 草稿冲突 | 目标字段前后差异、未应用批次 | 重新核对后应用/放弃 |
| 结果待确认 | 原请求与已知状态 | 只检查回执，禁用重复写入 |
| 完成 | 已读取、草稿已改、业务已保存分别列出 | 引用核对、撤销/继续 |

## 7. 验证要求

每个接入动作测试本人/无权、版本变化、重复提交、取消或结果未知中的适用组合；图谱逐边与来源一致，候选不升级事实。固定来源引用可核对不是结论正确的证明。已有引用/会话保护不能为扩大检索范围而删除。

首批必须同时通过：画布已移除工单仍能查到；空画布可查；未保存草稿被正确识别；查询不改画布；明确加入可撤销且无重复；保存产生真实新修订；驾驶舱只能查询并转后台；图谱对象不在画布也可解析查询。完整逐项验收见[计划](../plans/工程助手完整能力实施计划.md)。

## 项目工具实现（2026-11-04）

新流程使用 `ontovis-engineering-tasks-v1`，旧摘要、对话和采纳回执保持兼容。入口为 `task-start`（幂等提问）、`task-page`（固定工单列表快照分页）、`task-prepare`（授权、来源版本校验与资料登记后返回草稿批次）、`task-ack`（接收应用摘要并核对实际保存修订）。公开入口仅代理这些明确路径，草稿请求上限264KiB；不是任意工具代理。

规划模型仅接收当前用户要求、画布目录、当前故障码及最近用户问题/候选标识；不会读取工单正文来生成新增写入授权。有限工具读取项目工单、对象、资料目录、工程两跳邻域和已发布文档知识；本页唯一命中明确知识根节点时继续读取其固定发布版、证据页和两跳知识；项目还有后续分页时仍可读取本页固定来源，但须说明其他结果未读。来源内容只进入回答，不再生成动作。当前最多8次工具读取、2路并行预算、120秒、3次模型调用；常规实际为规划与回答两次，受项目与能力限制取严约束。

工单在当前项目库用独立SQL精确过滤故障码和可选工单编号后分页；有精确身份过滤时不再叠加模型复述的整句关键词，返回唯一编号、修订、状态、模拟标记、匹配依据、总数及列表快照。故障过滤不使用模糊标题，不将当前趋势区间套用于历史工单；资料卡移除不影响项目库。目录检索失败、空结果和预算截断分别留痕。对象位号先按项目主标识精确查询，无精确结果才回退到名称/位号模糊检索；多义结果不任取一个对象。图谱保留节点、逐边出处、固定发布及页码，不以名称分组推断接线、方向或根因。

后台可应用已确认候选，或执行有限的加入资料、移除卡片、增加待核验笔记、重排、改画布名、移动/调整卡片、添加假设关联及保存操作。固定趋势时间不能只改标记，继续使用既有趋势工具。所有草稿批次都绑定原始JSON的SHA-256、保存修订和具体运行；当前草稿或保存头变化即拒绝。资料沿用 `AnalysisEvidence.register`、来源快照和原画布校验；本地应用一次进入撤销栈。新空白画布首次登记时只建立空的私有容器，原草稿未因此保存。明确保存使用既有保存请求和版本保护。本次新发、明确且可撤销的编辑直接进入草稿；历史/恢复运行不自动重放，离开画布后不继续应用。已有未保存内容且请求保存时，先展示整张草稿的保存范围，由用户点击具体操作执行。

执行回执表保存准备批次及应用确认，重复准备回读同一批次；已有应用确认时不重复应用。回执失败只重读确认，不重做草稿动作；保存成功由后端读取实际保存修订核对，保存未知不冒称成功。界面优先显示实际回执，执行前生成的回答折叠保留；模型文字不替代执行状态。回执描述该次执行时的状态，之后手工撤销/保存仍以画布当前状态为准。取消已被后台接受时，迟到模型结果不能写成完成。

驾驶舱运行的模式持久化为 `cockpit_query`，准备与确认接口均拒绝写入，不能通过请求体把原运行升级为后台执行。“转后台继续”只带入问题和画布最新修订，后台重新规划、读取和核验，不自动应用原查询运行。旧“整理到工单”入口仅用于原固定摘要回执，不把项目检索目录伪装成已登记工单证据；本批没有开放任意模块写入、工程事实确认或现场控制。
