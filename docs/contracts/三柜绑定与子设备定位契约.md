## 2. 公共类型与不变量

### 2.1 身份与版本

| 类型/字段 | 约定 |
|---|---|
| `ObjectRef` | `{ontobaseConnectionId, projectCode, entityUid}`，均为非空不透明字符串。连接只能选部署批准项，服务端验证项目与 UID 所属关系 |
| ONTOVis 范围 | `projectId, sceneId, sceneModelInstanceId`；模型实例关联由 OntoBase 核实的 `installationContextId` 和机组 `ObjectRef`，不从 WTG-01 名称生成上下文 |
| `installationContextId` | OntoBase 拟新增的不透明安装实例范围标识，具体落库形式待评审；模板/实例需显式区分，未知实例不能发布 |
| 源构件身份 | `sourceModelKey + sourceElementId + placementId`；仅经来源验证且唯一时允许生成跨版迁移候选 |
| 版本内几何引用 | `modelVersionId + componentKey`，再与 `sceneModelInstanceId` 组合；`nodeIndices/primitiveIndices` 只能解释该版本的派生产物 |
| 修订 | `entityRevision/hierarchyRevision/bindingRevision/sceneRevision` 分域，作为不透明比较令牌；不能以更新时间或文件名代替。现有 `row_version` 只在其原领域内复用 |
| 证据 | `EvidenceRef` 固定对象、文档版本/内容摘要、anchor、来源和访问状态；短期文件地址不是证据 ID |
| `geometryQuality` | `source_verified / source_candidate / proxy_schematic`，与人工绑定审核和定位方式分别表达 |

单条绑定至少保存 `bindingId, bindingRevision, sceneModelInstanceId, modelVersionId, componentKey, objectRef, entityRevision, installationContextId, status, geometryQuality, evidenceRefs, reviewedBy, reviewedAt, reason`。绑定草稿可缺对象；已审核绑定不可缺身份与实例依据。同一场景实例、模型版本、构件只有一个主对象；一个对象可对应多个构件。子设备无几何时不新增虚假绑定。

### 2.2 时点、权限与分页

- `resolutionMode=live`：请求不自报权威时间/树版本，服务端捕获 `resolvedAsOf`，选当前发布场景并固定本次读取版本。各查询使用同一安装上下文、业务时点和层级快照；不能逐页读取不同“最新树”。
- `resolutionMode=history`：必传 UTC `asOf` 和固定 `sceneRevision`；可再传 `hierarchyRevision` 复现已保存快照。只给时点时，OntoBase 解析该时点的已记录事实并返回选定修订；它不承诺还原“当时系统已知什么”。旧会话重现须保存并传回层级修订。版本无记录返回不可用，不查当前树补齐。
- 关系业务有效区间为 `[validFrom, validTo)`，`validTo=null` 表示无已知结束；`recordedAt` 表示记录时刻，不能替代业务有效时点。历史模型/绑定/放置均取固定场景组合；资料版本另固定，不宣称全库已具备双时间能力。
- 授权始终按**当前**用户与当前策略检查，即使查询历史。浏览器 scope 只是请求选择；服务端从受信身份求交，不接收客户端/模型提供的 capabilities。项目能力读取不能替代后续资源授权。
- `listObjects/listChildren/listEvidence` 建议默认50条、最大100条；批量 resolve 最大50个；祖先深度建议最多32。均为待样本校准预算，超过上限拒绝或返回明确截断，不全量加载后前端假分页。
- 分页响应统一含 `items, nextCursor, snapshotRevision, resolvedAsOf, retrievedAt`。cursor 不透明，绑定连接/项目/实例/父对象/过滤条件/时点/修订与授权范围；默认稳定按 UID（证据按固定记录键）排序。条件变化拒绝复用，快照过期要求重读首屏。每页重新鉴权，撤权优先于快照。
- 子节点计数可为 `visibleChildCount=null`，只统计调用者可见范围；不暴露隐藏总数、隐藏祖先名称或路径距离。关系链不完整时不跳过受限节点猜位置。

## 3. OntoBase 提供的首批操作

操作编号用于需求、任务和合同测试互相追踪。以下输入均隐含服务端用户身份；不在载荷传令牌或秘密。

| ID / 拟议操作 | 最小输入 | 成功返回 | 关键失败/约束 |
|---|---|---|---|
| OB-C01 `getProjectAccess` | 受控连接、projectCode | 项目代码/名称、当前可读范围、有效能力、`accessRevision, checkedAt` | 未连接与拒绝访问分开；缺真实委托方案不得用超级服务账号或共享签名密钥代替 |
| OB-C02 `resolveObjects` / `getObject` | ObjectRef[]（或单个）、实例范围；history 时加时间选择 | 每项 `requestedRef, canonicalRef, resolution, lifecycle, entityRevision, objectKind, installationContextId, identifiers, displayName` | `resolution=exact/merged`；merged 返回有权可见的跳转依据，相关绑定进入复核。缺失/无对象权限统一不可定位；退役、删除保留可授权的生命周期说明 |
| OB-C03 `listObjects` / `listChildren` | 项目/实例；父 ObjectRef；q、类型/标识scheme/scope、cursor/limit、时间选择 | 已授权对象摘要；children 附已确认 `relationId, parentRef, childRef, validFrom/To, relationRevision`、可见子节点计数 | children 仅直接物理子设备。候选/电气邻域不能混入；不存在/受限与空列表区分，外部响应不泄漏对象存在性 |
| OB-C04 `getAncestors` | ObjectRef、installationContextId、时间选择、maxDepth | 最近父级在前的 `path[]`（每步对象与确认关系、有效期、证据、修订）、`hierarchyRevision, resolvedAsOf, completeness` | 仅确认关系；环/多父/未知历史/超深/路径不可用不能当完整成功。无父且已确认是根可返回完整空链；不完整链不得推测 |
| OB-C05 `createIndependentObject` / `reviewContainment` | 对象：项目、实例、名称/分类/标识、来源/依据；关系：父子ref、有效期、证据、动作/理由、expectedRevision、clientRequestId | 对象新修订或原子关系变更；确认者、时间、审计引用 | 在 OntoBase 自身界面操作。无需 bbox；跨项目/跨实例、模板串挂、自指、重叠单父、并发成环被事务拒绝。移装一次关闭旧关系并建立新关系 |
| OB-C06 `listEvidence` / `getAuthorizedFile` | 对象ref、资料类型/适用时点、cursor；打开固定 evidence/documentVersion/anchor | `evidenceId, objectRefs, relationBasis, documentVersionId, contentDigest, anchor, applicability, verificationState, accessState`；受控打开响应 | 固定文件版本，不静默换最新；无区域降为页/章节，缺文件与无资料分开。原文每次校验当前授权；禁止复用当前 public/immutable 图片策略作为受保护证据策略 |
| OB-C07 生命周期解析（由 C02 及权威写流程提供） | 旧 ref；合并/退役/删除动作带修订与原因 | canonical/退役或 tombstone 状态、可公开原因、有效时刻/修订、可见影响 | 不自动把旧绑定迁到新 UID；删除最后一张图纸不静默删除仍可能被引用的工程身份。首切采用保留身份/受控退役，不依赖跨库外键或新建引用注册平台 |

OB-C02 返回的 canonical 链必须可终止并有深度上限；循环、目标失效或目标无权时不返回一个猜测 canonical。用户可以对有权的 canonical 打开对象卡；旧 UID 的几何绑定仍需重新核实并发布，不能因解析成功就静默迁移。

OB-C04 的 `completeness` 为 `complete/incomplete`，响应只带可见节点及通用原因 `PATH_UNAVAILABLE/DEPTH_LIMIT/HISTORY_UNAVAILABLE/INVALID_HIERARCHY`，不透露被隐藏节点的存在或数量。不完整路径首切统一返回未定位，保留有权对象资料入口。

OB-C05 新建对象没有既有对象修订，但须验证项目/安装上下文当前版本；其他改动必须提交目标 expectedRevision，关系变更至少比较整个受影响安装上下文的 hierarchyRevision。服务端锁定上下文，在同一事务内检查整批关系的有效区间/环/重复父并写入审计；不以先读后分别写两笔请求替代。

OB-C06 首切先覆盖对象关联图纸与原文。已有手册/照片若有可核验版本可按相同语义读；完整照片上传归档、有界电气图邻域不阻断本切片，留在原 WBS05/06 和后续范围。

## 4. ONTOVis 提供的首批操作

| ID / 拟议操作 | 最小输入 | 返回与版本 | 关键失败/约束 |
|---|---|---|---|
| OV-C01 `createModelVersion` / `processModel` | ONTOVis projectId、modelId（新资产可同时建立）、目标expectedRevision、来源/用途/许可、文件与sidecar指纹、clientRequestId | `modelId, modelVersionId, jobId, status`；完成后原件/派生指纹、处理器版本、质量/坐标/身份报告 | 新资产比较项目配置版本，追加版本比较模型目标修订；受权接收与隔离处理，不抓取外部URI。失败/取消不替换当前发布版；任务重试/完成比较attempt与租约 |
| OV-C02 `inspectComponents` | projectId、modelVersionId、cursor/limit/过滤 | 构件目录：componentKey、keyStability、源三元组、版本内节点定位、bounds、属性白名单、geometryQuality | sidecar 与实际文件指纹一致；源/派生节点映射单列。重复ID、缺属性可浏览但不能伪称跨版稳定 |
| OV-C03 `proposeBindings` | 固定场景草稿/实例/模型版本、构件、受控属性映射规则或人工选定ref、expectedRevision、clientRequestId | 候选/歧义/缺身份、依据、核验版本、草稿新修订 | 文件内 claimedObjectRef 必须经 OB-C01/02；名称/RDS匹配只出候选；缺对象去 OntoBase 建档，不在此生成权威UID |
| OV-C04 `reviewBindings` / `publishSceneRevision` | binding draft revision、审核动作/理由/证据；发布带 expectedRevision 与固定模型/实例/可视化配置引用、clientRequestId | 审核记录；发布产生不可变 `sceneRevision, bindingRevision`，固定模型与放置/配置修订、authorityChecks | 服务端能力检查、身份/实例复核、构件唯一/存在、必须三柜、坐标/处理报告、代理用途全部通过。发布与审计在自身事务原子切换，不修改工程事实 |
| OV-C05 `locateObject` | selectedObjectRef、sceneId、sceneModelInstanceId/representationChoice（有歧义时）、resolutionMode；history 需sceneRevision/asOf；contextEpoch | 见下节；只解析已发布绑定（明确的管理员草稿预览另走隔离入口） | 多实例/多表示需显式选择，未知/冲突/失效不得随机取第一条；前端按 contextEpoch 丢弃过期响应 |

所有带写副作用的操作按操作者、项目、操作与 `clientRequestId` 幂等：相同键/相同内容重放原结果；相同键/不同内容返回冲突。每次重放先检查当前授权，不以旧成功记录绕过撤权。修改草稿、审核、发布、归档/回滚都检查版本；回滚是经当前权限/身份校验的新发布，不重新授权旧对象。

发布固定组合：`sceneRevision → modelVersionId[] + sceneModelInstanceId/placementRevision[] + bindingRevision + visualizationConfigRevision`。`authorityChecks` 保存所查工程引用、entityRevision、hierarchyRevision（涉及时）、checkedAt 和访问策略版本；它是核验记录，不是永久访问凭证。

两端没有分布式事务。ONTOVis 发布前有界批量核验身份/关系并记录版本，再在自身事务比较草稿/expectedRevision 和发布指针；校验后远端变化仍可能发生。后续定位/打开证据重新核验，发现合并、退役、实例变化或无法取得一致层级时显示待复核/不可用。首切用按需批量复核与有界重试，不宣称已有实时变更总线或零延迟强一致。

## 5. 定位算法与响应

1. 校验用户对 ONTOVis 项目/场景、目标工程对象与安装实例的当前权限。捕获并固定本次场景组合、业务时点和层级修订。请求中的展示名、父级或模型树不参与工程身份判断。
2. 按 C02 解析所选对象。合并/退役等变化不能拿旧绑定继续导航；有权对象卡可展示变化，绑定进入待复核。用户分析目标不因柜体高亮被替换。
3. 在当前场景/明确实例中查所选对象可用的已发布直接绑定；有唯一主表示则 `direct_geometry`。同一对象的多个组成构件可一起高亮；多个独立表示且无已审核主表示则返回候选要求选择。
4. 没有直接几何时，取得相同时点/修订的**完整已确认**物理祖先链，从近到远查最近有可用已发布直接绑定的祖先。只在当前实例中解析，命中则 `ancestor_proxy`；不写子设备绑定，不反向修改物理父级。
5. 无祖先绑定、链不完整、快照无法复现或相关引用失效，返回 `unlocated` 及原因。有权对象/证据仍可读；无权时清理旧缓存与高亮，不返回对象内容。首切不启用 `annotation_proxy` 写入。

最近祖先存在绑定却版本失效/歧义时，首切保守返回未定位或要求选择，不越过它跳到更远设备制造“成功”。历史查询缺任何指定版本都不回退当前版本。live 跨读取遇层级修订变化可有界重试一次，仍不一致返回可重试错误；不能混用两条父链。

### 响应字段

| 字段 | 含义/空值规则 |
|---|---|
| `selectedObjectRef` | 当前有权分析的目标ref；正常无几何子设备场景始终是子设备ref。发现合并时仍保留原目标，待用户明确切换，不以canonical或祖先自动替换 |
| `requestedObjectRef` / `identityState` / `canonicalObjectRef` | 保留原始请求ref；identityState为exact/needs_review；合并时canonicalObjectRef仅是已授权的新目标提示，其余为null；旧绑定不得静默迁移 |
| `locatedObjectRef` | 实际几何宿主：直接定位等于 selected；祖先代理为柜体；未定位为null |
| `locationMode` | `direct_geometry / ancestor_proxy / unlocated`；保留将来 `annotation_proxy`，本切片不返回该模式 |
| `geometryQuality` | 宿主几何质量，不能推导设备工程等价性；未定位为null |
| `resolutionMode, resolvedAsOf, resolvedAt` | live/history、所查业务时点、响应计算时间，均明确UTC |
| `sceneRevision, bindingRevision, hierarchyRevision` | 本次实际使用的冻结修订；未查询父链时hierarchyRevision可null，历史缺失不得伪填最新 |
| `modelVersionId, sceneModelInstanceId, componentKey, componentKeys` | 定位产物与实例；componentKey为主构件，componentKeys为该表示的完整组成构件；无定位为null/空数组 |
| `path, reasonCode, reason` | 可授权的确认祖先依据和有效期；稳定码＋简短用户提示，未定位时不泄漏隐藏路径 |
| `representationChoices` | 多表示时返回有权候选，每项固定`sceneRevision, sceneModelInstanceId, modelVersionId, componentKeys`；用户将整项作为representationChoice重传，服务端核验仍属于当前请求与发布组合。未选择时无位置，非歧义时为空数组 |
| `contextEpoch` | 原样回传界面请求上下文标识，供丢弃旧响应；不构成权限或工程版本 |

## 6. 失败、生命周期与状态映射

业务“未定位”与请求失败分开：对象仍可读但无可靠位置时成功返回 `locationMode=unlocated` 和安全的原因；无权、来源不可达或版本不一致则返回错误，不能伪造一份确定位置。错误载荷拟为 `code, message, retryable, requestId, details?`；details 仅含已授权目标的冲突摘要。HTTP 映射为评审建议，具体沿用各仓库错误格式局部扩展。

| 原因/错误码 | 返回/页面行为 | 恢复路径 |
|---|---|---|
| `NOT_CONNECTED / SOURCE_UNAVAILABLE / TIMEOUT` | 来源级失败；不显示旧高亮为本次成功，不标假空列表 | 重试/核验连接，保留已授权对象入口 |
| `FORBIDDEN / NOT_FOUND_OR_FORBIDDEN` | 项目级拒绝可403；对象/文件级统一404且不泄漏存在性；清理对应缓存/资料正文 | 权限恢复后重新获取，不能重用历史成功 |
| `AMBIGUOUS_IDENTITY / INSTANCE_MISMATCH` | 候选歧义或实例不符，禁止审核/发布 | 在 OntoBase 核实身份与实际范围 |
| `IDENTITY_CHANGED / OBJECT_RETIRED` | 现行定位不可用、绑定待复核；历史有权时可展示原版本及现状态 | 核实canonical或退役影响后生成新修订 |
| `NO_GEOMETRY / NO_CONFIRMED_PATH / PATH_UNAVAILABLE / DEPTH_LIMIT` | `unlocated`，不伪造柜内点；限制信息不能泄漏隐藏关系 | 补确认父链/授权或真实几何；保留资料分析 |
| `HISTORY_UNAVAILABLE` | 不具备指定历史位置，scene/tree/model/binding缺项分别在授权范围解释 | 补版本记录；可由用户另行选择live，不能自动切换 |
| `MULTIPLE_REPRESENTATIONS` | 无位置＋有权候选，不随机跳机组 | 用户明确选实例/表示，或审核主表示 |
| `REVISION_CONFLICT / SNAPSHOT_EXPIRED / CURSOR_MISMATCH` | 不覆盖他人修改，不混合分页版本；建议409 | 重新读取差异/首屏后重试，必须重新审核受影响项 |
| `INVALID_MODEL / EXTERNAL_RESOURCE / ID_COLLISION / COORDINATES_UNVERIFIED` | 报告错误或发布阻断，旧发布版保留 | 修复/重传派生新版本，复查坐标和构件身份 |
| `FILE_UNAVAILABLE / VERSION_UNAVAILABLE` | 原证据引用保留，原文缺失/固定版本不可得 | 找回原版本或经用户选择新证据，不悄悄换版 |
| `INVALID_HIERARCHY / MULTIPLE_PARENTS / CYCLE_DETECTED` | 写入拒绝；读路径不确定则无定位/错误，不宣布成功 | OntoBase 事务修复与审核；电气回路不受物理树规则误伤 |
| `IDEMPOTENCY_CONFLICT / CANCELLED` | 不同内容复用幂等键拒绝；确认取消后迟到任务不提交 | 新请求/新attempt，不制造重复发布 |

首切必须测合并、退役、图纸删除、撤权和物理移装：合并保留原ref/来源；退役不删除旧会话；图纸删除保护工程身份；撤权立即停止新读取与提交；移装按有效期取不同祖先，不能在模型里批量重绑子设备。下载后的文件不能靠前端隐藏撤回，首切采用整模型/场景授权范围，需保密分区时拆制品或阻断发布。

API的输入是受控连接上的projectCode＋entityUid；连接标识由ONTOVis后续受控配置持有，不让OntoBase根据客户端自报连接名确认来源。当前响应以`projectCode, requestedEntityUid, canonicalEntityUid`表达其权威范围，未来调用方在已批准连接上下文中构造本稿ObjectRef。没有新建通用适配层。

数据库新增独立entityRevision技术字段及incarnation；实体、标识和RDS变更推进修订，不将图纸row_version、更新时间或文件指纹当对象修订。已有properties中的合并指向在同项目、同安装范围最多解析16跳；失效时canonical为空。两条已有图纸/源文件删除流程现保留正式实体与RDS标识；受控退役/tombstone仍未实现。

读取使用同一只读REPEATABLE READ事务；目录修订在服务器聚合计算，响应行仍由LIMIT有界返回。游标5分钟绝对过期，不是登录令牌；撤权优先于旧游标。既有定义保持`objectScope=unclassified`；新安装对象有独立UID、上下文及可选来源定义修订，不批量重分类。未核实类别仍保留unknown/needs_review。

关系按`[validFrom,validTo)`维护有效期和系统修订。live由服务器固定时点；history须有带时区asOf，可固定hierarchyRevision，缺历史不回退当前。关系历史与对象元数据分开，`objectMetadataMode=current`，不宣称还原当时名称/标识。工程用途审核引用项目证据，当前只保存内容摘要快照，不等于授权原文归档。
