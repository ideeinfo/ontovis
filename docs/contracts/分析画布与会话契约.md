## 2. 快照与来源引用

页面形状由 [analysisCanvas.ts](../../apps/workbench/src/analysisCanvas.ts) 定义并供 MagicPath 预演实际使用。它是有界页面校验，不是权限实现。`schemaVersion=1`；范围为完整 `(ontobaseConnectionId, projectCode)`，相同项目码在不同连接下不能互读。身份、owner、操作者、权限和服务端修订不得由客户端自报。

快照保存名称、分析状态、上下文、卡片、人工关系及 viewport。上下文为最多20个对象ID、可选事件/工单ID、递增UTC时间窗和显示时区。首版时区支持 Asia/Shanghai、UTC；其他时区扩展需受控字典。坐标有限且在±20000，卡宽240—720、高176—960；相机平移±50000。小型快照上限256KiB，标题120字、关系依据1000字；禁止额外正文、文件字节、HTML、凭据或URL字段混入。

页面 `SourceRef` 的 `id/revision/locator` 是通用呈现形状，**不能直接当作各源API的完整参数**。正式服务需从受控资料选择结果生成不可变 `evidenceRefId`，将其版本与下列完整来源描述绑定；卡片只保存引用及布局。`source.id` 对应此受控引用，`source.revision` 对应引用修订。不能用浏览器自填字符串发起任意源请求。

| 资料类型 | 正式引用必须绑定的条件 | 当前真实能力缺口 |
| --- | --- | --- |
| 工程对象 | 源连接、项目、对象UID/版本、身份状态 | 现场身份/安装适用性仍以源状态为准 |
| 图纸 | 对象关系、文件/页、内容与来源修订、区域/坐标空间 | 当前内容快照不代表任意历史图纸原文可读；缺历史须显式不可用 |
| 照片 | 对象UID、contentVersionId、sourceRevision、displayRevision、显示摘要、原区域及坐标空间 | 已有固定版读取可复用；不制造区域、不重复串行核权与整图摘要计算 |
| 文档 | 可靠对象关系、内容修订、页/节及适用性 | 手册对象关联/历史原文尚未完整接入 |
| 模型 | 自有资源/版本、内容摘要、节点身份与场景/实例/绑定修订 | 稳定源身份缺失仍标待核实；共享模型引用需当前项目使用权 |
| 趋势/报警 | 连接、源ID、对象映射版本、事件版本/时间窗、质量/水位 | Q-16暂无真实源；不能画假实时曲线或0报警 |
| 历史工单 | 项目、orderId、固定orderRevision、引用时的完整可读快照 | 当前诊断历史接口只提供诊断快照，不是完整工单历史；新增明确读取能力后方可启用固定工单卡 |
| 人工分析 | 自有笔记、假设/结果状态、作者及所引证据修订 | 不提升为源系统工程事实 |

源卡名称/摘要来自服务端当前有权的读取结果；保存不复制资料正文。恢复历史时仍重新检查当前权限。单份资料撤权隐藏名称、原标识、正文、区域及涉及的来源连线；自动抽取的摘要/引文也随来源隐藏。项目撤权隐藏整个会话与上下文，清理临时图片URL、异步请求和迟到结果。来源缺失/换版/超时分别占位，不静默换成最新文件。人工独立笔记受会话自身权限控制，不通过自动摘要重新引入已撤销资料。

## 3. 拟议服务协议与权限

沿用当前受保护 POST、`expectedSessionRevision`、完整 `projectRef` 及同源会话。下面表格是完整目标契约；首期实际字段、已实现路径和限制以[草稿契约§4](分析草稿存储与整组恢复契约.md#4-首期-http-与页面)为准。

| 拟议路径 | 输入要点 | 返回/事务语义 |
| --- | --- | --- |
| `/analysis-sessions` | 搜索/状态/对象/作者/时间、limit≤50、游标 | 只列有权会话；游标绑定主体、项目、筛选和快照，不泄露无权摘要 |
| `/analysis-sessions/create` | requestId、名称、可选工单上下文 | 由服务端当前主体成为owner，创建r1；工单入口先核对期望工单修订 |
| `/analysis-sessions/detail` | sessionId、可选固定analysisRevision | 当前有权快照、头修订、可用操作、来源有效性；不返回跨项目存在性 |
| `/analysis-sessions/save` | sessionId、expectedAnalysisRevision、requestId、snapshot | 快照、头指针、审计与幂等回执同事务；过期版本409，拒绝覆盖 |
| `/analysis-sessions/restore` | 目标历史修订、期望头版本、requestId | 从有权历史生成新修订，保留原历史；来源失效不替换/消失 |
| `/analysis-sessions/revisions` | sessionId、limit/游标 | 有界修订摘要，按需读取一份历史正文 |
| `/analysis-sessions/link-work-order` | 固定analysisRevision、orderId、expectedOrderRevision、requestId | 仅关联已保存分析版本；工单事件和引用同事务，不流转/消警/覆盖原诊断 |

每次读写均用当前会话、源项目授权和会话授权的交集。写前及提交前检查授权版本，变化必须回滚；丢失响应以同requestId核对，当前已撤权不得重放成功回执。同requestId不同内容409。源工程关系在服务端按受控引用重建/比对，不能相信客户端 `origin=source`。恢复、复制、关联和权限修改分别审计，不借“保存草稿”绕过约束。

首期坚持单owner编辑；读取需会话授权与当前项目权限同时满足。普通viewer不能保存，技术admin不自动成为领域专家。reviewer必须同时具有独立 `reviewHypothesis` 资格与该会话审阅授权；只审阅明确固定修订，不能顺带覆盖owner草稿。授权主体和配置方法在接入正式账户前需落实，预演角色不直接迁成真实授权。

分析状态为 `analyzing → awaiting_field_check / awaiting_expert_review → concluded → archived`，允许补证回到分析但保留历史。前三种是人工过程记录；结论需独立专家身份、逐项依据及当前权限。当前组件只允许前三种，后两种是只读/禁用设计状态。归档不删除修订；确认分析不确认工程身份、根因、源安装关系，也不关闭工单。
