## 2. 运营信息架构与页面

### 2.1 导航和共同框架

顶栏含用户原ONTOVis Logo、产品名ONTOVis、组织范围、全局搜索、会话入口和用户；左侧轻量 rail 只保留资产、分析、资料/设置入口。驾驶舱里“告警”是视图和抽屉，不再做一整套监控中心。

共享上下文使用完整ObjectRef、事件/时间窗、场景/模型/绑定修订与contextEpoch；详细字段见连续导航和首切契约。相机和图层是场景局部恢复状态；Canvas 的 viewport/卡片拖拽是会话布局状态。导航传稳定 ID，刷新从会话和读接口恢复，不能复制一整份旧对象作为事实。

| 页面 | 主任务 | 主区域 | 默认状态 / 首要动作 |
| --- | --- | --- | --- |
| P01 地球总览 | 从资产组合进入风场 | 地球+可收起风场列表 | 有权风场区域；选择风场→进入 |
| P02 风场驾驶舱 | 看异常、找到对象 | 场景主导；同页单一右侧检查区 | 简洁浏览；选报警→定位 |
| P03 设备与部件 | 理解故障涉及的部件和资料 | 局部模型+对象摘要 | 显示定位粒度；进入分析 |
| P04 分析Canvas | 组织证据、形成待验证假设 | 自由画布+右侧助手 | 已有最小证据布局；加资料/提问题 |
| P05 分析会话 | 恢复和审阅已有调查 | 紧凑可筛选列表 | 风场/对象/状态过滤；继续分析 |

### 2.2 P01 地球总览

首屏地球为主视觉，同页可收起风场列表约280px，浮层只显示当前选择、活动报警和更新时间。默认不旋转；点击风场先显示摘要，选择“进入风场”后按需加载。自然语言“进入青岚风场”走同一动作。

列表行：名称、区域、数据连接状态、重点报警、最后同步；未接入不能显示0报警冒充正常。少量点直接显示，规模大时聚合。地理位置未经核验时只提供列表入口，不在地球上放伪精确点。原型中的示意标记仅演示入口，不验证经纬度。

### 2.3 P02 风场驾驶舱

1920×1080 主稿：顶栏约56px，上下文条约56px，rail约64px；场景默认占内容区约70%，左对象导航默认可收起，右侧对象/报警检查区单选，宽约320px。1440下优先收左树，让场景与当前操作保持完整；检查区展开允许场景面积下降，但不被固定 KPI 卡片长期占满。

最多4项紧凑摘要：范围、活动报警、风速、温度。每值附来源时间；正常值用深灰，状态色仅用于异常。底部保留“图层、复位、检索、对话”最小工具。三种视图预设为简洁浏览、报警定位、系统查看；不是三套互不一致的主题。

对象树按功能/产品/位置切换单一视角，不把三种结构拼成一棵树。切换视角保留稳定对象选择，未归入该视角时显示明确提示。RDS、长设备名、动作描述换行，复制按钮提供完整码。

同页右侧一次展示对象摘要或报警列表；点击报警展开事件卡：原始严重性、规范级别、发生/恢复时间、源状态、映射状态。活动报警到达只更新徽标，不强制飞行打断分析。关报警图层后顶部保留“3条活动报警 · 图层已隐藏”等提示。

### 2.4 P03 设备与部件查看

相机围绕当前设备；显示几何质量“精确/简化/示意”和绑定质量“已核验/待核验/歧义”两个标签。选中是描边，告警是局部状态色+文字，避免二者覆盖。

操作：选中、隔离、恢复、隐藏遮挡物、透明。爆炸视图只有结构/分组元数据可用才启用。无法提供相应几何就禁用并给原因，不能用静态图的缩放伪装工程模型旋转。

无部件模型时定位上级，右侧展示“当前定位到风机级，暂无部件模型”。无任何模型时，主区域切对象、图纸、照片；证据与分析入口仍可用。AI 生成机舱图只演示这一区域的视觉构图，不作为维修指导或真实组件定位。

### 2.5 P04 故障分析 Canvas

顶行：会话名、风场、对象、事件、时间窗口、保存状态、返回驾驶舱。中央按阅读顺序组织“问题与事实 → 对象与资料 → 假设与验证”。右侧详情/助手316px（窄屏285px，Q-20当前稿），资料栏默认收起。原型可展示侧栏折叠的宽画布布局。

从报警进入Canvas即建立最小布局：报警卡、对象卡、已检索证据卡、缺口卡；检索尚未完成时用进度占位，不把空画布交给用户。初始不生成未证实的完整因果链。

对话与卡片双向联动：回答引用定位证据卡；卡片来源打开受权原文；原文标记当前页/章节/bbox；关闭后保留画布位置。卡片内滚动、文字选择、图纸缩放不应拖动外层节点；外层拖拽只从卡头，空格拖动背景，工具按钮及键盘也可适应视口。

自动排版尊重固定卡片，新卡放入对应栏目；布局操作有撤销，不撤销已发生的外部事实。保存含revision，冲突时显示“本地变更/服务器版本”，可另存副本或选择重新应用；不自动最后写入覆盖。

### 2.6 P05 会话列表

列：会话/对象、风场、事件发生时间、分析状态、负责人、最后更新、待办。可筛选风场、对象、作者、状态、更新时间；服务端cursor分页。空结果提示清除筛选；无权限项目不会因搜索结果摘要泄露。

会话状态是分析工作流，不是报警恢复/工单关闭状态。归档不删除历史引用。点击“继续分析”还原保存的时间窗与布局；来源撤权的卡片变成受限占位，不能显示旧缓存正文。

## 3. 卡片、关系与异常状态

### 3.1 九类卡片契约

| 卡片 | 可见摘要 | 展开/操作 | 缺失与限制 |
| --- | --- | --- | --- |
| 对象 | 名称、稳定ID/RDS、类型、审核状态 | 关联对象、定位模型、复制ID | 无模型不阻断分析 |
| 图纸 | 版本、页码、定位框、关联理由 | 共享图纸表面→授权原图 | bbox缺失降到页；不可开原文标未核验 |
| 文档 | 手册、适用型号、修订版、章节 | 原文片段与上下文 | 版本/型号冲突先确认 |
| 照片 | 图像、采集时间来源、对象关联 | 原图与标注区域 | 时间未知不能自动填当前时间 |
| 三维 | 局部视角、几何/绑定质量 | 返回设备与选中上下文 | 示意/无几何明确标签 |
| 趋势 | metric/单位、窗口、时区、采样方式 | 对齐报警、查看原始质量 | 缺段留白；无数据不画曲线 |
| 报警 | 原始事件、源级别、源状态、时间 | 打开源事件、定位映射 | 本地已读与源确认分开 |
| 工单 | 编号、时间、源状态、工作/验收摘要 | 源系统只读入口 | 文本关联未经审核标候选 |
| 分析 | 观察、假设、支持/反证、缺口、检查 | 追溯引用、专家决定 | 无依据不能标结论 |

每卡固定来源栏，包含版本、页/章节、更新时间与访问状态；正文不足以支持断言时不以“来源数多”替代证据质量。

### 3.2 必须展示的状态与响应

| 状态 | 页面反馈 | 可继续任务 |
| --- | --- | --- |
| 未接入 | “环境源未接入”，对应操作禁用说明 | 看对象、图纸、已有分析 |
| 无权限 | 不返回内容/数量；来源入口显示范围限制 | 申请由管理员处理，不能用AI绕过 |
| 空数据 | 已成功查询，但此范围无记录 | 调整时间/范围 |
| 过期数据 | 最后采样时间+过期状态；不标实时 | 看历史与重试 |
| 请求失败 | 来源级错误与重试，保留已有内容 | 其他来源仍可查 |
| 文件不存在 | 固定原引用，标原文缺失 | 看审计/寻找获准替代版本 |
| 资料版本冲突 | 并列候选与适用范围 | 用户明确选择后继续 |
| 未映射 / 歧义 | 禁止部件高亮；显示候选和待核实 | 可在来源事件级建分析但对象未定 |
| 模型缺失 | 对象/图纸/照片降级视图 | 进入分析 |
| AI超时 | 标明已完成检索/未生成分析，重试可用 | 资料浏览与手动编排 |
| 保存冲突 | 本地与服务端 revision 差异 | 另存或审核后重放 |
| 取消 / 断网 | “取消中→已取消”；未保存标记 | 已保存会话恢复，不自动重启写入 |

### 3.3 关键端到端流程

F01：同一视口地球选风场 → 摘要 → 可取消准备与镜头飞行 → 风场 → 同屏机组细节 → 返回恢复相机/范围。F02：报警 → 映射判定 → 可靠则定位，歧义则选择/核验 → 事件详情。F03：分析原因 → 创建会话 → 确认时间窗 → 并行最小检索 → 自动布局。F04：自然语言“把系统图、手册和工单放一起” → 受控查询 → 加卡+关联依据 → 油压缺失标缺口。F05：新增受权证据 → 支持/反证更新 → 保留旧假设 → 专家复核。F06：建议检查 → 引用适用规程、角色、安全前提和待反馈结果 → 本地工单草稿；首期到此结束。


## 4. 实施阶段与现有工单的衔接（2026-10-25）

用户所指的类Cognite Canvas对应本文P04「分析Canvas」与P05「分析会话」，属于运营端的“分析”模块。当前上线的是项目管理工作台及Q-49/Q-50演示工单；尚无可拖入多类资料、连线与保存分析会话的正式Canvas入口。工单中的只读来源参照图和本单诊断表不代表Canvas已交付，也不替代其需求。

| 顺序 | 队列与工作 | 当前状态与边界 |
| --- | --- | --- |
| 1 | Q-20：同一MagicPath冻结P04/P05页面和服务契约 | 已完成页面契约范围；九类合成入口、布局/笔记/关系、会话保存/冲突与工单关联预演通过，正式服务仍待Q-21/23 |
| 2 | Q-21：分析会话、固定引用和修订审计 | 待Q-20及Q-13所需存储边界；会话修订独立于场景和工单修订 |
| 3 | Q-23：九类卡片和证据联动 | 待Q-21；先接已授权图纸、模型、文档、照片、历史工单和人工分析，未接报警/趋势保持未接入，不等待真实源才开始静态证据工作 |
| 4 | Q-22/24/25：受限策略、助手与人工结论/草稿 | 后续；AI建议不直接关闭工单或确认根因，真实趋势/报警联调另依赖Q-16/17/18 |

既有WBS10–13的W7–W14是原相对阶段估算，不能当作当前承诺的日历日期。各队列完成条件以[统一任务队列](../plans/统一任务队列.md)为准；本次Q-20仅核销页面与服务契约范围，Q-21/23及真实资料/AI联调分别验收。

拟议衔接如下，尚未实现：

1. 工单提供“进入分析”入口，携带当前项目、工单ID/修订、选定对象、报警及时间窗口；恢复关联会话或由用户创建新会话。对象与工程资料仍从OntoBase按当前权限读取。
2. Canvas围绕同一问题组织资料与关系，可拖入图纸、模型、文档、照片及历史工单。关系区分源工程关系、资料关联和人工假设，不把用户画出的连线写成OntoBase工程事实。历史工单卡固定到被引用修订，只读展示并重新核权。
3. 本单已有假设、步骤与结果作为分析上下文使用，避免生成另一套互相覆盖的工单记录。Canvas保存自己的证据布局、推理过程与修订；“分析已保存”不等于“故障已处理”。
4. 人工选定某一分析修订后，将其结论与固定证据引用关联回工单；后端仍检查当前项目权限及工单期望版本，再进入现有排查、复核和关闭流程。历史分析保持原修订，不能被后续画布编辑悄悄改写。

因此，Canvas承担综合分析与证据组织，工单承担任务执行记录、复核和流转。两者共享来源与上下文，分别保存各自修订；目前演示报警与资料缺口不能视为真实现场消缺闭环。
