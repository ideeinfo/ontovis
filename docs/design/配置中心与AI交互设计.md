# 配置中心与 AI 交互设计

**ONTOVis V0.2 · 2026-10-20 · 设计提案。** 首期采用固定业务表单、明确权限和版本发布。设置不是浏览器偏好集合，也不是任意脚本、模型工具或工作流的搭建平台。

## 1. 配置层级和生效规则

| 层级 | 负责内容 | 谁可修改 | 生效规则 |
|---|---|---|---|
| 部署级 | 受控OntoBase连接、模型服务、凭据引用、资源配额、允许外发目的地 | 平台运维 | 环境配置/秘密管理；项目表单只选批准引用，不展示密钥 |
| 项目级 | 行业术语、工程项目映射、成员能力、数据源、模型/绑定政策、AI政策 | 项目管理员/有指定能力者 | 草稿→校验→预览→发布；权限变更需各服务即时校验 |
| 场景级 | 图层/地形/模型实例/视角/状态呈现/可见范围 | 场景编辑者；发布者另控 | 固定引用项目允许的资源，形成场景修订 |
| 会话级 | 所选对象、报警/时间窗、固定证据、Canvas与假设 | 有会话编辑权限的分析人员 | 乐观并发、版本保存；AI不能覆盖人工确认 |
| 个人级 | 面板宽度、主题、布局密度、默认展开、运动偏好 | 当前用户 | 可即时保存，不改变他人的场景和权限；不得覆盖必须显示的告警/代理标识 |

普通展示参数可按个人→场景→项目→部署默认逐级取值；**权限、外发、工具、限额取允许集合交集或更严的上限**，不是“最具体配置覆盖一切”。某层没有配置时显示继承来源；项目无法放宽部署禁止的操作。所有页面提供“有效配置”视图，区分默认、继承、覆盖和被策略限制。

行业模板只预填术语与有限配置，不改变身份、证据和权限语义。首期风电配置可选“机组/控制柜”，通用仍叫设备/子设备；油气、铁路可使用不同项目术语但不产生新的代码插件或自动宣称行业流程适用。

## 2. 导航与页面布局

顶栏：原始ONTOVis Logo、当前项目、场景/环境标签、搜索、帮助、用户。左侧主导航：运营场景、分析Canvas、会话；管理入口：项目配置。配置区域采用左224px分类、中心可伸缩表单/列表、右约320px校验摘要；1440px时右栏可收起，1920px完整展示。工程对象名称/标识允许换行，关键身份不可截断丢失。

| 配置入口 | 页面核心内容 | 关键操作与状态 |
|---|---|---|
| 项目与访问 | 工程项目连接、术语、时区/单位、成员能力 | 核验连接、查看有效权限、待绑定项目、无访问权限 |
| 模型库 | 模型列表、版本、处理进度、来源、身份质量 | 上传、查看报告、预览、创建新版本、归档；失败可重试 |
| 绑定工作台 | 左构件树/队列，中模型，右工程对象和证据 | 提议、消歧、审核、撤回；未核实UID禁发布 |
| 设备层级 | 左物理树，中分页子设备，右身份与定位路径 | 查询/搜索、定位所属柜体、跳到OntoBase维护；不在此复制可写树 |
| 场景与可视化 | 左图层/坐标/样式，中预览，右质量摘要 | 草稿预览、校验、发布、回滚；无真实数据时准确空态 |
| 数据与告警 | 连接健康、源标识映射、单位、时间质量、聚合方式 | 未映射队列、质量预览、断线/缺口、模拟/实时切换权限 |
| AI策略与交互 | 左策略分组，中固定表单，右有效权限和上下文 | 只读工具、运行预算、证据规则、上下文预览；不展示密钥 |
| 证据与审计 | 发布差异、绑定审核、模型/策略版本、运行追溯 | 筛选、查看来源、导出脱敏记录；权限内操作 |

绑定工作台提供三种布局偏好：均衡（树240/详情340）、模型优先（可收起树/详情）、证据优先（右侧证据展开）。这是个人展示偏好，不生成三套产品或影响真实绑定。

## 4. 配置数据与发布工作流

首期按真实需求使用 `project_settings`、`scene_revisions`、`source_connections/point_mappings`、`agent_policy_revisions` 等固定结构，数据库保存结构化JSON并以版本化schema校验。不建设用户可编程schema、通用配置元模型或任意脚本函数。

步骤：编辑草稿 → 服务端字段与引用校验 → 查看有效配置/差异 → 使用明确标识的预览数据验证 → 选择发布范围 → expectedRevision原子发布 → 审计与回滚入口。配置变更应显示哪些场景/绑定/会话受影响，不能保存一个颜色设置就重跑所有模型。

分三类生效：

- 个人面板布局即时生效，仅本人；出错可重置默认。
- 场景/数据/AI配置经发布后供新视图/新run使用；已有会话和运行固定自己的版本，不中途切换模型或提示模板。
- 授权收紧、源凭据撤销、安全外发禁令即时生效，正在运行的工具重新检查，不能等下一次发布；被撤权任务不得提交迟到结果。

回滚是新的一次受控发布，保留原版本与原因。回滚到旧模型/旧策略前重新检查当前对象、权限和制品是否存在；回滚不能恢复已经撤销的授权。凭据仅保存 `credentialRef`，不进入导出JSON、前端状态或审计差异。

复制配置到新项目只迁移白名单非敏感字段，并进入草稿；工程对象、数据源和模型资源引用全部重新解析。首期导入导出仅用于固定模板的项目迁移，不承诺跨版本自动无损还原，也不携带绑定审核结论。

## 5. AI运行结构与可配置边界

继续采用一个会话编排器＋固定领域工具。LLM解释意图、提出读取计划、组织证据和生成待核验假设；权限、身份、时间序列计算、单位转换、绑定发布与配置生效由确定性代码负责。首期不需要自治Agent群或可上传任意代码的技能市场。

```text
自然语言 + 当前选择/事件
  → 服务端授权与上下文快照
  → 固定策略/预算/工具允许集合
  → 有限只读查询与确定性计算
  → 带引用的观察、假设、反证与缺口
  → 结构校验/证据校验/上下文版本检查
  → 可撤销的导航/Canvas建议 + 人工判断
```

### 5.1 上下文配置

`ContextSnapshot`需保存project范围、当前场景与模型/绑定版本、selectedObjectRef、实际locatedObjectRef、locationMode、物理层级版本/时点、事件及分析时间窗、固定资料版本、会话revision、contextEpoch和数据质量摘要。上下文由服务端重新查询，浏览器提交的对象名称/父级不作为工程事实。

“带上父设备”默认最多取到已确认物理路径，不能改用名称分组；“带上子设备”默认关闭，用户开启时只取一层、最多50条已授权摘要（建议值），并明确是否截断。大范围趋势/计数使用确定性聚合工具；不靠LLM看到不完整分页后猜总数。

默认将所选子设备与其柜体定位分开呈现，例如：`分析对象=控制器；空间定位=CN2柜体；精度=祖先代理；柜内安装坐标=未知`。AI不得因柜体高亮就声称控制器位于柜门左侧或拥有精确几何。

### 5.2 工具与动作

| 类别 | 首期允许 | 约束 |
|---|---|---|
| 查询对象/层级/关系 | 有界读取与消歧 | 物理树、电气图、RDS视角分开，服务端注入scope |
| 检索图纸/手册/照片 | 授权文件版本与定位 | 资料若未接入明确缺失；新照片上传不由AI工具补建 |
| 查询告警/趋势 | 固定窗口、源质量、受测聚合 | 不编造缺口、不自行变更单位或源阈值 |
| 导航 | locateObject受控结果、返回视角、选中对象 | contextEpoch已变化则不把用户拖回；无法定位时保留资料入口 |
| Canvas编排 | 允许类型卡片、位置/连线建议、撤销 | 固定卡与人工结论不可静默覆盖；先权限和revision校验 |
| 绑定辅助 | 解释属性匹配候选与缺失证据 | 仅建议；不确认父子、不批准绑定、不发布模型 |
| 外部控制/写入 | 首期不开放 | 不启停设备、不改SCADA参数、不发外部工单、不直接写工程事实 |

不接受模型输出的JavaScript、SQL、Cypher、任意URL或工具注册代码。业务人员可选择批准的提示模板与有限语气/输出语言，不修改系统权限提示、检索授权或执行规则。

### 5.3 交互行为

- 页面常驻当前对象/范围/事件时间，用户可打开“本次上下文”检查模型、绑定、父路径和来源。
- 歧义先给少量候选让用户选；不能用“我猜你要的是”自动切换机组。
- 流式显示步骤、已找到资料与草稿；正式引用校验完成后才保存为分析结果。不给用户展示内部思维链。
- 状态至少包括等待选择、读取证据、整理、校验、部分完成、失败、取消、版本冲突。按钮“停止”要有后端回执；断网不冒充已取消。
- 等待用户与执行预算分开；初始等待失效期建议24小时。恢复时校验权限/版本，剩余工具预算不重置。
- 对象/场景切换只影响新上下文；用户固定的会话证据不被新选择抹去。进入另一项目时必须重新授权。
- 原因假设需区分观察、支持证据、反证、缺口和下一步核验；“已确认根因”必须由具备资格的人在独立动作中确认。

### 5.4 策略试运行与验收

AI配置页右侧显示有效策略：选定模型引用、被允许的资料范围、工具清单、最大调用和外发限制。首期离线夹具测试与人工验收样例不少于：正常证据、缺资料、同名设备、代理定位、过期数据、越权引用、上传文档提示注入、取消、并发版本、无原始历史。

真实试运行需明确选择测试项目和只读样例，记录策略/提示模板版本、来源覆盖、引用有效率、工具失败/超时及预算。原型中不连接模型，试运行入口显示“待接入”，不返回伪造回答。模型厂商“可调用”不等于工程分析已验收。

|---|---|---|---|
| `scene_editor` | 场景放置、视角、地形/影像资源引用、状态样式草稿 | 项目管理员，在平台允许范围内 | 由`scene_publisher`发布；编辑者不能跳过坐标/绑定校验 |
| `data_editor` | 已批准连接的测点映射、单位/质量、告警呈现规则草稿 | 项目管理员，另核源系统访问 | 经业务规则复核后由项目配置发布者发布；不写源系统阈值/凭据 |

项目配置发布者是明确的`publish_project_config`能力，可与场景发布者由同人兼任；模型编辑者不因此获得数据映射编辑或AI策略发布权限。用户实际能力由后端返回并在每次写入检查。

角色是可组合能力集合，不等同现有OntoBase `admin/reviewer/viewer`枚举。首期只实现必要的固定能力，不建立通用ABAC策略语言。小团队可同人兼任编辑/审核/发布，但每次动作与依据独立留痕；需双人审阅的客户策略作为项目限制，不能UI假装满足。

## 7. 空态、异常与渐进范围

必须设计的状态：未连接OntoBase、无项目权限、模型处理中/失败、没有稳定ID、候选歧义、工程对象缺失、柜内设备无几何、层级未知、模型换版失效、坐标未核验、DEM/影像覆盖缺口、监测断线/过期、模拟模式、策略未发布、AI无资料/部分完成、发布版本冲突、撤权中断。

首期完成项目、GLB模型/版本、绑定/层级读取、场景基本设置、一个实时源、受控AI配置和审计。后续再评估：原生IFC/CAD转换、自动版本配准/大规模拆合、全行业模板库、自定义着色脚本、任意工具/提示词编辑器、多租户自助开通、多人实时协同、远程控制、照片完整归档。它们不会因“有配置中心”而自动纳入本期。

## 8. 公开目录与连续导航配置增补

- 部署/管理员：固定来源启用状态、批次检查周期、许可/署名、成功版本与失败水位；GEM文件版本、REPD CRS核验状态、质量阈值。凭据和内部地址不出现在运营UI，不能配置任意抓取URL。
- 项目：目录项目/分期到工程项目的审核链接；公开目录与私有工程的能力边界；AOI、真实机位、水平/高程基准与用途精度门。
- 场景：全球/风场/机组相机书签、近景锚点/朝向/比例、模型与低模对应、LOD/资源预算、地形/影像覆盖、有效发布版本；未核验变换不能发布为精准定位。
- 用户：检查区、图层、镜头速度与减少动画、返回偏好；系统reduced-motion优先，不能覆盖来源/代理/过期/缺模型状态。
- AI交互：明确目录/工程上下文，导航提交稳定引用和contextEpoch，由同一确定性导航控制器处理；后台告警和旧AI回答不能抢镜头，不向模型开放相机矩阵/地图URL/任意脚本。

原型参数只是演示；生产发布、权限及持久化继续遵循本文既定固定表单/版本合同。详细规格见[采集](风场数据库与数据采集设计.md)、[连续导航](全球风场风机连续导航设计.md)。
