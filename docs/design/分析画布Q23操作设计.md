## 1. 本次要交付什么

用户应能从一条报警直接开始分析：系统带入问题和相关对象，推荐有依据的资料；用户把图纸、照片、三维、趋势及历史工单放在同一画布中查看，记录原因假设、支持与反证、排查结果，保存后把明确版本关联回工单。

画布负责综合分析与证据组织；工单负责排查任务、执行记录、复核与状态流转。两者互相可达，但不会相互静默覆盖。保存分析不会关闭工单、确认根因或改变源工程关系。

## 2. 页面结构与首屏

全局顶栏仍为“分析画布 - 项目名”；保留项目导航、原Logo、灰绿双主题、13px正文和11px说明。进入项目后才能使用分析画布。

| 区域 | 展示与操作 |
| --- | --- |
| 分析头栏 | 返回列表、分析名称、保存状态/修订；右侧“保存”“关联工单”“更多” |
| 上下文条 | 当前报警、对象、时间窗；信息过长折叠为“分析范围”，点击查看完整内容 |
| 左侧资料栏 | 约280px；“本次推荐 / 项目资料”；类型筛选、已加入状态、推荐理由；可收起 |
| 中央画布 | 默认按“报警与现象—对象与资料—假设与排查”组织，用户可自由移动；不是不可修改的固定流程图 |
| 右侧检查区 | 约316px；选中卡片时显示详情、关联资料或笔记编辑，一次只开一个面板 |
| 画布工具 | 选择、平移、添加笔记、关系、分区；撤销/重做；缩放与适应全部放在角落 |

有效画布宽度小于800px时，左右面板互斥展开；资料详情用可关闭的覆盖面板。大图/模型可全屏，关闭后回到同一画布位置和选中卡片。打开侧栏不重新排版或重置视角。

主工具栏只保留常用操作，版本、来源完整身份和操作记录按需展开。当前未接AI时，不放一个无法工作的聊天框占据右栏；助手接入后复用该栏。

## 3. 四种进入方式

| 入口 | 用户动作 | 系统处理与落点 |
| --- | --- | --- |
| 数据与告警 | 选中报警→“进入分析” | 带入事件身份/版本、故障码、映射对象、发生区间和模拟来源；自动推荐相关对象与资料 |
| 工单 | 当前工单→“进入分析” | 带入本单固定修订、已有排查记录和报警上下文；有明确关联时优先打开该分析入口 |
| 对象/照片/图纸 | 更多→“加入分析” | 选择本人当前分析或新建；沿用当前资料位置，不要求重新搜索对象 |
| 分析画布列表 | “新建分析”或“继续分析” | 新建可先选一条报警/对象，也可空白开始；继续恢复已保存布局与来源 |

“进入分析”是明确的开始动作。已有本人同事件分析时，默认继续；没有同事件分析但有相同故障码历史Canvas时，按§3.2自动调入可用历史。无匹配项时使用最小布局新建，系统名称可直接修改。不同日期、设备、事件各自保留分析身份，不因为同码而混成一份记录。

只查看报警、展开推荐或浏览资料不创建会话、不登记来源。开始分析后先建立会话，再按需登记所加入的固定引用；失败或重复点击使用同一请求回执恢复，不生成多份空分析。只读账号仍可查看有权资料；保存与工单关联使用服务端返回的操作能力，不由前端猜测。

### 3.1 新分析的最小布局

从报警开始时，自动放入：报警卡、唯一映射的主对象卡、已有的1～2张关键趋势卡、一张待填写的“排查记录”笔记。正常为4～5张；从工单开始可再带入本单快照，最多6张初始卡。

没有可靠对象映射时，先放报警和笔记，左栏显示待确认对象候选，不伪造对象卡。暂无趋势时只保留现有卡和一条缺源说明。初始笔记不自动填写“已诊断”或预设根因。

图纸、照片、三维先在推荐区出现；用户点“加入”或拖入时才创建卡片。首屏不自动下载所有原件或启动3D。

### 3.2 同故障码历史Canvas自动调入

系统先在**当前项目、当前账号可读范围**内查历史，不让用户自行翻分析列表。首期沿用现有本人会话权限；其他人的分析只有在后续明确授予共享读取权限后才可出现，不因项目管理员身份自动开放。

| 情况 | 默认操作 | 用户可做的调整 |
| --- | --- | --- |
| 同一事件已有分析 | 自动恢复最近的本人分析及保存视图；有固定工单关联时显示关联修订与最新修订的区别 | 新建另一项、查看旧修订 |
| 同码新事件，存在同一对象的历史分析 | 自动调入最匹配的已保存Canvas，建立本次独立分析；顶部说明“参考了某分析 · rN” | 换一个历史案例、只看历史、使用空白布局 |
| 同码、同适用设备类型/型号/分支，但对象不同 | 自动载入历史画布供对照；可靠映射的资料可用于本次，其余保留在历史分区 | 选择其他候选、手动加入本次对象资料 |
| 仅故障码文字相同，语义/型号或来源命名空间不明 | 自动展示历史参考及匹配原因，不能把其旧对象、定位和工程关系自动认作本次对象 | 选定适用候选或继续当前最小布局 |
| 无可读历史、历史不可恢复 | 立即使用当前最小布局；有可读缺口时给出说明 | 继续本次分析，不等待历史读取完成 |

排序采用同事件、同对象、同适用型号/分支、同码其他候选的确定顺序，再按最近更新时间排列。故障码以源含义为准，保留代码命名空间及必要适用性；不能把不同系统中碰巧相同的编号视为同一故障。首批最多返回3个历史摘要，按需翻页，默认载入最佳候选的一个固定修订。

调入后的处理规则：

1. **布局可直接复用**：保留历史分区、卡片位置、固定状态、人工关系和检查结构；用户无需重新搭画布。只因新卡加入做局部避让，不全面重排。
2. **本次事件独立**：本次报警、时间窗、趋势和工单形成“本次调查”分区。历史报警、趋势、结果留在“历史参考”分区，标明事件时间及修订；不直接改写旧卡时间来冒充本次数据。
3. **记录和结论保留出处**：历史笔记/结果以带原分析修订的只读参考呈现；可复制成可编辑的本次笔记，保留继承出处。复用的检查清单从“未执行”开始，历史完成状态和结果不自动成为本次结果。
4. **对象和资料分别判断**：相同固定资料可共用文件传输；新会话的来源句柄由服务端重新登记。旧设备的照片框、模型节点和线路关系不直接套到新设备；无法可靠对应的保留历史参考，推荐本次资料。
5. **原件保持**：原历史Canvas及工单修订不变；本次保存产生独立记录，记录来源分析ID/修订、来源卡及复用时间。旧资料不可读时保留可解释占位，不退回当前文件冒充历史。
6. **可见、可撤销**：自动调入后有轻量提示“已参考历史分析，可撤销”；不额外弹必经确认框。用户已经编辑后到达的历史结果只提示可用，不覆盖当前画布；重复打开同一事件不重复导入。

历史匹配需服务端按项目/主体、事件和规范故障码检索索引，不能下载全库Canvas再搜索。先读候选摘要和布局，照片/模型继续按需加载；不重放历史对话指令，不自动执行历史工单操作。

若历史已接近50卡上限，先自动打开完整历史参考，同时建立本次最小布局，再让用户选择需要继承的部分；不静默截断原历史或突破容量上限。

## 4. 自动推荐：默认围绕本次报警

### 4.1 推荐依据与顺序

推荐由确定的源关联和已登记的报警规则开始，不依赖LLM回答，也不加载全项目对象后在浏览器筛选。

| 优先级 | 对象/资料范围 | 用户看到的推荐理由 |
| --- | --- | --- |
| 1 | 当前事件直接映射的对象、已有工单明确引用的对象 | “本次报警对应对象”“本单排查对象” |
| 2 | 本故障码、该项目及适用分支的参照链节点 | “温度信号采集模块”“报警反馈回路”；同时保留规则的演示/适用性状态 |
| 3 | 已登记物理归属的上级设备/柜体、直接相连对象 | “已登记所属柜体”“信号链相邻对象” |
| 4 | 上述对象的直接图纸、照片、测点、模型绑定 | “该对象的图纸”“该对象已有照片标注”；型号共用资料单独标识 |
| 5 | 同一对象的历史工单；必要时补同故障码候选 | “同一对象的历史处理”“相同故障码，适用性待核查” |

每个推荐项给出**一条简短理由**；展开可看“报警→对象→资料”的来源路径、版本和适用性。不显示没有依据的百分比置信度。名称相似、位号前缀相同不等于已建立工程关系。

### 4.2 默认呈现

- 首屏推荐对象最多8个，资料最多12项；按相关度分组，已加入的标“已加入”。这是展示预算，不代表项目只有这些数据。
- “直接关联”在前；“相关候选”折叠在后；没有可靠关系时显示具体缺口。
- “加入推荐资料”先展开一份小清单，默认勾选直接相关且可用项；用户可取消，随后一次加入。重复点击相同来源/版本/位置时定位已有卡，不重复下载或创建。
- 主对象旁有“查看关联资料”；用户可一次加入对象及所选资料，保留来源关系。
- 仅在需要扩大调查时点“扩展相邻对象”或“搜索项目资料”。先读一层关系；显式扩展最多到两层，每次有界返回，不递归遍历整个工程图。
- 推荐列表滚动/分页不改变已加入卡片。已加入但被用户移除的项不会在刷新时自动塞回画布。

### 4.3 Demo-PDS的具体差异

| 报警 | 默认推荐与分析重点 | 不能自动推定的内容 |
| --- | --- | --- |
| 13001 温度高 | CN1-1B4温度传感器、相关采集模块/线路、CN1机舱动力柜、现有图纸/照片；传感器与独立参照温度对照 | 测试预设偏差不等于现场根因；X91跨页链未闭合 |
| 13002 温度低 | 可共用同一温度链资料，带入本次低温事件及不同趋势；排查记录独立 | 不复用13001的结论、选择状态或工单记录 |
| 13003 浪涌保护反馈异常 | 按该码对应的器件、模块地址及反馈信号推荐 | 无照片区域时保留缺口，不改推温度传感器充数 |
| 13004 主断路器反馈异常 | 按该码对应的开关、供电/反馈/过流测点推荐 | 模拟断开不等于实际过流跳闸，不复用温度原因树 |

CN1为机舱动力柜、CN2为机舱信号柜。CN2只在本次故障或显式扩展存在关联依据时加入，不能每个故障都同时放两柜。105A3的IX.1/IX.2保留为模块内地址，不生成虚构通道对象。

### 4.4 切换、刷新与缺证

推荐绑定当前项目、事件/工单修订、来源版本和调查对象。切换项目或事件后取消旧请求；迟到结果不出现在新页面。来源换版显示“关联资料有更新”，由用户决定加入新版本，不静默更换旧卡。

推荐服务部分失败时，已知主对象和本地笔记仍可操作；失败分组可单独重试。没有匹配关系显示“暂无已关联对象”，保留报警和项目资料搜索；不会先要求做全链路资格核验才能浏览报警、趋势或照片。

## 5. 画布的基本操作

| 操作 | 明确行为 |
| --- | --- |
| 单击卡片 | 选中，显示轻量工具和检查区；不拖动、不重新加载原件 |
| 拖动卡片 | 从标题栏空白/拖动手柄开始；标题中的资料名称仍可点击打开 |
| 多选 | Shift追加选择；空白处框选；只移动选中的未固定卡片 |
| 缩放卡片 | 九类资料块全部支持鼠标拖拉四边和四角调整大小；拖边改宽或高，拖角同时改宽高；内部图像/模型不拉伸变形，原始坐标不变 |
| 平移画布 | 平移工具，或空格+左键拖动背景；手型提示清楚 |
| 缩放画布 | 背景滚轮以指针为中心，25%～150%；提供缩放按钮、100%、适应全部 |
| 照片/图纸内操作 | 鼠标在内容区域时滚轮缩放内容、左键平移内容；事件不传给外层画布；文字区域仍可选择/滚动 |
| 固定 | 锁定卡片位置和大小；卡内查看/缩放仍可用；整理布局绕开固定卡 |
| 分区 | 用“现象”“资料”“排查”等可改名框组织卡片；分区不代表工程关系；最多10个 |
| 整理布局 | 按当前分区整理未固定卡片，处理重叠；整次操作可撤销，不自动打乱用户已有布局 |
| 移除 | 只从分析移除卡片及其连线，不删除原对象、文件、模型或工单；可撤销 |
| 撤销/重做 | Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z；至少保留20次本地内容/布局动作；不撤销源业务操作或已提交的工单关联 |
| Escape | 先关闭当前菜单/预览/连线操作，再退出选择；不会突然丢弃整份分析 |

单会话沿用50张卡片、100条关系上限；临近上限时只提示剩余数量。长名称可换行。大图、3D和编辑表单均可独立展开；不会把外层画布放大到150%当作照片细节放大。

### 5.1 更多与右键菜单

遵循[统一菜单规范](列表与上下文菜单规范.md)：省略号与右键使用同一动作、图标和禁用理由，支持键盘、Escape、焦点返回及边界避让。

- 来源卡：打开资料、查看相关对象/资料、定位引用、复制标识；固定/取消固定、复制视图；最后一组“从画布移除”。
- 笔记卡：编辑、建立关系、固定/取消固定、复制笔记、从画布移除。
- 人工连线：编辑关系类型/依据、跳到起点/终点、移除关系；源工程关系只提供查看依据与隐藏。
- 画布空白：添加笔记、添加分区、展开推荐、整理布局、适应全部。

“复制视图”用于同一图纸不同页/区域或同一资料不同观察视角，共用固定来源，不复制文件。“移除”不用源资源的“删除”措辞。

### 5.2 每个资料块均可鼠标拖拉缩放

用户补充明确要求：对象、图纸、文档、照片、三维、趋势、报警、历史工单、分析笔记九类资料块都采用相同的边框缩放交互；不能只有图片或笔记可缩放，也不能只提供全屏按钮替代。

- 选中后显示四角控制点；鼠标靠近四边时出现对应方向的缩放指针和足够宽的命中区。按住左键连续拖拉，尺寸实时跟随；拖标题移动整个资料块，操作互不混淆。
- 四边分别调宽或高，四角同时调宽高；默认外框宽高自由调整，按住Shift可临时保持外框比例。尺寸有可读下限，不能反向拖成负尺寸或让标题、操作入口消失。
- 文字/表格自动换行或滚动；趋势随容器重绘；照片、图纸保持原图比例；三维只调整视口尺寸与相机宽高比，不重置已有观察方向。调整外框不改变原件、标注坐标或模型几何。
- 图片/图纸内部滚轮缩放与左键平移、三维内部操作继续独立；拖边框时只改资料块大小，不同时缩放画布或拖动内容。
- 拖拉按照当前画布缩放比例换算，25%、100%、150%下均跟手。关系线端点跟随新边界，其他资料块不被自动挤走；发生重叠可由用户整理布局。
- 来源内容只读不妨碍有权用户调整其资料块；固定卡片保持位置/尺寸，先取消固定即可调整。读取中、失败或缺源卡也可调大小，内容到达后保留用户尺寸。
- 一次拖拉结束计一次可撤销动作；保存后刷新、重登及历史Canvas复用都恢复对应尺寸。拖动过程中不逐帧写后端、不重复请求原文件或重建3D场景；按帧更新可见内容，沿用§11性能目标。

### 6.1 图纸和照片中的对象

点击已有区域后显示小型对象摘要：名称、定位粒度、关联依据，以及“加入对象”“查看相关资料”。关联到多个对象时展示候选及来源，不替用户任选一个。

“定位引用”将卡片带入可见范围并打开指定页/区域；只高亮有来源依据的区域。缺区域时打开整页/整图并明确告知，不以居中显示冒充精确定位。关闭预览保留卡片位置及局部视角。

照片沿用OntoBase的整图100%基准、50%～1600%范围、指针锚定滚轮及左键平移。默认聚焦已有标签；选中框采用清楚的描边和对象名称。验收时以同一照片与OntoBase对照缩放和落点，并检查最大视图下的标签可读性；不能扩大真实标注范围或通过合成细节制造清晰度。

同一照片被多个对象引用时，共用一次内容读取和解码，各自保留定位区域。照片名称点击后立即展开承载区域和读取反馈，避免没有任何响应的空白等待；无需再次点“核验”才能看图。

### 6.2 三维与物理定位

模型卡固定资源版本；只有已有场景实例/绑定可核对时，才能显示对应安装对象。选中模型节点可回到对象卡；对象没有子部件几何时，只定位已绑定上级并注明粒度。

启动另一张3D卡时，前一张保留视角预览、停止渲染并释放活动资源；不会同时创建多个WebGL渲染循环。用户返回可恢复其视角。文件过大可取消加载，继续其他证据操作。

## 7. 原因假设、证据关系与排查记录

### 7.1 如何建立和修改原因图

从报警卡点“添加假设”，或添加一张“原因假设”笔记，输入可修改标题和说明。选中两张卡，点连接手柄/“建立关系”，选择关系类型并填写依据；可拖线，也可用无拖拽的表单完成。

| 关系 | 方向约定 | 呈现与编辑 |
| --- | --- | --- |
| 工程归属/连接 | 按源关系实际方向 | 只读来源关系，实线及文字标签；只由服务端有权结果产生 |
| 资料引用 | 笔记/问题→资料 | 人工关系，可编辑依据及具体页/区域/时间锚点 |
| 原因假设 | 假设→待解释的现象 | 虚线；不被画成已证明因果 |
| 支持证据 | 证据→假设/判断 | 显示“支持”及理由；可展开原位置 |
| 反证 | 证据→假设/判断 | 显示“反证”及理由；不能只靠红绿颜色区分 |

新建关系不能为空依据、自连接或重复相同起止/类型。解除源关系的显示不改变OntoBase；人工关系不会写回工程知识图谱。

### 7.2 一条排查记录

编辑区分为“观察现象”“原因假设”“待做检查”“检查结果/下一步”，均可修改；支持把已有卡片拖到证据栏，生成固定引用而不是复制大段源正文。正文合计沿用每笔记4000字上限。

原因假设的工作标记可为“待核查 / 正在核查 / 暂不采用”，另用证据关系表达支持与反证；这些标记只记录个人分析进度。改变为“暂不采用”需写理由，原记录和连线仍可追溯，不删除反证。

分析整体只提供“分析中 / 待现场核查 / 待复核”。不提供“确认根因”“批准结论”按钮，不在页面标题、保存按钮和每张卡上加“草稿”字样。用户可以记录自己的分析结果，但不会因此生成工程确认。

## 8. 时间窗与比较

初始范围来自当前事件或已保存分析；模拟窗口准确显示为2026-10-25 08:00—08:03（Asia/Shanghai），可切UTC显示。不能默认为“现在”或把回放写成实时监控。

1. 报警发生/恢复时刻以竖线标在相关趋势上；鼠标游标联动同时间窗的可见趋势，浮层列出时间、数值、单位和质量。
2. 图内选择小区间是局部查看，不自动改变其他卡的固定证据；点“应用到分析时间窗”才明确更新。
3. 新时间窗需要新趋势来源引用时，保留旧固定引用；准备成功后一次替换受影响卡。部分来源不支持所选时段时列出缺口，不伪造历史曲线，也不改变无关照片/图纸。
4. 最多选择4张同量纲趋势做并排比较；不同单位分别保留坐标，不用双轴制造相似性。对照查看不是新的权威来源，保存的是引用和查看范围。
5. 第90秒bad/null保留断点；模拟事件发生/恢复可回放，暂停/拖动只改变观看位置，不更改事件状态或生成工单动作。

Q-17/18接入实时流后再增加“跟随最新”；本次不放一个实际上只刷新固定数据的“实时”按钮。历史分析始终保留其固定时间和来源。

## 9. 保存、版本、失效与退出

“保存”一次保存布局、笔记、人工关系、时间范围和固定来源引用；源原件仍留在原系统。系统反馈为“未保存 / 保存中 / 已保存 · rN / 保存失败”。已保存不代表已确认。

- 标题、笔记、连线、卡片增减和布局变化计为修改；单纯查看原文不计。个人平移/缩放不反复弹未保存提醒，点击保存时附带视口；需要仅保存打开视角时使用“保存当前视图”。
- 保存期间保留可读画布，不阻塞照片浏览；写入动作串行处理，同一请求重试不重复创建修订。结果不确定时先核对原请求，避免“另点一次”产生第二份。
- 服务端有新版本时保留本地修改，显示具体冲突：名称、卡片、笔记、关系变化。允许另存副本或明确放弃后重读，不用最后一次写入覆盖。
- 历史只读打开；“恢复为新修订”追加版本，不覆盖旧修订。复制分析必须由服务端按当前权限重新登记本人新会话的引用，不能直接复制旧会话专属句柄。
- 来源受限时隐藏原名、标识、正文、区域及来源连线；源相关自动摘要同步隐藏。项目撤权时退出该分析并清除临时图像/迟到请求。独立人工笔记沿自身会话权限处理。
- 资料缺失、权限受限、版本变化、读取超时分别呈现；缺历史原文不悄悄打开最新文件。“改用当前版本”是明确的新引用操作，保存后才成为新分析修订。
- 单张资料暂不可用不阻断保存其他笔记和布局；已登记来源保留固定引用及缺口占位。新增但未登记成功的项明确显示“尚未加入”，可重试或移除，不能伪装已保存的证据。
- 离开存在修改的分析时，仅一次提供“继续编辑 / 放弃修改并离开 / 保存并离开”；跨项目时执行同一规则。

## 10. 与工单衔接的闭环

### 10.1 从工单进入

工单的来源参照图可提供进入分析的上下文；已有排查表作为该工单固定快照可见。画布中可以另行修改假设、组织证据，但不在后台同步改写本单字段。

已关联分析显示分析名称、固定rN、关联时间及入口。用户打开的是该固定版本；本人可再选择“继续最新分析”，避免误以为工单已经引用最新内容。

### 10.2 保存并关联回工单

1. 点“关联工单”；默认原工单，也可在当前项目内选择有权工单。
2. 有未保存修改时显示“保存并关联”，先保存成功，再关联得到的确切修订。
3. 小面板列出工单号、分析名/修订、准备关联的分析记录摘要；操作名为“关联此版本”。
4. 成功后显示“已关联到工单 XXX · 分析rN”；返回工单可看到同一固定版本。若关联失败，明确“分析已保存，工单尚未关联”，可重试，不伪装全部成功。
5. 工单出现新版本时展示变化并刷新关联目标；不能覆盖他人排查或状态。分析之后保存rN+1，工单仍引用rN，只有再次关联才更新入口。

本批关联证据与分析修订，不自动覆盖工单诊断表、派单、关闭或消警。执行人可沿已有工单编辑/排查/复核流程继续操作。模拟测试能走通软件流程，但不能据此称真实现场故障已消除。

## 11. 性能设计与验收目标

优化对象是**点击后能否开始操作、何时看见内容、何时能看清局部**，不是只看接口返回时间。所有指标在实施阶段实测，本稿不预先宣布达标。

### 11.1 读取与请求预算

| 环节 | 实施要求 |
| --- | --- |
| 首屏 | 先绘制已有报警摘要与空壳卡片；推荐/摘要/轻量趋势并行到达，逐块可用；禁止等待全部原件再显示 |
| 推荐 | 按报警的已知映射和有界邻域查询；禁止下载全项目对象、全部工单或全模型库后筛选；独立于文档/照片资格核验 |
| 历史复用 | 推荐聚合中附带少量同码历史摘要；按索引读一个匹配Canvas；继承布局不下载全部历史原件，不把旧图像重复登记成新文件 |
| 聚合 | 增加本页面需要的推荐/摘要批量读；首次核心信息以1次聚合读取为目标，最多2次轻量业务读取；新会话创建/引用登记是独立写入，不虚报成零额外请求 |
| 来源登记 | 推荐预览不登记；加入多张资料时批量复用当前上下文和重复来源；避免逐卡串行的N次相同授权、对象解析和内容下载 |
| 并发 | 同一页面轻量源读取最多4个并发；大文件最多2个；用户刚点击的资料优先，取消/离开后中止旧任务 |
| 图片 | 点击或进入可见区后按需取一次原图；同版本同内容请求合并、解码复用；不在浏览器重复计算整图摘要；不把压缩预览设成看原图的门槛 |
| 三维 | 进入活动视口才加载几何；单活动渲染器，隐藏停止；释放旧模型、纹理和监听器；保留已有合法预览 |
| 列表/画布 | 列表分页/虚拟化；视口外的重内容暂停；卡片拖动只更新相关坐标与连线，不重新读取来源或重绘整页 |
| 趋势 | 复用固定数据集和已取窗口；181点不重复拉取；大范围未来由服务端有界采样，保留极值、事件与质量断点 |
| 缓存 | 公开带版本脚本/Logo按现有策略；受保护内容仅在当前授权上下文内复用，换用户/项目/权限版本清理；不写公共CDN或永久浏览器缓存 |
| 权限 | 保留源接口必要的当前权限和固定版本检查，在一个受控请求内复用；减少重复核验不等于绕过源权限；不用共享正向权限缓存掩盖撤权 |

原图仍为默认资料来源。仅有合法既有预览时可先显示预览再换原图；没有预览就明确显示原图读取状态，不增加“先核验→再预览→再请求原图”的串行流程。

原件复用与显示校验分离：热打开仍核对当前可用性，但不重复传输相同固定内容。缓存必须有容量上限，采用最近使用淘汰；非活动照片最多保留2张解码结果，关闭会话释放临时URL、图片与模型资源。照片和模型不与推荐/趋势争抢同一条串行任务队列。

### 11.2 交互和时延目标

基准条件：用户当前Mac、正常登录、公网实际发布入口；另做可复现的50Mbps下载/100ms往返网络剖面。9.10MB既有柜体照片、最多50卡/100关系、最多4可见趋势及1活动3D作为边界样本。冷缓存与热缓存分别至少30次，记录p50/p95及失败样本，不只取最好一次。

| 指标 | 基准目标 |
| --- | --- |
| 点击后出现明确反馈 | ≤100ms；按钮、卡片骨架或查看器立即出现 |
| 首批核心推荐与报警/对象可操作 | p95≤2s，热返回≤500ms；重资料不在此等待链 |
| 已有分析文字/布局恢复 | p95≤1.5s；原件独立补齐 |
| 9.10MB照片冷打开至可见、可操作 | 网络剖面下p95≤5s；同授权上下文热打开≤300ms；另记录首次局部清晰时间 |
| 照片/图纸滚轮、拖动及卡片移动 | 目标≥50fps，p95帧耗时≤20ms；单次主线程长任务不超过100ms |
| 普通保存反馈 | p95≤1.5s；不重新下载全部源文件 |
| 取消与切换 | ≤100ms反馈；旧请求/旧图片结果不会回填新项目或新分析 |

3D首次可交互时间按实际文件大小/面数单独设基准，不为所有大型模型承诺同一秒数；不能拖慢已有文字、报警、趋势操作。照片指标不把显示空框/模糊占位算作完成。

慢网下1秒内出现加载状态；超过3秒补充实际进度（有Content-Length时）或阶段文字及取消入口；超过8秒显示“读取较慢，可继续分析”，提供单卡重试/取消。未知总量不造百分比；禁止几十秒白屏。单卡超时不让整页报错。

再做5Mbps/200ms慢网、取消大图、快速切项目/报警、同图多引用、连续打开关闭20轮的检查。记录网络等待/传输、服务处理、解码及渲染耗时和内存趋势，定位瓶颈后修复；不以新增无依据的长期延时/自动重试掩盖问题。不新增外部埋点，使用验收期间的本地浏览器/服务端证据。

## 12. 契约与实现影响

以下是确认后需要完成的实现工作，不声称现有接口已支持：

1. **推荐聚合读取**：按项目、事件/工单固定身份和版本输入；服务端读取可信映射/已登记关系，返回分组候选、推荐理由、来源路径、可用性与分页边界。完整通用图邻域仍属Q-19；本次先覆盖报警参照链及已有对象资料关系，不开放任意图查询。
2. **源卡快照保存**：启用受控来源卡，服务端逐项绑定本人会话的evidenceRefId及kind/revision；任何跨项目/跨会话、伪来源、原件正文或任意URL均拒绝。已有笔记分析能继续打开、保存和恢复。
3. **有界视图字段**：对页/区域、三维视角、趋势查看范围、笔记类型/过程标记及分区结构增加明确字段和上限。若使用新schemaVersion，提供旧版只读/升级保存兼容和整组恢复验证；禁止任意扩展JSON。
4. **批量消费**：保留现有`/evidence/register`、`/evidence/detail`、`/evidence/content`语义；需要的批量入口在代码实施前冻结请求/结果合同，逐项失败且不混淆来源权限。这里不虚构已存在路径。
5. **工单入口**：接已有`/link-work-order`与固定工单快照；追加入口查找及页面交接，仍有期望版本、幂等回执和当前权限校验。
6. **显示来源有效性**：服务端返回可显示的来源摘要/状态；受限时不先把旧保存标题画出来再隐藏。来源变化不自动更新历史事实。
7. **历史匹配与继承**：保存可检索的故障码/代码语义范围、对象、事件及原分析修订；历史导入和当前事件创建需幂等。旧分析有明确工单/事件关联时可由服务端据此补索引；没有可靠故障码时不从标题猜测，显式补充上下文后才参与精确匹配。历史笔记引用需绑定原会话固定修订与当前读取权限，不能作为无出处的新结论复制。
8. **文档最小接入**：为典型案例补齐源资料登记/已有资料选择、可靠对象关联、固定版本、受保护正文及页/节定位。需扩展源服务时遵循OntoBase仓库与API边界，不把分析笔记伪装成源文档。

### 12.1 为自然语言对话设计同一套操作

Q-23实施时，按钮、右键和拖拽调用明确的画布动作，后续Q-24自然语言也调用这些动作。动作是有限的类型化业务调用，不建立插件平台，不允许模型返回任意脚本、SQL或网址执行。以下为逻辑合同及操作设计，不宣称当前已有可用助手。

右侧复用“详情 / 助手”面板；对话可收起，选中卡片后有“围绕此资料提问”。输入区清楚展示当前报警、对象、时间窗和选中卡片，允许去除不需要的上下文；不要求用户反复输入位号和工单号。“这个对象”“刚才那条曲线”优先指向明确的选择/上一轮引用，存在多个合理候选才给少量选项澄清。

| 自然语言示例 | 预期操作 | 本批应准备的接口行为 |
| --- | --- | --- |
| “调出以前13001的分析” | 查有权同码历史并打开/复用匹配Canvas | 使用§3.2同一匹配和导入动作，保留历史版本 |
| “把这个温度传感器的图纸和照片放进来” | 根据所选对象取关联资料并加卡 | 与推荐加入共用去重、来源登记、布局和撤销 |
| “把报警前后温度和参照温度放在一起比较” | 找当前事件关联测点，调整显示窗口并对照 | 复用时间窗/比较动作；缺数据或单位不符明确返回 |
| “在照片里定位这个对象” | 打开已有固定照片及来源区域 | 与定位按钮共用；无区域时说明实际定位粒度 |
| “这次和上次有什么不同” | 对照两次事件、趋势、资料版本和排查记录 | 返回带来源/时间/修订的差异，不将历史结果当本次事实 |
| “把这些证据整理成一个原因假设” | 生成可编辑建议，列支持、反证、缺口 | 结果与引用分开保存；AI假设不自动变为确认结论 |
| “保存并关联到这张工单” | 执行已有保存及固定修订关联流程 | 目标唯一且用户明确指令时执行；有歧义或版本冲突时才要求选择 |

共用规则：

- 上下文包含当前项目/主体、会话及所见修订、当前事件/工单、选中卡、明确时间窗、固定证据引用。模型不决定权限，不从另一个项目继承上下文。
- 查询、定位和比较可直接执行；用户明确要求的加卡/布局/笔记变更可应用为一批可撤销修改，和手动操作一样显示“未保存”。明确要求保存才提交分析修订，不因普通问答悄悄保存整张画布。
- 建议性回答先显示建议和引用；用户要求加入或编辑后再应用。删除/覆盖已有人工内容、改时间范围或改用新来源版本须有明确意图；不能用“帮我分析”隐含授权这些变更。
- 动作批次带baseRevision、请求身份、目标卡及固定引用，提交前核对；用户编辑、切项目、取消后，过期AI结果不能覆盖新内容。新卡遵守固定卡片及50卡/100关系上限。
- 回答引用可点击到具体卡、页/区域/样本时刻；用户可从证据回到引用它的对话。自动摘要和回答的来源撤权时同步隐藏受影响内容。
- 对话历史按分析隔离；从历史Canvas建立新分析时只带明确的参考信息，不复制并执行历史用户命令。对话中的任务进度、来源及结果可见，不展示模型内部推理。
- 运行中可以继续浏览画布；支持进度、取消、部分结果和重试。布局/定位等确定性操作直接执行，不为每次手动操作调用大模型。一次对话只取所需片段和引用，不反复上传9MB原图或整个项目资料库。
- 本阶段不启用工程结论确认、设备控制、自动关闭工单或外部派单。模型/服务配置和真实对话运行在Q-22/24完成；Q-23验证动作合同与UI一致性，不用预录回答冒称AI已接通。

本节对保存行为的细化同步到[Agent设计](AI_Agent详细设计.md)，作为下一阶段实现输入；既有运行预算、取消及引用校验原则继续适用。

预计涉及已有模块：`AnalysisWorkspace.tsx`、`analysisCanvas.ts`及相关样式/API类型；复用`SourceEvidence.tsx`、`WorkOrderPhotoViewport.tsx`、`workOrderPhoto.ts`、`ModelViewport.tsx`和统一菜单；后端涉及`analysis_drafts.py`、`analysis_evidence.py`、`analysis_source_reader.py`、`project_sessions.py`与对应定向测试。实际拆文件以小型可评审改动为准，不建立通用卡片插件平台，不直写OntoBase数据库。
