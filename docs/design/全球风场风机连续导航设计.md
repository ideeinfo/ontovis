# 全球—风场—风机连续导航设计

**ONTOVis V0.2 · 2026-10-20 · 拟议实现合同。** 用户明确要求三级空间平滑切换，不通过弹窗、新窗口或突兀替换页面进入下一级。本篇替换旧版“独立 Three.js 细模切换”的视觉实现解释；独立是渲染职责边界，用户始终留在同一空间工作区。

## 1. 体验决定

采用持久 `SpatialWorkspace`：顶栏、导航轨、面包屑、时间窗、空间视口和详情区不随层级卸载。全球/风场/风机是这个工作区中的三个尺度与选择状态，不是三个弹窗。URL 可以改变可恢复状态，不能触发整页重载。

用户点击目录或地球项目点，镜头靠近风场；点击有定位能力的机组，镜头继续靠近并进入部件细节。返回、面包屑和浏览器后退按原路径恢复上级视角。右侧是同一页面的摘要/对象检查区，仅更新内容，不能承载下一级空间主场景。

| 动作 | 同屏结果 | 必须保留 |
|---|---|---|
| 全球选风场 | 标记选中、镜头推进、边界逐渐清晰、摘要更新 | 目录筛选/滚动、全球相机、图层、时间窗 |
| 风场选风机 | 机组描边、镜头靠近；细模就绪后渐入 | 风场相机、机位/告警选择、场景版本 |
| 风机选子设备 | 分析对象保持子设备，空间落到已核实柜体或说明无法定位 | selectedObjectRef与locatedObjectRef分列；代理精度 |
| 返回风场/全球 | 镜头沿连续路径退回，恢复既有状态 | 上级相机、筛选、图层和焦点；不跳回默认北向 |
| 报警/AI建议定位 | 用户触发后走同一导航动作 | 不强制打断当前阅读；迟到结果不劫持镜头 |
| 无细模/无真实机位 | 留在可用尺度，内联显示原因，资料/分析可继续 | 不打开空模型窗口，不制造坐标 |

信息密度：默认只留项目/对象名、必要来源/精度/连接状态及动作。连续导航无需教学横幅。参数、地图服务地址、转换矩阵和调试统计放管理区或帮助，不进入运营主流。

## 3. 引擎选择与衔接

**首选 MapLibre 持续承载全球和场站，Three.js 承载局部模型，不默认引入 Cesium。** 首先在同一 MapLibre WebGL 上下文中用受支持的 custom layer绘制地理低模，全球到场站无需卸载地图。部件细模使用 Three.js 独立场景能力，按W2试验选择继续共用地图渲染或同视口内的受控画布交接；不预建通用引擎适配框架。

MapLibre 官方提供 globe/terrain/Three.js结合示例和 custom layer接口，能验证这条路线的可行方向；示例不是本项目复杂机舱/地形条件的性能承诺。固定项目所选版本后核验其公共API和类型，不依赖 `map.transform` 等内部字段，也不盲用旧版 Mercator 矩阵到 globe。[官方三维示例](https://maplibre.org/maplibre-gl-js/docs/examples/add-3d-tiles-3d-objects-and-models-using-threejs/)、[CustomLayerInterface](https://maplibre.org/maplibre-gl-js/docs/API/interfaces/CustomLayerInterface/)

### 3.1 全球到风场

同一地图实例，从聚合/项目点逐步提高细节。用公开 camera `flyTo/easeTo/fitBounds/stop` 对应所选版本实现；按视口padding计算目标，展开检查区时不把对象遮到面板后。世界投影到本地展示遵循该版本的投影插值；不在飞行中突然 setStyle重建所有图层。大跨洲先低仰角飞行再接近，避免穿地和异常旋转。[官方飞行示例](https://maplibre.org/maplibre-gl-js/docs/examples/fly-to-a-location/)

全球只加载底图和分级目录；进入风场前预取周边低级地形/影像、边界与低模。场景相机由真实边界/已核机位计算，不能因目录 approximate中心点而自动飞到柜体级。

### 3.2 风场到风机与细模

优先使用已地理配准的机组外形持续靠近。细模源GLB与地图低模共享经过验证的机组锚点、朝向、比例及组件身份。若W2验证共用custom layer可满足近景拾取、裁切和精度，则保持单画布；若必须切独立Three画布，则执行以下一次性交接：

1. 保留MapLibre画布和相机状态，异步预热Three模块、GLB、纹理及着色；解码任务放Worker/可用后台任务，避免主线程长阻塞。
2. 两画布暂时叠放在**同一viewport容器**；将地理锚点转换到局部米制坐标。通过选定机组的屏幕投影、朝向、视角/距离关系计算接续姿态，核对至少3个非共线控制点；不能机械复制两引擎camera字段。
3. 细模首个有效帧、当前授权/版本、定位精度与必要资源均就绪后才开始250–400ms交叉淡化；交接期间禁止双画布同时拾取，焦点与输入交给一个owner。
4. 淡化完成后暂停上级渲染，仅保留有界返回状态/必要资源。返回时反向预热、匹配当前退场姿态，再向上级保存视角平滑退回。
5. 加载失败或坐标不成立时不启动淡化；原风场仍可交互。取消/新选择使旧过渡失效。只有交接窗口允许短时双渲染，不意味着长期两套引擎满速运行。

如果细模只是教学示意而非真实地理配准，风场上保持真实机组锚点，在接近过程中降低地理细节并进入**同屏模型检查模式**，明确“示意模型”，不让不匹配几何伪装与地面严丝合缝。返回恢复地理上下文。自动配准与高精工程测量不在此范围。

## 4. 统一上下文与导航状态

拟议的状态字段，不是已经上线的服务API：

| 状态 | 内容 / 约束 |
|---|---|
| 导航身份 | `level(global/site/asset),catalogSiteRef?,projectRef?,turbineObjectRef?`；公开目录ID与工程UID分开 |
| 选择/定位 | `selectedObjectRef,locatedObjectRef,locationMode,geometryQuality`；子设备不能被祖先柜体悄然替换 |
| 数据快照 | `catalogRevision,sceneRevision,modelVersionId,bindingRevision,hierarchyRevision,resolutionMode,resolvedAsOf` |
| 调查上下文 | `alarmRef?,timeRange,timeZone,sessionId?,contextEpoch`；默认不因镜头尺度改变时间窗 |
| 返回状态 | 每级cameraBookmark、筛选/列表scroll、layerVisibility、inspectorMode、键盘focusRef |
| 运行控制 | `transitionToken,target,state,abortHandle`；只有当前token能提交相机/选择/URL |

选中对象/调查上下文由工作区管理，渲染器只消费；相机和LOD可局部更新，不导致每帧React整树重渲染。相机书签是显示状态，不是工程事实。

拟议URL只存可恢复稳定ID/尺度和会话入口，不放大段相机矩阵或凭据。用户确认进入新层级才push历史；动画帧不push；同级调整用replace或内存书签。刷新/深链先校当前授权、解析当前可用版本，再恢复书签。浏览器back/forward调用同一导航控制器，不执行整页重载。URL编码和具体路由在Web切片中冻结。

目录全局入口只能读公开数据；工程入口的project/object引用都要重新授权。从旧浏览器历史恢复时，已撤权设备与旧细模缓存一并清理，返回最近可用范围，不泄漏对象名称/计数。

## 5. 过渡状态与中断

逻辑状态：`idle → preparing → flying → handing_off(需要时) → settled`；可从中途进入`cancelled/replaced/failed`。这是导航状态，不复用AI运行状态。真实实现由资源就绪事件和相机事件驱动，不用固定等待秒数伪装加载完成。

| 场景 | 处理 |
|---|---|
| 用户连续选择A、B | 递增transitionToken/contextEpoch，取消A；B从当前实际相机继续，A迟到数据不能落入B |
| 准备细模时返回 | 取消该次准备；上级画布仍在；不先闪进细模再退回 |
| 飞行中手动拖动/滚轮 | 用户输入优先，停止自动相机，保留当前显示与选择；可再次定位 |
| 异步AI返回A定位但已切B | 保留回答所属会话的引用，不移动B镜头；用户明确点击引用才产生新导航 |
| 大模型下载/纹理解码失败 | 保留低模/原场景，内联重试和来源状态；不能用空白viewport替代 |
| 地形瓦片缺失 | 地形降级/底图可用时保留地理范围；标缺失，未经核实不把高度设为精确0 |
| 场景换版 | 当前一次导航固定到可用快照；新发布提示按需应用；不混用新绑定与旧组件索引 |
| WebGL context lost | 保留对象/资料与状态，恢复画布或退到资料视图；同屏错误，不新开窗口 |
| reduced-motion | 取消长途镜头飞行，立即/短淡化到目标；保留相同选择与返回合同 |

新告警只更新计数和状态，不自动抢占镜头。后台预取受网络/GPU/许可限制，一次最多一个细模预取提案；用户选择改变即终止不需要的工作。取消不删除已保存调查，但不可再用旧结果写当前上下文。

## 6. LOD、地形与坐标合同

| 尺度 | 加载/保留 | 暂停/释放 |
|---|---|---|
| 全球 | 基础底图、聚合目录、少量选中摘要 | 不加载全部风场GLB、全世界高精DEM或所有测点 |
| 风场 | AOI地形/独立影像、边界、真实机位低模/实例化、受控状态 | 未选机组细模；屏外标注；原子回收前一风场大资源 |
| 风机 | 一台细模、必要材质/构件目录、柜体与当前选择、证据摘要 | 地图长期帧循环/其他机组细模；返回状态有界保留 |

沿用TU-3000一台细模＋30台低模背景的试验规模，不复制31套细模。教学模型的转子没有现成动画clip，确认转轴/父级后程序驱动；模拟与真实转速分别标记，过期/断线冻结或停止，并允许暂停动画。

地理交换WGS84；场站使用以核定锚点建立的局部ENU米制，glTF Y-up/米与ENU Z-up的轴、旋转顺序、比例、原点矩阵显式记录。DEM的正高/椭球高不混用；模型基底高度由认可高程/工程定位确定。公开30米DEM不能担保基础/柜体精确高程；影像是独立许可输入。详细管线见[技术栈、模型与实时接入](技术栈与实时接入设计.md)。

## 7. 性能预算与W2决策门

以下是**待实机验证的目标**，不是本轮SVG原型实测结论。基准建议现代Chrome/Edge、16GB内存，集显/独显各一台，20Mbps/100ms网络；记录具体硬件、浏览器和资源字节数。W2用同一真实DEM/影像、低模与细模样本检验并冻结。

| 项目 | 建议目标 / 测量办法 |
|---|---|
| 用户操作反馈 | 100ms内选中/按钮反馈；慢加载不阻塞资料操作 |
| 热缓存全球→风场 | p95≤2.5s达到可交互目标视角，含约1.2–2.0s镜头飞行 |
| 热缓存风场→风机 | p95≤2.0s；引擎交接控制点视觉跳动≤8px（1600视口） |
| 冷加载 | 按下载/解码/首帧分别计时；细模50MiB在20Mbps下仅传输即约21秒，**不能承诺2秒**；低模保持可用 |
| 帧率 | 代表样本交互≥30FPS；30FPS帧预算约33ms，主线程长任务>50ms单列追因 |
| 资源预算 | 初试低精入口≤15MB，单设备细节≤50MB压缩后；纹理/几何GPU峰值单独测量 |
| 往返稳定 | 连续20次全球→风场→风机→返回，检查GPU/堆内存回落、监听器与WebGL资源；无持续增长/黑帧/重复订阅 |
| 异常/中断 | 10次快速逆向/跨场切换、慢网/断网/撤权、版本变化、context lost、reduced-motion |

W2通过条件：地形与机位配准可解释、同视口连续过渡/返回成立、近景拾取与权限有效、性能达到目标或有经批准的资源调整。优先优化LOD/纹理/加载；只有明确能力缺口才重新评估Cesium。引入第二套地球引擎不是本轮默认工作。
