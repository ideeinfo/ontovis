## 2. 总体决策与产品边界

1. **ONTOVis独立产品/独立仓库**，前后端及基础设施尽量沿用OntoBase已采用技术。两者通过授权API协作，不直接读写对方数据库或复制Feature内部。
2. **模型管理在ONTOVis**：上传/原件/派生版本/构件目录/模型实例/场景放置/绑定审核与迁移/可视化配置；OntoBase负责设备身份、物理层级、资料与工程关系。
3. **设备父子关系在OntoBase**：无bbox设备可建档，柜体下开关/仪表/控制器/传感器按已确认安装事实关联。模型深度止于柜体不阻断子设备证据与分析。
4. **MapLibre＋Three.js为首选**，Cesium仅在真实PoC揭示明确能力缺口后评估。全球—风场—风机保持同一空间工作区，通过连续镜头、细节递进和必要的同视口交接完成。
5. **公开目录与工程主数据分开**：以官方来源构建项目/分期目录，经人工确认crosswalk连接私有工程项目；名字、邻近位置和容量不能自动生成工程UID。
6. **Canvas基础效果可实现**：React Flow自由卡片、Dagre排版、九类卡片/来源定位、单活动3D视图；不承诺全量Cognite能力或多人实时协作。
7. **Agent为单编排器**：固定工具、有界读取、证据/假设/反证/缺口、取消/部分结果/修订；不确认工程事实、不执行现场控制、不提交外部工单。
8. **页面简洁**：常驻内容只保留身份、质量、来源时间、关键阻断和有效动作；说明按需展开。运营导航不通过模态框承载下一级空间。

## 3. 逻辑架构与职责

```text
公开数据（EMODnet / REPD / 获准GEM文件）
      → 固定来源采集 → 原始批次/质量报告 → 目录审核发布
                                      ↓ 公开项目/分期引用
业主空间资料 → DEM/独立影像/机位 → 场景版本/同视口导航
                                      ↓ 经审核工程入口
用户 → ONTOVis Web：SpatialWorkspace / Canvas / 管理配置
           ↓ 服务契约/当前用户权限
       ONTOVis API + 必要Worker
       ├─ 模型/构件/绑定/场景/配置发布与回滚
       ├─ 监测映射、可靠事件、最新值与历史读取
       ├─ 会话/证据/人工判断/受控Agent
       └─ 目录批次与授权工程crosswalk
           ↓ 授权API（非直连数据库）
       OntoBase：工程对象/物理树/资料版本/证据/有界图谱

持久化：PostgreSQL（按需PostGIS）/ Redis / MinIO
监测来源：一种协议的后台只读Worker → 规范时间/质量 → 授权SSE
```

具体选型、Cognite实证边界、动画、区域地形/影像与监测合同见[技术栈与实时接入设计](技术栈与实时接入设计.md)。SQLite仅为本机目录暂存；生产仍使用PostgreSQL，不因本轮工具增加一套业务数据库。

## 4. 身份、模型、物理层级与定位

工程引用统一`ObjectRef={ontobaseConnectionId,projectCode,entityUid}`；ONTOVis项目ID、目录项目ID、外部监测ID和源模型ID分别管理。RDS/名称可检索、不能当唯一工程身份。

物理安装关系独立于模型节点父子、电气连接和RDS分类：同上下文/时点单父、无环、有证据/审核/有效期；防环与并发约束在OntoBase权威事务层执行。合并、退役、删除资料和移装各有生命周期处理，不重写历史证据。

模型上传自包含GLB2，米/右手/Y-up；可附固定JSON/CSV映射清单，IFC作为离线转换输入，不承诺任意CAD原生直读。源构件跟踪键`sourceModelKey+sourceElementId+placementId`，场景发布定位固定`modelVersionId+sceneModelInstanceId+componentKey`，节点下标仅版本内。模型内容/属性/坐标/资源预算先校验，再产生候选，人工核实并发布。

选中子设备时，`selectedObjectRef`不变；直接几何不存在则沿当前安装上下文的已确认祖先链定位最近有效柜体，另返回`locatedObjectRef`及`ancestor_proxy`。几何质量另列source_verified/source_candidate/proxy_schematic；“能高亮”不能升级成精确位置或工程等价。

本试点CN2机舱信号柜仅有教学controller源构件候选；CN1机舱动力柜、CT塔基柜为示意代理，实际柜级UID/实例仍待核实，不能提前填成正式绑定。附件TU-3000细模用于一台主机，其他机组低模只做可视化模拟；样例模型许可、三柜证据和真实工程身份分别过门。

完整字段/动作/分页/异常见[模型工作流](模型与设备关联工作流.md)和[首切逻辑契约](../contracts/三柜绑定与子设备定位契约.md)。

## 5. 空间连续性：全球→风场→风机

同一个`SpatialWorkspace`持续存在，地球、区域地图和近景模型占用同一viewport。全球到风场尽量保持一个MapLibre实例；风机近景Three模块异步预热，必要时在同视口叠放短时画布并以锚点/控制点匹配后交叉淡化。旧场景在新场景可用前保持，不能闪黑、开对话框或另起窗口。

导航保存每级相机、选择、图层、目录筛选/滚动、时间窗、场景/绑定版本和焦点；URL深链/浏览器后退使用同一动作。每次意图递增transitionToken/contextEpoch，旧加载与AI返回不能把用户拉回旧对象。新告警只更新状态，不强制飞行。

没有获准工程入口/真实机位/可用细模时，停留公开目录或可用上级尺度，资料仍可读；approximate目录点不能作为精确柜体镜头。尊重reduced-motion，加载失败内联重试，返回恢复上级上下文。真实性能目标与冷加载传输时间分开，50MiB模型在20Mbps下仅传输就约21秒。

详见[连续空间导航设计](全球风场风机连续导航设计.md)，含状态机、双引擎衔接、坐标/LOD、目标硬件、首帧/FPS/内存预算及NAV-01～08。MagicPath新画面是几何/交互示意，尚未验证真实地图/GLB/GPU。

## 7. AI与配置

Agent由意图路由、服务端上下文、固定读取工具、证据归纳、结构化验证、有限Canvas patch及运行审计组成。明确对象导航可直接用确定性动作，不能为每次镜头变化调用模型。

默认预算提案：8次读取、2并发、2轮补检索；活跃执行软60秒/硬120秒；等待澄清/版本冲突独立24小时失效。恢复不重置剩余预算并重校权限/版本。运行状态、会话业务状态和现场告警状态分别管理。

每个回答有支持/反证/缺口/适用范围，证据固定来源/文件/提取版本及页/节/区域；历史监测保存本run实际用到的有界快照，不能只固定时间窗。文档内容和外部监测文本都是数据，不成为工具指令；任意SQL/脚本/URL/设备控制不在工具目录。

配置分部署/项目/场景/会话/个人层：工具能力/权限取交集，预算取更严限制；个人布局不能隐藏代理、未核验、过期或阻断状态。模型密钥、连接凭据仅受控后端配置。固定表单支持草稿→校验→预览→发布→回滚，不提供任意代码编辑器。

详见[Agent完整详设](AI_Agent详细设计.md)和[配置中心与AI交互](配置中心与AI交互设计.md)。AI运行不改工程身份、物理树、绑定审核或人工根因，不自动对外派单。

## 8. 数据与实时连接

一个选定源协议在后台只读接入，浏览器通过授权SSE消费当前范围。连接身份决定租户/项目，sourceConnectionId/externalAssetId/pointId与工程ObjectRef显式映射。保留源时间、到达时间、sourceEpoch/序号、单位、原质量码、映射版本与sourceKind。

关键告警先写PostgreSQL事件/outbox，再按协议能力确认；下游幂等，不能声称exactly-once。Redis保存最新值/有界流，不以Pub/Sub充当可靠历史。切站/撤权/游标过期/慢客户端分别处理；没有源历史时展示缺口，不从实时流编造过去。

30台×20点×1Hz＝600samples/s是试点预算，若全量保存约5,184万点/天；优先源historian，必要时仅60关键点分钟聚合。模拟、历史回放、实时分开，未知/坏值/过期/未映射不画正常绿灯。公开目录容量与SCADA实发值分开。

已交付的登录/授权、工程读取/分类/设备路径、当前图纸、受限GLB和演示关联、三柜定位与工作台交互直接复用。正式工程身份/现场精度缺口阻断相应核实验收，不阻断保留假定/代理标记的场景开发；目录和真实数据也分别按自身输入推进。

六人角色、单场站和2026-10-26启动基准沿用。原496核心＋91支持＝587人日及2027-03-19交付窗口留在[历史估算](../plans/实施范围与排期增补.md)，未覆盖场景V2全部新增。Q-01核销已交付、分拆原剩余与净增、核对角色容量后再更新日期；不把SC工时整包追加WBS，也不挪用风险缓冲掩盖新范围。
