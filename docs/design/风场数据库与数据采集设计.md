# 风场数据库与数据采集设计

**ONTOVis V0.2 · 2026-10-20。** 本轮已经实现本机采集工具、官方数据快照及 SQLite 暂存库；后文的生产 PostgreSQL 服务、增量发布、GEM 导入、审核工作台和自动调度仍为拟议能力。SQLite 是设计阶段的可查询交付，不是另选生产数据库。

同日技术Demo增补：另从GEM当前官网链接的公开地图取得2026年2月GeoJSON快照，含35,089个风电分期点，用于本机全球可视化；原4,089条EMODnet/REPD暂存库保持独立。此次未取得正式工作簿、未修改`tools/wind_catalog.py`或建立生产导入服务，后文的正式GEM输入门继续适用。数据来源、点位精度和验证见[夏李空间验证](../references/夏李风场空间导航验证.md)。

## 1. 结论与数据分层

公开风场目录由 ONTOVis 管理；OntoBase 继续管理工程设备与安装关系。公开目录回答“哪里有什么项目”，业主台账回答“本项目有哪些真实设备”，监测系统回答“某设备在某时刻发生什么”。三类数据不互相充当依据。

EOS 官方信息页说明使用公共登记、政府和行业资料，并列出 REPD、The Crown Estate、EMODnet 等来源；公开展示不代表其聚合接口可自由调用。本次不把 EOS 自有接口作为数据源。[EOS 信息说明](https://eos-omnia.com/omnia/l1-information)

| 层 | 本期内容 | 权威边界 |
|---|---|---|
| 公开目录 | 项目、分期、容量、状态、目录位置/边界、来源版本 | 不产生工程 UID、精确机位或实时运行状态 |
| 项目工程数据 | 获准项目、真实机组/柜体/子设备、安装关系、机位与测绘基准 | OntoBase 授权对象与业主工程资料；跨产品显式引用 |
| 可视化资产 | 模型、场景、放置实例、构件、几何绑定、DEM/影像 | ONTOVis 管理不可变版本和当前发布指针 |
| 监测数据 | 测点值、告警、质量、历史窗口 | 源监测系统；公开容量不能代替实发功率 |

公开目录进入产品时设独立“公开目录”范围，只有明确授权并建立 crosswalk 的条目才能进入业主项目。公开条目可以打开地图和公开摘要；私有项目的存在、设备数量和告警不能通过公共目录推断。

## 3. 本次实际采集与质量结果

本地批次：`output/spatial-catalog-design-20261020/catalog-20261020/`。其中 `manifest.json` 为成功批次清单，`catalog.sqlite` 可查询，`observations.jsonl` 为规范化导出，`raw/` 保留原始输入。输入文件均来自上述官方发布端点。

| 项目 | 数量 / 状态 |
|---|---:|
| EMODnet 风场点 `windfarms` | 631 |
| EMODnet 边界 `windfarmspoly` | 600 |
| REPD 原 CSV 全部技术类型行数 | 14,657 |
| REPD Wind Onshore / Wind Offshore | 2,748 / 110，合计 2,858 |
| 总来源观测记录 | **4,089** |
| 有几何的来源观测 | 1,231；点和边界分别统计 |
| 可检索的非空名称项目观测 | 3,488；631 点＋2,857 REPD，**未经跨源去重** |
| 缺名称记录 | 22：EMODnet 边界21、REPD1；暂存并标记，退出普通目录入口 |
| REPD 坐标待核验/转换 | 2,858；保留原 X/Y，规范几何为空 |
| 工程对象绑定 / 真实逐风机位置 | **0 / 0** |
| SQLite 完整性检查 | `ok` |

4,089 不能写成“4,089 个唯一风场”；EMODnet 点和面可能描述同一项目，REPD 还可能记录分期、修订申请等。公开目录初期返回带来源的项目观测，在跨源审核前不计算去重总容量或唯一风场数。

真实样本：`emodnet / windfarmspoly / windfarmspoly.103` 为 Saint-Nazaire，来源容量480MW、风机数80、状态Production。本轮原型仅引用其公开摘要；示意机位 WTG-07、柜体和监测不与该真实项目建立工程事实关系。该项目在当前点层中没有同名记录，不能假定点面拥有相同 ID 或一一对应。

首次执行发现缺名称字段，工具随后调整为保留带质量标记的记录；两次失败批次保存在 `_work/`，均标为 `failed` 且没有可用数据库，不会伪装成功。

## 4. 已实现工具与运行方式

维护工具：`tools/wind_catalog.py`；边界测试：`tests/test_wind_catalog.py`。Python 标准库实现，无新应用框架、无数据库服务器依赖、无凭据。

在 ONTOVis 根目录运行，输出目录必须是一个尚不存在的新批次目录：

```bash
python3 -m unittest discover -s tests -v
python3 tools/wind_catalog.py --output output/wind-catalog-20261027/batch-01
```

工具使用官方 WFS 分页（每页100条），检查 total、返回数、分页长度及重复 ID；按发布页唯一的官方 CSV 链接获取 REPD。原始文件保存 URL、字节数和内容摘要，规范数据保留原字段。单次 HTTP 超时60秒、响应上限40MiB；失败退出非零并保留失败清单。目录不覆盖，因此失败不会替换旧批次。

当前未实现：自动重试/调度、自动发布、跨源实体归并、坐标转换、GEM 工作簿导入和生产 API。重复执行会获取新批次，不执行自动增量或合并写入。工具只接受固定官方来源，不提供任意远端 URL 抓取入口。

查询示例：

```bash
sqlite3 output/spatial-catalog-design-20261020/catalog-20261020/catalog.sqlite \
  "SELECT source,layer,count(*) FROM observation GROUP BY source,layer;"
sqlite3 output/spatial-catalog-design-20261020/catalog-20261020/catalog.sqlite \
  "SELECT name,capacity_mw,turbine_count,status FROM observation WHERE name LIKE '%Nazaire%';"
```

测试覆盖分页、重复/变动总量、短页、NaN/非整数、经纬度范围、缺名称隔离、REPD 平面坐标、官方下载来源约束、失败批次和源内身份。测试通过不等于数据拓扑或行业真值已核验。

## 5. 生产数据库设计（拟议）

复用 PostgreSQL；只有空间查询切片落地时添加 PostGIS。暂存库两张表 `dataset`、`observation` 和 `catalog_points` 视图是首批证据，不要求把它扩展为业务主库。生产实体按具体需求建立，避免先造通用采集平台。

| 实体 | 关键字段与约束 |
|---|---|
| `catalog_batch` | batchId、sourceKey、releaseLabel、retrievedAt、sourceUrl、licenseRef、rawArtifactRef、rowCounts、qualitySummary、status；不可变成功批次 |
| `catalog_observation` | batchId、sourceKey、sourceLayer、sourceRecordId、name/status/capacity原值与规范值、observedAt/sourceUpdatedAt、geometry、locationAccuracy、provenance；源内键唯一 |
| `catalog_site` / `catalog_phase` | ONTOVis 自有稳定目录 ID；项目与分期分开；仅经审核的观测归并；不把同位置不同分期容量相加两遍 |
| `catalog_link_review` | 候选观测对、匹配依据/冲突、负责人、决定、理由、版本；结果可撤销，旧观测保留 |
| `catalog_project_link` | catalogSite/phaseId ↔ ontobaseConnectionId/projectCode/可选siteObjectRef；当前授权与人工确认，不自动建工程对象 |

索引以 source键、国家/状态/安装类型、名称检索及几何空间索引为主。点、面保留各自角色；边界以真几何承载，不把中心点升级为边界。项目机位由工程数据管理，目录表不塞入合成风机。

`capacityMw` 未知为 null，源0单独保留；容量和风机数必须符合非负/整数规则。状态保存 `sourceStatus` 与规范 `lifecycleStatus`，未知值不默认operating。`sourceUpdatedAt`、`retrievedAt`、`validFrom/To` 分开；源未给日期不补当前日期。

## 6. 采集、复核、发布与更新

1. **准入**：登记覆盖、粒度、官方入口、许可、署名、用途、责任人及版本；GEM 文件/许可输入门、Crown Estate 用途门未通过不启用。
2. **获取**：定时任务检查当前发布入口；新版本进入独立批次。原始文件先落 MinIO，处理 Worker 只读输入；凭据来自服务配置。
3. **规范化**：固定来源映射，保留源 ID、原字段、原坐标和不确定性。列缺失/重复 ID/分页不完整阻断批次；单行缺名/几何异常隔离该行并出报告。
4. **质量门**：必需列、非空唯一键、行数变化、状态字典、数值、国家/海域覆盖、坐标、空名称、明显跨国漂移。变化超过20%进入人工复核提案；首批不使用比例门假装已有历史基线。
5. **匹配**：首先尝试已审核源间映射；名称/国家/距离/容量仅生成候选。相似名称或重叠边界不直接合并。分期/扩建、规划修订、海域协议与建成场站分别处理。
6. **发布**：质量报告和许可状态通过后，在事务中替换目录当前批次指针；只读查询固定到同一版本。失败保留上一成功版本并展示同步时间和错误；不清空目录。
7. **更新**：源记录消失标 missingInLatestBatch，连续两次合格批次/官方证据后才提议退役；不直接删除或修改工程对象。人工归并与链接在新批次重校、保留审计。
8. **回滚**：切回已获准的成功批次；当前授权仍生效，撤权不因旧快照恢复。外部缓存带 catalogRevision，不混合新旧分期。

正式调度建议 EMODnet/REPD 每周检查一次，GEM 每月检查官方版本；这是产品运维建议，本轮没有创建 Codex 自动化或系统定时任务。连续失败由数据管理员处理，退避次数和通知渠道在部署切片配置，不写入用户浏览流程。

## 7. 空间精度、坐标及地图读取

WGS84 经度/纬度为交换格式，顺序明确 `longitude,latitude`。本次 WFS 使用 `CRS:84` 请求，并以英国/比利时样本核对返回坐标顺序；响应元数据可能仍写 EPSG:4326，保留原文，不靠标签猜轴。

REPD X/Y 没有在当前 CSV 逐行声明 CRS；英国本土与北爱尔兰可能涉及不同国家格网。W1取得该发布版本的明确坐标说明后按区域核实 EPSG/转换参数，使用受检 GIS 工具转换，抽查海岸、国别和已知项目。没有依据的行继续无规范几何，不能用国别猜一个 CRS 后宣称已精准定位。[英国坐标系指导](https://www.gov.uk/guidance/uk-geospatial-data-standards-coordinate-reference-systems)

目录 `locationAccuracy` 至少区分 source_site_point、source_site_boundary、approximate、unresolved_source_grid；几何有效不等于测绘精度。全球尺度展示目录点/聚合，场站尺度用边界/公开摘要；只有授权真实机位和模型定位合同齐全才推进精确设备视角。公开地形是另一条管线，目录几何不提供 DEM。

拟议查询操作只描述服务语义，尚未冻结 HTTP 路径：

| 操作 | 输入 / 输出与约束 |
|---|---|
| 查询目录 | bbox、zoom、国家/状态/来源、catalogRevision、cursor；默认50条、最多100条，低缩放返回聚合及单位，不能下载整库后假分页 |
| 读取目录详情 | sourceObservationRef 或已审核catalogSiteId；返回来源、许可、更新时间、精度、分期和是否有关联工程项目 |
| 读取范围几何 | 场站ID、简化级别、catalogRevision；保持原边界供追溯，展示副本可简化 |
| 解析工程入口 | 用户、catalogSiteId；只有当前授权匹配才返回projectRef；没有工程连接时返回公开浏览能力 |

Agent 目录检索只能返回公开事实及出处，不可将目录年产/装机容量当实时监测，不可从名称/邻近点推断子设备安装关系。导航需要的上下文和精度门见[连续空间导航设计](全球风场风机连续导航设计.md)。

## 8. 交付与验收

- **本轮完成**：两官方来源的采集工具、11项测试、真实全量快照、质量清单、可查询 SQLite，全部位于 ONTOVis；无工程数据库写入。
- **W1输入**：P/数据负责人落实 GEM 正式文件、许可与引用；GIS 明确 REPD 坐标说明及实际试点 AOI/机位；BE2登记来源版本与归并规则。
- **W2验证**：抽检原始与规范值、坐标轴、分页总量；重跑新批次；坏批次不替换旧版；确认跨源/分期计数口径。
- **产品化**：落到 WBS26，完成 PostgreSQL、MinIO、固定来源任务、发布/回滚及查询合同；不把本地采集完成等同于生产服务上线。
- 全球目录发布前必须取得 GEM 文件（或单独批准等价覆盖来源），并核验国家/分期范围。当前欧洲/英国种子库可支持技术验证，不能通过“完整全球库”验收。
