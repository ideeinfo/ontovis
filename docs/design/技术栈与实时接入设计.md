# ONTOVis 技术栈、模型与实时接入设计

**V0.2 · 2026-10-20 · 设计提案。** 将此前Cognite/三维/地形/实时详细方案迁入本仓库独立维护；模型身份以当前工作流和首切契约为准，三级视觉交接以[连续导航](全球风场风机连续导航设计.md)为准，公开数据以[风场采集设计](风场数据库与数据采集设计.md)为准。旧版“独立详情”的说法不再表示打开窗口或离开空间页面。

## 1. 整体技术栈与依赖边界

| 层 | 选择 | 落地约束 |
|---|---|---|
| Web | React / TypeScript / Vite，复用OntoBase已批准的组件、表单、i18n及token方法 | 版本在正式切片核对现有包；不直接导入另仓Feature内部 |
| 空间 | MapLibre GL JS + 按需Three.js | 地球/场站同地图；近景同视口交接；Cesium条件评估，不默认安装 |
| 模型 | 自包含GLB2、GLTFLoader、可选经验证的压缩解码 | IFC离线转换；不承诺原生RVT/DWG上传后直接浏览 |
| 分析Canvas | React Flow + Dagre | 九类基础卡片/有限布局；多人协作不含在核心库采购假设内 |
| API / Worker | FastAPI / Python，必要异步任务 | 与OntoBase同类技术；独立产品发布，禁止直写OntoBase数据库 |
| 持久化 | PostgreSQL、Redis、MinIO | 空间查询需要时加PostGIS；本地采集SQLite仅暂存；不默认Kafka/新时序库 |
| 工程知识 | 通过授权API消费OntoBase资料/对象/有界图谱 | Neo4j保持OntoBase一侧；ONTOVis不复制一套可写工程图谱 |
| 实时 | 后台一种协议Worker + FastAPI授权SSE | 浏览器不进入工业网；历史依赖真实historian/有限聚合 |
| Agent | 单编排器、固定类型化工具、结构化结果/Canvas patch | 部署/模型在受控配置；权限、预算、证据校验由代码执行 |
| 部署 | 现有容器/反向代理/健康检查方法 | 两仓分别构建版本；不要为单场试点先造Kubernetes/通用插件平台 |

当前ONTOVis尚无生产apps/API/数据库迁移；依赖名不是已安装清单。MapLibre/Three/PMTiles与解码器先通过W2真数据小样，再锁定兼容版本。团队沿用既有Web门禁思想，最终具体命令随正式apps创建确定，不能在空仓宣称已有npm检查。

## 2. 模型与参考站结论

模型选型/原始节点事实见[模型格式与来源核验](../references/模型格式与来源核验.md)，三柜流程见[模型与设备关联工作流](模型与设备关联工作流.md)。附件TU-3000作为精细教学主机，一台精细主机加30台背景低模；官方多风机场景用于空间参考，不将三柜模板复制到每台机组。

上传为自包含GLB2，米、右手、Y-up，源属性通过extras或固定sidecar携带；每次处理生成报告和不可变构件目录。跨版本源键为sourceModelKey+sourceElementId+placementId，发布定位固定modelVersionId+sceneModelInstanceId+componentKey；nodeIndex仅版本内。几何缺失的子设备通过已确认物理树定位柜体，不能用GLB父子替代安装事实。

EOS Globe的2026-10-19公开资源/默认样式检查显示Next.js/React、MapLibre、Protomaps/PMTiles及叠加层相关资源；默认所查样式未配置DEM。它支持MapLibre作为候选方向，不能证明该站全部模式不含地形，或证明本项目比Cesium更轻。引擎、瓦片、纹理、解码与显存必须用相同输入实测；不照搬参考站框架/版本。[EOS Globe](https://eos-omnia.com/globe)、[其公开默认样式](https://eos-omnia.com/protomaps/styles/v5/light-en.json)

## 3. Cognite Canvas：已知技术与可实现效果

公开资料可以确认 Industrial Canvas 的调查能力，以及独立 Reveal SDK 使用 WebGL/Three.js；**不能确认 Canvas 二维编辑器内部使用 React Flow、Konva、Fabric、tldraw 或某个公开 Canvas SDK**。本次未核验到可直接嵌入的公开 `@cognite/canvas` 包。不能因此把闭源产品克隆的成本归为“接个SDK”。[Industrial Canvas 官方文档](https://docs.cognite.com/cdf/explore/canvas/)、[Reveal 开发文档](https://cognitedata.github.io/reveal-docs/)、[Reveal 源码](https://github.com/cognitedata/reveal)

| 体验 | 本项目能否实现 | 实现及范围 |
|---|---|---|
| 无限平移缩放、自由卡片、连线 | 可做首期主要效果 | React Flow nodes/edges/viewport；保存布局、撤销和键盘路径 |
| 图纸/PDF并排调查、页引用 | 可做 | 同一文档的页引用，不复制文件；屏幕只渲染可见页/裁剪区域 |
| 点击工程对象找资料/关联设备 | 可做，但依赖数据 | OntoBase稳定ID、授权检索、图纸位置与已审核关系 |
| 多条时序、统一时间窗、事件标记 | 可做基础版 | 有限曲线数、服务端降采样与质量缺口；不承诺完整信号分析台 |
| 3D对象/相机书签放入画布 | 可做 | 首期卡片用快照+选中时打开单一活动3D视图，避免每卡常驻WebGL |
| Cause Map/原因图与自动排版 | 可做 | Dagre基础对齐；事实、假设和证据边有类型，根因由人工确认 |
| Agent加入证据、整理调查 | 可做 | 受限Canvas patch、preview/commit、revision与操作审计 |
| 图片/视频资料卡 | 本产品可做 | 图片首期；视频按实际来源另定。此次不把视频说成已核实的Cognite等同能力 |
| 会话批注、审阅、权限范围 | 可做基础版 | 首期已有批注/指定专家审阅/授权版本链接；完整评论线程、@提及和公开匿名分享另估 |
| 多人同时编辑、光标、离线合并 | 后续独立范围 | 需要协作协议、冲突策略与权限撤销；并非React Flow自带完整服务 |
| 海量CAD/点云/全厂统一上下文 | 有条件后续 | 数据转换/分块/LOD/元数据与性能专项；不在首期等效承诺内 |

这意味着可以实现“资料在同一空间里调查、对象可互相定位、AI可准备证据”的主要效果；无法仅凭公开资料承诺 Cognite 的全量能力、规模与企业数据整合成熟度相同。

工程约束：图纸内部沿现有 viewport/page surface/overlay 契约；卡片默认选择态，进入交互后才消费滚轮，退出后恢复画布缩放，避免嵌套手势争抢。保存 `viewport + node positions + source refs + revision`，不保存临时DOM或短期下载URL。AI可在固定分区新增卡片，但不能随机重排用户锁定卡片。来源更新显示差异，不改写历史事实。

React Flow 核心库采用 MIT；公开的多人协作示例另有 Pro 使用范围，不能把示例复制权与核心库许可混为一谈。Reveal 为 Apache-2.0 的独立3D SDK，本方案先用直接Three.js；只有确认需接入其数据服务与格式时再评估Reveal，不同时维护两套局部3D内核。[React Flow](https://reactflow.dev/learn)、[协作示例](https://reactflow.dev/examples/interaction/collaborative)、[React Flow 许可](https://github.com/xyflow/xyflow/blob/main/LICENSE)

## 4. 三维显示与动画

### 4.1 资产管线

原始包只读 → 派生版本副本 → 保留部件父子关系/原点 → 标记稳定componentKey → 补代理柜体 → 材质与LOD优化 → glTF校验 → 拾取与绑定检查 → 发布版本清单。原整机、机舱内部视图、拆分件不是要同时叠加的三个模型。

`all-parts` 包含隐藏备选几何，不能无条件全部显示。合批只在同部件/同材质内进行，不能把三个柜体合成不可分辨的网格。压缩和LOD转换后要保留节点关联表，验证ID、坐标、材质、轴向和动画轴心，而不只验证“文件能打开”。

地球级仅加载地图原生标记；进入场站才加载低模实例，选中风机后在同一空间视口内加载高细节，按连续导航合同接续镜头。地图低模与局部细模通过sceneModelInstanceId/固定版本componentKey关联；镜头交接计算控制点投影与姿态，不复制裸相机矩阵。机舱详情同一时间只挂载一个，离开时释放不再使用的 geometries/materials/textures；共享资产按实际引用释放。拾取优先包围盒或简化碰撞体，再解析componentKey。透明/隔离在局部视图完成，避免全场透明造成排序和性能问题。[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)

### 4.2 动画契约

| 动画 | 驱动 | 实施方式 | 数据缺失时 |
|---|---|---|---|
| 转子旋转 | `rotorRpm` | 沿经过核验的转子局部轴；每帧角增量 `rpm × 2π / 60 × Δt`（轴向符号经模型校验） | 停止实时外推，显示陈旧/未知；可另开明确标识的演示模式 |
| 机舱偏航 | `yawDeg` | yaw父节点，最短角差插值并处理359°→0° | 保留最后姿态并标数据时间，不继续追风 |
| 三叶片变桨 | `pitch1/2/3Deg` | 各blade-root本地轴及零位，不能旋转整个转子替代 | 未提供的叶片显示缺测，不自动复制第一片 |
| 罩壳打开/剖切/爆炸 | 用户交互 | 独立查看态或制作clips；与运行姿态分层 | 不依赖监测源，也不能暗示现场已拆开 |
| 柜门与检修高亮 | 用户交互 | hinge子节点/样式；补模型时定义枢轴 | 无铰链资料只做示意旋转并注明 |
| 报警/电气流向 | 事件状态/教学序列 | 状态色、文字；仅短暂可跳过反馈，不持续闪烁，减少动态偏好可关闭 | 未知态不着正常绿；教学能流不当电气计算结果 |

网页原有动画逻辑与静态GLB是两份不同能力。静态导出后，需重新绑定转子、yaw和pitch轴心；不能仅调用 `AnimationMixer` 就得到原网页控制效果。真实导出的 glTF clips 才交给 Mixer；数据驱动动画使用受控变换，避免两套系统同时写同一个节点。[Three.js 动画系统](https://threejs.org/manual/pages/animation-system.html)

只有质量good、未陈旧、时间有效且映射有效的数据才能驱动实时姿态；坏值、未来时间、失效映射或断连均停止实时外推并标原因。源时间判断测量有效性，到达时间辅助判断通信中断，两者不能互相替代。

动画帧和数据帧解耦：数据1Hz也可60Hz平滑渲染，但插值不是新增测量值。实时模式、历史回放和模拟模式分别显示时钟及来源；后台页暂停动画；暂停只是视觉操作，没有停机控制含义。画布和Agent读取原数据，不读取动画中间值。

## 5. 地球、地形、影像与自托管

地球/场站由MapLibre承载；近景Three使用同一workspace内的细节能力。地图原生点/线/面优先，低模使用经验证custom layer；不默认依赖第三方Three桥接插件。球面到局部投影、地形深度、拾取和近景精度在W2验证，采用公共API；无法满足时按证据重估，不能偷偷改成突兀页面切换。[连续导航合同](全球风场风机连续导航设计.md)

### 5.1 以实际AOI选择高程与影像

项目实际风场名称、经纬度/边界与机位表尚待提供。W1先明确AOI、海陆和数据精度目标；Crystal Rig的苏格兰坐标仅属于异地演示素材，不能作为默认所在地。

| 来源 | 使用定位 | 必须记录的限制 |
|---|---|---|
| Copernicus GLO-30 | 实际AOI高程首选候选，核对目标瓦片后下载并区域自托管 | 约30米级DSM，含植被/建筑影响；高程基准EGM2008；核验产品版本、质量层、实际覆盖与许可，不能把90m回退当30m |
| NASADEM / SRTM | GLO-30缺口或质量异常时交叉检查/备选 | 覆盖主要为60°N～56°S，输出1角秒并不保证等同30m有效细节；主观测年代较早，合并高程产品采用EGM96，不能直接混拼基准 |
| Mapterhorn | MapLibre格式与小样性能PoC候选；正式使用仍按区域提取并保留来源 | Terrarium瓦片/PMTiles、全球30m级及局部高精来源；当前环境取TileJSON/归属JSON返回403，未证明可稳定在线消费；代码许可与数据许可分开 |
| 影像 | 优先客户合法正射；缺少时选择获授权的卫星影像，或明确高程着色 | 与DEM独立取源；Sentinel-2可见光10m采样可表现整体环境，不能替代基础/道路近景测绘 |

### 5.2 区域处理、自托管与离线合同

处理顺序：**AOI与机位确认 → 下载DEM及质量/许可元数据 → GDAL裁切/拼接、检查NoData → 水平重投影与经核验的高程基准转换 → 在数值高程域重采样/生成层级 → 编码为Terrarium或Terrain-RGB瓦片 → TileJSON/区域PMTiles → 现有受控网关与MinIO → MapLibre raster-dem/terrain**。影像单独校正、裁切与生成raster瓦片；道路/边界另用矢量源。

- GDAL负责栅格准备和经配置的坐标/高程转换；RGB高程编码与切片工具在W2以解码样点验证后锁定。先处理数值高程再编码，不能对编码RGB作普通有损压缩或任意图像重采样，也不能把GeoTIFF改后缀当作瓦片。NoData处理保留可审阅规则与覆盖边界，缺测不默默填成海拔0。
- 标明 `encoding`、`tileSize`、`minzoom/maxzoom`、bounds、原始/派生分辨率与数据版本；PMTiles只封装瓦片，不把OSM矢量底图转换成DEM。目标区域可用XYZ/TileJSON或经验证的PMTiles读取方式，W2确定一种正式分发路径，不同时建设两套通用服务。
- PMTiles按HTTP Range读取；网关/对象存储必须正确透传Range并返回206/Content-Range，保持同一归档版本的ETag一致性，不因代理转压缩导致偏移失效。跨域配置允许需要的GET/HEAD/预检与Range/If-Match，暴露ETag及必要范围响应头；采用Authorization时一并核验预检和凭据策略。不得以每个请求下载整个区域归档的方式伪装按需加载。
- 私有地图归档执行与项目一致的授权；所有Range请求均受保护。PMTiles客户端认证按其FetchSource能力验证，不能假定MapLibre的transformRequest自动覆盖归档读取；采用现有受权网关或短期访问引用，不把长期token写进URL/书签。缓存按公开许可数据与私有资料分开，私有缓存包含授权范围/版本，撤权后失效；不可用跨用户公共缓存绕过权限。
- 离线包除区域高程/影像/矢量瓦片外，还包含style JSON、中文glyph/font资源、sprites、署名、选定JS/worker及模型解码资源。逐项核验字体/数据许可，限定AOI和zoom；离线指通过内网/本地HTTP服务可用，不承诺双击file://即可运行。断网检查不再请求外部字体、样式或CDN。

来源：[GDAL warp与高程转换](https://gdal.org/en/stable/programs/gdalwarp.html)、[MapLibre DEM源格式](https://maplibre.org/maplibre-style-spec/sources/#raster-dem)、[PMTiles读取集成](https://docs.protomaps.com/pmtiles/maplibre)、[PMTiles Range/CORS部署](https://docs.protomaps.com/pmtiles/cloud-storage)、[FetchSource认证](https://pmtiles.io/typedoc/classes/FetchSource.html)、[外部资源与隐私](https://github.com/protomaps/docs/blob/main/guide/security-privacy.md)。

### 5.3 数据、坐标与高程合同

每个数据集记录 `datasetId/revision/source/license/horizontalCRS/verticalDatum/resolution/bounds/acquiredAt/noData/processing`；处理记录含原始与目标CRS/高程基准、单位、使用的格网/算法版本及质量检查。机位坐标、基座标高/安装朝向、影像与道路/边界分别有来源；只有程序山丘或风景贴图不算真实地形完成。

- 业务位置采用经纬度及声明的高程基准，工程计算保留WGS84/ECEF和带原点的局部ENU米制，Three模型声明轴/单位。MapLibre显示投影不能当作工程权威坐标；局部米制坐标先通过已核验转换映射到地图，不能把经纬度直接当米，也不能忽略Mercator比例随纬度变化。
- 地图DEM与地图低模基座使用同一个已声明目标高程基准 `H_site`；GLO-30的EGM2008与NASADEM的EGM96不能直接拼接。涉及ECEF/ENU时将正高转换为椭球高 `h=H+N`，记录大地水准面模型及版本。若候选插件固定采用EGM96，必须显式转换并复核，否则不采用；不让插件的隐式修正叠加第二次高程偏移。
- 对已约定的Three局部坐标X东、Y上、Z南，转ENU为 `(E,N,U)=(X,-Z,Y)`。列向量下保持 `pECEF = T_ECEF_from_ENU × T_install × C_model × A_runtime × p_model`：先在模型局部按核验父子关系/枢轴施加yaw/pitch/rotor，再做轴/单位/原点校准、安装位姿及ENU到ECEF。安装heading与运行yaw分开；地图低模只消费由此得到且转换到地图高程基准的位姿，不另造一套身份/坐标真值。
- 地形夸张默认1；任何夸张显示不改设备尺寸或业务坐标。原始DEM采样、瓦片像素与屏幕视觉精度分别报告；30米级数据只支持总体地貌，不验收基础、道路净空或施工量测。海上场站不能用陆地DEM声称获得海底地形。
- 风机基座以核验的基础标高为准；DEM采样仅用于候选与偏差检查，不能随当前地形LOD每帧移动基础。无可靠基础标高时显示待核验，不伪造贴地精度。
- 地图与Three详情传递 `tenantId + projectId + sceneId + turbineInstanceId + modelRevision + transformRevision + selectedNodeKey + cameraBookmark`；地图与详情各存自己的相机书签并声明空间/版本，不共享renderer或裸相机矩阵。返回只恢复用户视点，不重算工程绑定。

## 6. 外部监测系统实时接入

### 6.1 链路与源协议

```text
SCADA/监测平台/历史库（只读账户）
        ↓ 厂站出口或现有数据网关；不由浏览器进入工业网
一个选定协议的连接worker
        ↓ 原始标识、源时间、质量码、单位、事件序号
验证/去重/时序处理/单位与资产映射
        ├─ PostgreSQL：报警、映射版本、审计、可靠事件outbox
        ├─ Redis：最新值、有限期stream/游标
        └─ 历史查询：回到源历史库，必要时有限聚合存储
        ↓ 授权订阅与背压
FastAPI SSE（默认）/WebSocket（需要双向订阅时）
        ↓ 只推当前场站/视区/卡片需要的值
三维状态 / 趋势卡 / 数据质量提示
        └─ Agent：通过只读工具拉取冻结时间窗摘要
```

| 源能力 | 首选接入 | 必须确认 |
|---|---|---|
| 已有统一监测HTTP API | REST快照+增量游标；必要时轮询 | 分页、限额、更新时间、历史补数、报警生命周期；轮询要显示刷新周期 |
| 已有MQTT数据出口 | 后台MQTT客户端、TLS、按topic授权 | payload schema、QoS、会话/保留消息、序号与离线期；QoS不代替业务幂等 |
| 只提供OPC UA | 受控边缘/服务worker订阅数据和事件 | 证书信任、NodeId稳定性、采样/发布周期、队列、断线重订阅与历史访问 |
| 只有厂商SDK/数据库 | 先用批准只读出口或网关 | 不把直接生产库查询当通用默认方案；协议开发单列 |
| 只有Modbus等现场接口 | 由现有采集网关转换后接入 | 本产品不新增PLC轮询和写寄存器能力 |

默认MQTT候选使用Eclipse Paho Python，版本在W2锁定；它的客户端会话有内存持久性限制，进程重启后的恢复仍依赖源端保留/历史与本项目水位，不能把自动重连当成持久补数。关键消费确认按锁定版本支持的手动ack模式验证。[Paho官方文档](https://eclipse.dev/paho/files/paho.mqtt.python/html/)

MQTT至少一次交付可能重复；OPC UA可靠性受队列、会话、断线时间及历史能力约束。不能承诺协议名称本身保证“零丢数”。[MQTT 5.0 标准](https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html)、[OPC UA MonitoredItem](https://reference.opcfoundation.org/specs/OPC-10000-4/5.13.1)、[OPC UA服务](https://reference.opcfoundation.org/specs/OPC-10000-4/full)

### 6.2 统一数据契约（建议，不是已有API）

```json
{
  "sourceConnectionId": "demo-monitoring",
  "sourceKind": "simulated",
  "externalAssetId": "WTG-01",
  "pointId": "rotor.rpm",
  "sourceTimestamp": "2026-10-19T01:42:00Z",
  "ingestedAt": "2026-10-19T01:42:00.180Z",
  "sourceEpoch": "sim-run-20261019-01",
  "sequence": 2401,
  "value": 11.2,
  "valueType": "number",
  "unit": "rpm",
  "quality": "good",
  "qualityRaw": "SIM_OK",
  "mappingRevision": "demo-mapping-v1"
}
```

tenant/project由服务端连接身份与授权上下文确定，不能信任源payload自报；源值同时保留原单位与转换版本。`quality=good`只说明该模拟源记录可用，不把`sourceKind=simulated`变成实测。规范键为 `(tenantId, sourceConnectionId, externalAssetId, pointId)`。

事件去重优先源事件ID+版本或序号；没有可靠序号时记录受限语义，使用规范化payload辅助去重但不承诺绝对唯一。源重启序号归零必须使用sourceEpoch/bootId或经核验的重置规则；没有可靠epoch时先重建快照和水位，不因任意变小的序号猜重启。每点在同epoch内按源序号/源时间处理迟到值，最新值缓存不能被旧消息覆盖。未来时间或超过允许时钟偏差的数据标time_invalid并进入待核验，不更新正常最新值，防止锁死后续合法消息；历史更正走独立路径。UTC存储，界面按用户时区展示，报警时间窗和Agent查询使用同一时钟。

报警保留 `active/cleared`、源严重性、源确认状态和所有更新时间；驾驶舱的“已查看”不等于在SCADA确认。恢复快照与事件增量用水位衔接，避免快照期间新增报警丢失。

### 6.3 恢复、持久化与广播

- 关键报警：先把源事件与outbox在同一PostgreSQL事务提交，再按源协议能力确认消费。worker重试可以重复传递，下游以幂等键消重；不宣称端到端exactly-once。
- 高频最新值：Redis保存带源时间/质量/映射版本的最新记录；短期Stream有时长和长度上限。数据丢失或游标过期时明确要求快照重建。
- Redis Pub/Sub是至多一次、无历史，不用它独自承担可靠报警；Streams支持日志和消费游标，但持久性仍取决于AOF/副本/故障策略。不能引用新版Redis专属能力作为仓库现有版本事实。[Redis Pub/Sub](https://redis.io/docs/latest/develop/pubsub/)、[Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)
- 多个网关实例不能共享一个消费组后误以为各连接都收到全量消息：需每网关独立读游标/广播方案，消费组只用于处理任务的分工。重放范围按用户当前ACL过滤。
- 默认前端以REST设置订阅、SSE接收更新。当前JWT若通过header传递，采用支持认证header的fetch流或同站安全会话；不把长期token放URL。需要双向订阅才采用WebSocket，并检查Origin、握手/续期权限与每次订阅范围。[FastAPI WebSocket](https://fastapi.tiangolo.com/advanced/websockets/)
- 断线保留用户仍有权查看的最后值并标stale；撤权立即清除不可再访问的内容。切站取消旧订阅，消息带scope、subscriptionId、contextEpoch，前端丢弃旧上下文在途数据；每用户限制点位数、消息率和并发连接。慢客户端合并最新值但不默默丢报警，发gap标记并重取快照。
- staleness阈值按点位采样间隔设置，例如 `max(3×周期,10s)` 作为试点默认。未知、坏值、陈旧、未映射分别展示，不能用最后一个正常绿灯一直掩盖断线。

### 6.4 规模、历史与目标

建议试点按 **30台×20点×1Hz＝600 samples/s** 估算，这不是已测性能。若全量逐条入库，一天约5,184万点；因此本期不把普通PostgreSQL变成无边界原始历史库。

1. 全部点位的最新值进入Redis；UI按可见范围以1Hz合并，图形动画独立插值。
2. 原始历史查询优先接现有historian。无历史权限时显示缺口，不凭实时订阅还原过去。
3. 本地可选仅保留60个关键点的1分钟聚合，约86,400行/天、30天259.2万行；记录min/max/avg/count/quality与时间范围，绝不冒充原始曲线。采用PostgreSQL按日期分区并设保留策略。[PostgreSQL分区](https://www.postgresql.org/docs/current/ddl-partitioning.html)
4. 经业务确认需更高频/更长历史或多风场时，另评估TimescaleDB/专用时序库或源历史服务扩容；不预先加入第二套时序平台。

验收目标：正常1Hz源的源时间→界面P95≤2s（源时钟健康且无自身批处理时），普通页面合并推送≤1Hz；报警尽快推送但有速率保护。测试重复、乱序、未来时间、坏质量、数值越界、源断线5分钟、服务重启、游标过期、慢客户端和权限撤销。若源只5秒轮询，就显示5秒更新并相应调整延迟承诺。

模拟器与真实连接器使用同一验证/映射合同但不同 `sourceConnectionId/sourceKind`，模拟故障可以覆盖其他模型对象。未在OntoBase建模的齿轮箱、叶片、变流器仅建立ONTOVis监测对象，页面写明“无工程资料绑定”，不虚构资料或借用三柜ID。

## 7. 对Agent架构的补充

- 既有 `find_assets/get_asset_context` 工具输出补充，同时返回工程实体、模型实例、映射状态；只有候选几何时回答“可定位示意柜体、工程身份待确认”。
- 监测工具只读选定的点位、时间窗和聚合级别，返回 `sourceKind/quality/coverage/lateData/mappingRevision`，不让LLM拼topic、NodeId或历史库SQL。
- 一个分析run锁定事件时间、映射版本和证据版本，并持久化其实际用到的有界序列/聚合结果快照、查询条件、聚合算法版本、retrievedAt及源水位/摘要。历史库可能回补，固定时间窗本身不等于结果不可变；不需要为此复制全量原始历史。实时值持续变化时不改写已提交的假设；用户请求更新时建立新revision。
- “温度高所以故障”必须区分阈值规则、统计相关和已确认因果。教学功率曲线与模拟报警不能作为真实故障证据。
- 多次实时更新不触发无界Agent循环。首期由用户显式发起分析；批量报警汇总以后按去重、预算与审批另外设计。
- 三维动画、LOD、单位转换、采样降噪、时间排序、阈值计算都由确定性代码处理；模型只负责解释和组织已验证结果。

## 8. 生产验证与范围

模型真实输入、AOI/机位、DEM和独立影像、源协议与历史能力分别有负责人和时间门。W2验证真实地图—地形—低模—细模的连续交接、拾取、30FPS目标与资源释放；公开采集样本不能充当SCADA，SVG交互样例不能代替WebGL性能。

试点规模30台×20点×1Hz、600samples/s、60关键点分钟聚合等为估算输入；不同来源频率或保留要求要重估，不把未知值补0。具体工作包/角色/日期统一见[现行排期](../plans/实施范围与排期增补.md)，不另加旧技术附录人日。生产前逐项完成授权/撤权、文件访问、模型版本/绑定、断线/缺口、AI证据/取消和回滚验证。
