# 工程助手统一能力设计

V0.3 · 2026-11-04 设计基线。项目检索、受限画布编辑和固定证据已分批上线，实际范围见[实施计划](../plans/工程助手完整能力实施计划.md)，下文原问题与未实现说明保留当时背景。

2026-11-11 工单职责按[工单工作流与分析复用设计](工单工作流与分析复用设计.md)实施。工单记录流程、处理文本和附件，分析画布承载诊断编辑。系统推荐有权分析，由人员采纳固定版本、新建或修改另存。EA-05 已接入 Q-55，后台助手遵循相同权限，驾驶舱只查询。

本设计依据用户“删除历史工单卡后，助手仍应搜索已有工单并加入画布；能够操作当前画布、查询知识图谱、使用系统现有数据和功能”的要求。用户已确认：**后台助手可完整编辑；驾驶舱继续查询，可转后台执行。** 本文覆盖旧[Agent详设](AI_Agent详细设计.md)中与本设计冲突的检索范围、画布动作和保存语义；已上线行为仍以[操作指南](../guides/AI策略与分析助手操作指南.md)为准。

## 1. 产品目标和已核实问题

工程助手是当前用户的自然语言工作入口。用户在页面中有权完成的业务操作，应能从助手发起，经过相同的业务服务、权限、版本、表单校验与结果回读。助手不获得一个比用户权限更高的“万能账号”，也不要求用户理解某项操作属于 OntoBase 还是 ONTOVis。

本次只读核对见[能力与接口清单](../references/工程助手现有能力核对20261104.md)。已保存案例仍为 r8；“加入资料 → 历史工单”实际列出 DEMO-PDS-WO-001、008、015。当前助手只从 `evidenceRefIds` 取摘要，无项目工单搜索工具；`AnalysisWorkspace`只向助手提供定位及追加笔记回调。因此截图不能解释为“系统没有历史工单”。截图同时标注“未保存 · r8”，说明草稿与保存版本也必须区分。

需要一起解决的七处缺口：

1. **画布成员被误当检索边界**：删除卡片后无法重新发现系统记录。
2. **项目查询与本轮证据混在一起**：没有说明查了哪些来源、哪些还没查。
3. **缺少完整执行链**：文字说“可加入”与实际加卡、保存没有统一回执。
4. **上下文未覆盖当前草稿**：用户改动后的画布与助手使用的保存版可能不同。
5. **图谱摘要被过度压缩**：当前工程邻域只有两跳、24节点/48关系，模型摘要进一步限制为最多5条关联；不能用它回答任意全项目图谱问题。
6. **所有问题固定套四区回答**：查工单需要候选清单，操作需要变更回执；不是每次都要输出故障假设。
7. **已有页面能力未完整暴露给助手**：源端已提供项目知识图、文档知识与问答能力，Vis已有资料推荐、工单检索、画布保存等服务，尚未组成同一个用户流程。

## 2. 范围：完整覆盖现有能力，按任务读取

### 2.1 三种范围分别显示

| 范围 | 含义 | 默认及改变方式 |
|---|---|---|
| 可查范围 | 当前账号有权访问、已接入的系统资料和业务记录 | 当前项目；可由明确问题或范围控件选择其他有权项目、全局模型/设备目录 |
| 本轮依据 | 为回答本题实际读取并允许进入模型的固定片段 | 按问题选择；显示类型、数量、出处、版本和未读取项 |
| 当前画布 | 用户用于组织分析的卡片、关系、分组、笔记和视图 | 包含当前未保存修改；不是系统目录，不限制查找能力 |

“仅画布内资料”保留为用户可主动选择的收窄方式，不再是隐藏的唯一范围。范围收窄时，找不到只能说“当前画布内未找到”，并提供“查本项目”。跨项目查询必须在当前用户已获授权的项目内明确选择，不能因一个项目没命中就自动扫全部组织。

搜索按服务器分页执行，不先把全库送给模型。列出结果不等于读取全文；实际送入模型的内容仍受项目/能力资料分类、数量、字数和模型外发规则约束。因策略不能读取时解释具体限制，不能报告“没有这份资料”。

### 2.2 画布移除不是源记录删除

从画布移除工单、图纸或对象只删除卡片引用及相连的画布关系。源记录继续可查，历史运行的固定引用继续保留。普通分析不主动加回用户刚移除的卡；新的明确“查找”“加回”请求可以重新读取或加入。用户选择“不用于本轮/本对话”时，另存显式排除范围；排除资料不能通过历史摘要偷偷返回。

同一来源同一版本重复加入应定位现有卡片；同一来源不同版本提供“更新当前卡 / 保留旧版并作对照”，不静默替换。卡片删除、来源删除、来源不可读、知识撤回须分别显示。

### 2.3 后台与驾驶舱

| 能力 | 后台 | 驾驶舱 |
|---|---|---|
| 本项目搜索、知识问答、原文/图谱/工单读取 | 可用 | 可用；与后台相同的授权检索范围 |
| 基于现有或新查到资料分析 | 可用 | 可用；不必先加卡 |
| 临时查看、放大、定位、平移 | 可用 | 可用 |
| 加删卡、笔记、关系、分组、布局、时间范围 | 按用户指令修改当前草稿 | 生成待执行方案，转后台核对 |
| 保存、另存、恢复修订、关联工单、源端业务修改 | 通过对应服务与业务规则 | 转后台；携带问题、结果引用和具体方案，不自动执行 |

从驾驶舱转后台时保留目标画布ID和基准版本，重新核对最新草稿、来源和权限。后台已有未保存修改时展示差异；不能用驾驶舱的旧快照覆盖。转后台并不意味着批准了所有后续业务写入。

## 3. 完整能力目录

下表是产品覆盖范围，不代表这些能力都已经可由现有助手调用。实际接口依据、缺口和接入顺序见[能力清单](../references/工程助手现有能力核对20261104.md)及[实施计划](../plans/工程助手完整能力实施计划.md)。每一项都应有“可执行 / 需选择 / 需核对 / 无权 / 未接入 / 暂不可用”的真实状态。

| 领域 | 用户可向助手提出的任务 | 操作方式和结果 |
|---|---|---|
| 项目与工作范围 | 查找、进入有权项目，解释当前身份与来源 | 同步页面范围；切项目前处理未保存修改 |
| 工程对象与层级 | 搜索位号、名称、类别、规格；读取定义/安装层级、属性、设备采用关系 | 精确身份消歧；可打开、定位、加入画布；源端维护使用正式业务接口 |
| 文档、图纸、照片 | 搜索项目目录及设备适用资料；找页、对象、端口、引用、知识摘录；按原版本查看 | 不限已选卡；逐项标识元数据、已读文本、结构化记录或实际读图 |
| 工程与文档知识图谱 | 查邻居、关系、路径、关联手册、定义与安装差异；按关系/状态过滤、统计 | 每条边带出处/版本/审核状态；已登记关系、候选接线、文本机理、人工假设分开 |
| 工单 | 搜索同码/同设备/同型号/指定时间工单；读文本记录、附件、已采纳分析、结果及旧诊断历史 | 按授权整理处理文本/附件；分析推荐、采纳和另存按Q-55，诊断在画布完成，人员最终流转 |
| 报警与趋势 | 查事件、关联设备、固定时间窗、趋势及质量；对比窗口、调整分析时间 | 计算使用确定性函数；历史工单时间不被当前报警的3分钟窗口误过滤 |
| 画布 | 创建/打开/重命名；加删卡、更新引用、笔记、关系、分组、布局、固定、大小与内部视图 | 与手工操作共用动作；一个任务作为一个可撤销批次 |
| 分析管理 | 保存、另存、历史查看/恢复、同码历史导入、回收站恢复、关联工单与固定版复用 | 明确目标与版本；工单修改已有分析默认另存，不改其他工单依据；项目共享须明确范围，不共享私人对话 |
| 模型与场景 | 搜索模型/版本、检查报告、预览、定位；场景创建、布置、绑定、外观/完整模型选择、视角与环境设置 | 复用现有编辑与校验服务；校准、批量替换、删除等显示具体差异与影响 |
| 设备型号与资料配置 | 查项目采用、配置、共享模型/照片、适用资料，准备与执行已有配置变更 | 无固定文件名或行业假定；核对设备身份、引用版本及受影响实例 |
| 数据与运行设置 | 查询天气、来源状态、模拟数据、现有连接与设置；准备已有表单可做的变更 | 明确模拟/真实、当时/当前；测试连接或生成任务计入对应预算 |
| AI能力与运行记录 | 解释生效连接、各能力参数、读取工具、用量；准备设置差异、查看失败与回执 | 不读取/显示密钥；修改沿用项目管理权限；不能自行扩大本次运行权限 |
| OntoBase资料与知识处理 | 上传用户指定资料、执行已有识别/知识处理、查看任务、复核及发布入口 | 任务归属由系统决定；可准备和跟踪，源端要求人工审核的最终动作仍走原审核界面 |
| 用户偏好与页面导航 | 切换主题/语言，打开模块、对象、资料、运行记录 | 复用现有设置与导航；不把导航成功说成业务操作成功 |

“所有数据和功能”不包括绕过产品服务访问数据库、主机、密钥或执行任意脚本。原产品尚无的现场控制、真实遥测接入、外部派单、专家结论确认，仍显示未接入。权限授予、凭据变更、工程事实确认、不可逆删除等需要本人在对应业务界面完成最终动作；助手仍能查条件、准备内容和解释结果，不能代签身份或审批。

## 4. 意图与动作：用符合任务的结果回答

| 问法 | 系统理解 | 首要输出 | 是否改画布 |
|---|---|---|---|
| “历史上有哪些相同故障工单，可以加入分析？” | 查候选，不是明确要求全部加入 | 工单列表、数量、同码/同设备依据、状态；可选择加入 | 否 |
| “把工单GPX-WO-041加回画布” | 精确查找并加入 | 定位新增卡；“已加入草稿，可撤销” | 是；不自动保存 |
| “把刚查到的这两单都加进来并保存” | 绑定上一轮两条精确引用、加卡及保存 | 先加卡后保存，返回新修订；若已有其他未保存修改先显示合并差异 | 是，保存须覆盖明确范围 |
| “删除这三张卡，保留笔记，整理布局” | 目标确定的复合草稿动作 | 删除/移动数量、受影响关系、撤销批次 | 是；保护未指名的固定卡和笔记 |
| “温度信号到控制器经过哪些对象？” | 对象解析与图谱路径查询 | 逐段路径、关系类型、原图定位及未闭合段 | 否；可“将路径加入画布” |
| “为什么这次报警？” | 分析任务 | 先回答，再展示事实、假设、支持/反证、缺口和核查 | 否；用户要求才添加笔记 |
| “把这条观察记录到工单” | 修改指定工单人工记录 | 工单原内容/拟追加内容/来源/状态差异与保存回执 | 不隐式改画布或关闭工单 |
| “当前用哪个模型，改成已有连接B” | 配置查询与修改 | 当前生效值及差异，按已有管理员保存流程 | 不自行新建连接或索取Key |

自然语言引用“这张/刚才两条/全部”须解析为具体ID。指向唯一、操作可撤销时直接执行；多个同名对象、版本冲突、缺必要业务字段时只问一个必要问题，提供带身份和范围的选项。不能用模型置信度替代身份校验。

## 5. 统一运行过程与提示词

采用**一个有界编排器 + 领域工具**。不按资料种类创建多个自治Agent。工单搜索、图谱读取和趋势计算本身使用确定性服务；只有自然语言意图理解、证据综合需要模型。跨域读取可以并行，所有调用仍归属同一运行、权限与预算。

流程：识别目标和意图 → 确定检索范围 → 查询目录/图谱 → 读取所需固定内容 → 回答或构造操作批次 → 校验 → 执行/等待必要选择 → 回读结果。进度只展示“查工单 / 读记录 / 核对引用 / 加入2张卡”等实际阶段，不展示隐含推理、不虚构百分比。

### 5.1 三个输入包

1. **任务与上下文**：用户原话、当前项目/画布/草稿版本、选中对象及卡片、当前事件、时间与时区。历史对话只作指代和意图上下文；旧回答不是新证据。
2. **可用能力**：本次允许的具体业务动作、参数约束、是否需要选择/确认、预算。只包含实际接入且本人有权调用的动作。模型不能选择任意URL、SQL、Cypher、脚本或修改权限。
3. **证据包**：从目录筛选后实际读取的类型化片段，逐项带E引用、固定来源身份、字段/页码/节点/边、数据质量、适用范围与未读部分。目录命中但未读内容标为候选，不提供给模型冒充已读证据。

固定规则中要求“先回答请求，未执行搜索不能说没有；不执行动作不能说已添加/已保存；模拟、候选、缺段和省略必须保留”。源资料中的指令仅作资料文字，不能改变用户意图或工具权限。

### 5.2 类型化组合

| 类型 | 输入重点 | 组合方式 |
|---|---|---|
| 报警 | 确切事件、故障码、对象、状态、发生/恢复、模拟标记 | 用来限定任务，不直接证明根因 |
| 工单 | 设备/型号身份、故障码语境、时间、状态、处理文本、附件及采纳分析固定引用、版本、省略信息；旧诊断按历史读取 | 与当前事件分列；建议不冒充已执行记录，同码不自动推为同设备或同根因 |
| 工程图谱 | 精确节点、逐边关系、方向是否明确、端口、审核状态、出处及截断 | 按路径逐段组织，不能只把若干邻接名称拼成完整信号链 |
| 文档知识 | 固定发布、节点类型、原文片段、证据页/区域、适用对象 | 定义、条件、原因、步骤分别组合；没有原因节点不能靠常识补造 |
| 图纸/照片 | 元数据、结构化定位、已提取文字；实际图面读取另列能力状态 | 未接入读图时明确“图面未读”，不得以页面可预览推断模型已读像素 |
| 趋势 | 确定性窗口统计、逐点/聚合范围、质量、单位、可复算对比 | 使用同窗口和可确认映射；当前值与历史值分开 |
| 模型与场景 | 模型固定版、绑定/校准质量、对象及空间位置 | 用于定位与展示，几何不能证明实物状态 |
| 草稿笔记与旧对话 | 人工记录/AI待核标识、草稿摘要、来源依赖 | 保留来源层次；修改笔记不能伪造源端工程事实 |

### 5.3 有界多步，不沿用一次调用的隐含限制

目标允许“计划一次—必要时补充一次—回答一次”，**最多3次模型调用、8次逻辑读取、2并行、120秒活跃时间**作为首批评估上限；简单命令可0次模型调用，常规检索问答通常2次以内。模型输入/输出上限由能力配置显式设置，不允许重试无限追加预算。

这些是新设计值，不会静默改变当前线上“一次模型”的策略。实施时增加明确的计划/补充/回答预算与工具授权字段，按项目和能力取更严值；旧配置按原行为运行，管理员启用新能力后生效。现有源端 `/ontovis-assistant/analyze` 只支持摘要回答，不能直接假装已支持工具规划，须按[执行契约](../contracts/工程助手检索与操作契约.md)补齐并版本化。

用尽预算返回已完成部分和尚未执行项；用户点“继续查找”才创建关联的新运行。明确搜索编号、定位、布局、撤销等能确定性处理的动作不为了“AI化”重复调用模型。

## 6. 画布完整编辑与保存

### 6.1 与人工操作共用同一动作

完整目录包括：新增/移除资料卡、创建/编辑/删除笔记、卡片名称、位置/尺寸/固定/内部视图、关系新增/修改/删除、分组/取消分组、分组标题及布局、整理布局、时间范围及趋势切片、分析名称/允许的进度、视图定位/缩放、保存、另存、导入历史、恢复修订、关联工单、回收与恢复。

助手不复制一套简化画布，也不直接生成HTML、坐标脚本或整张新快照覆盖用户编辑。复用当前手工业务函数和校验器，将缺少的动作补为明确的类型化操作。新增工程关系只能读取源端已登记关系；助手生成的支持/反证/假设关系保留人工/AI来源标记，不能写成源端工程事实。

### 6.2 草稿是第一等上下文

每轮冻结 `savedRevision + draftRevision + draftDigest`，包含当前卡片、笔记、关系、选择与来源引用。服务器验证来源引用，不信任浏览器填入的源内容。新查到证据可只存在本轮证据集中，不要求先插入画布；新建未保存画布也可发起项目查询，直到首次实际保存才创建正式分析修订。

查询结果可以在用户继续编辑时返回，但标记本轮所见草稿；执行动作前校验目标字段与草稿版本。目标被改、删、换版则返回具体冲突；不覆盖新编辑。只有纯新增且位置无冲突的批次才允许重新基于最新草稿核验，不能以“智能合并”静默覆盖。

### 6.3 执行、撤销、保存分别记账

- 明确的草稿编辑应用后显示“新增2卡、移除1卡、修改1条笔记 · 未保存”，提供定位和撤销。一次任务为一个撤销单元，保留原笔记、卡片、关系和视图。
- “保存这次修改”只在用户已明确指向的变更范围内提交。当前画布还有其他未保存内容时展示整体差异，避免偷偷一并保存。首批服务仍整张快照提交，因此必须把合并范围向用户说明。
- 保存成功显示实际新修订；超时/断线显示“结果待确认”，先按同一请求查回执，不重复保存。
- 保存后的撤销不是删除历史：恢复相应内容为新的草稿，再明确保存新修订。工单或源端记录不能通过撤销画布反向改掉。
- 运行取消与已执行操作分开：已落地的草稿批次仍可撤销；取消不能声称已经回滚业务保存。用户离开或切项目不得产生后台偷偷提交。

## 7. 知识图谱问答

支持三类图谱，回答中保留它们的语义：工程对象/层级与端口关系、文档发布知识、当前画布的人工分析关系。不能把三者扁平化成一种“已知关联”。

查找起点可来自位号、名称、当前选择或项目搜索，不要求先有对象卡。自然语言先解析允许的关系与目标，返回多个同名节点时消歧。使用源端有界分页/邻域读取；缺少路径接口时按明确的边类型和全轮预算逐段读取，不生成任意Cypher或宣称遍历全图。

路径结果逐边显示：起终点、定义/安装范围、关系类别、方向来源、记录状态、证据页/端口、固定版本。达到深度/节点/读取预算时显示终止点及继续选项。“本次限定范围未找到路径”不等于“系统无连接”。路径从温度传感器到控制器不闭合时直接标明缺段，不能用图纸页引用替代电气导通。

文档知识检索优先复用源端项目知识图、固定发布邻域和已发布查询能力；不让两个模型对同一资料先问答再互相总结。跨系统组合使用源端原始节点/边/证据及Vis本地工单、趋势。未实现的源端过滤或路径接口在清单中标为缺口，不臆造可调用接口。

## 8. 界面结构

延续原工作台灰绿主题、13px正文/11px说明、橙色报警/目标高亮。主界面为画布与右侧助手，顶部只有上下文和必要动作；不用一排复杂开关迫使用户配置代理流程。

1. 助手顶部显示“本项目 · 按需检索”，可展开范围；紧邻“本轮依据”显示实际读取来源数。两者与画布卡数不同。
2. 固定底部输入：“查资料、问关系，或描述要对画布做的修改…”；通过问题自动识别任务，保留可选的任务重定向，不强迫先选择分析/问答/工单建议。
3. 搜索结果用紧凑候选卡：编号、标题、状态、匹配依据、设备/时间、来源范围、在画布与否；支持原文、选择、加卡。大批候选分页，不铺满聊天区。
4. 图谱结果用路径和逐边证据；“查看原图”“展开这一段”“加入画布”就近放置。
5. 操作回执有独立色块：待执行、已应用草稿、已保存、部分完成、待确认。聊天文字不能替代真实回执。
6. 查询、编辑、保存均能展开“依据与过程”，只显示实际工具、参数范围、来源及结果，不显示模型隐含推理。
7. 驾驶舱显示“查询模式”，读数据与后台一致；编辑请求出现“到后台预览这2项修改”，保留目标，不要求重输问题。
8. 无结果、部分结果、权限不足、接口不可用、版本冲突、取消、结果未知各自有简短可行动状态；不统一写“找不到”。

## 9. 实施与完成标准

先交付用户当前闭环，但范围不止一个特判：**项目搜索 → 固定读取 → 明确加回/移除 → 当前草稿 → 撤销/保存 → 图谱问答**共用一套运行和动作契约。随后按现有模块逐项接入业务操作。完整完成必须逐行验证能力清单，不能以“某次13001查找成功”冒称所有功能已开放。
